# 端云通信 · 待冻结参数清单与云端冻结建议

> 用途：供甲方云端与 ODM 端侧一起冻结协议参数。云端给出当前默认值 + 冻结建议值 + 依据；端侧按自身硬件能力（EVT 实测）确认或提出异议。
> 状态：除「LID 阈值」已因架构调整不再适用外，其余均为 v1 建议默认值。

---

## 冻结建议总表

| # | 参数 | 云端当前默认值 | 冻结建议 | 依据 |
|---|---|---|---|---|
| 1 | 采样率 | 16kHz | **16kHz** | Azure Speech 标准；时延已达标（<1.5s）；带宽/算力均衡。24/48k 对语音翻译无增益 |
| 2 | 音频编码 | PCM 16bit 单声道（上行裸 PCM；下行带 44 字节 WAV 头，小端） | **PCM16 · 16kHz · 单声道**（下行 RIFF 头，上行裸 PCM） | Azure 原生输出；简单可靠；1.0 不做 Opus |
| 3 | 上行帧长 | 100ms（3200 字节） | **100ms**（可 80–200ms 容差） | 与时延、VAD 断句、网络抖动均衡 |
| 4 | TTS 下行分片 | 按 ≤8KB 分片（非严格时间） | **≤8KB / 约 100ms**，首帧即播 | 播放连续性与首帧时延的平衡 |
| 5 | 单帧上限 | 8KB | **8KB** | 100ms 音频仅 3.2KB，余量充足；WSS 二进制帧合理上限 |
| 6 | 心跳 | 10s（WS ping/pong） | **10s**，连续 2–3 次无 pong 判死（20–30s） | 连接保活与端侧低功耗平衡 |
| 7 | 会话空闲超时 | 20s | **20s** | 与 PRD 一致（连续 20s 无语音/按键自动结束） |
| 8 | LID 阈值 θ/θ_super | —（不适用） | **移除/不适用** | auto 模式已改「一步 auto-detect」，不依赖置信度（详见下） |
| 9 | 背压/流控 | 云端无显式背压（断连清理会话缓冲） | **1.0 暂不做显式背压**，仅约定断连清理 | 短会话+短句积压风险低；量产阶段再评估 |

## 逐项说明与端侧需确认点

### 1. 采样率 —— 建议 16kHz
- **需端侧确认**：麦克风 / ADC 是否原生支持 16kHz 采集；若不支持需重采样，会增加端侧功耗。
- 若端侧只有 24/48k，可协商（但云端仍按 16k 处理，端侧重采样）。

### 2. 音频编码 —— 建议 PCM16 单声道
- 上下行格式差异已明确：**上行裸 PCM（端侧采集）**，**下行 RIFF（44 字节 WAV 头 + PCM，云端 Azure 合成）**。
- 端侧解析下行时需**跳过 44 字节头**；上传时直接发裸 PCM 采样。

### 3. 上行帧长 —— 建议 100ms
- 帧长影响：越小→首字时延低、断句细，但帧数多、帧头开销大；越大→反之。
- 100ms 是语音流式常用值，建议先按 100ms 联调。

### 4. TTS 下行分片 —— 建议 ≤8KB / 约 100ms
- 需端侧确认：**首帧即播**还是**预填缓冲**（预填可抗抖动但增加首帧时延）。
- 云端当前按 8KB 切分，端侧按 turn_id 顺序播放即可。

### 5. 单帧上限 8KB
- 双方实现时都要保证单帧（音频分片 + TTS 分片）不超过 8KB。

### 6. 心跳 10s
- 需端侧确认：断线判死后是否自动重连（重新握手、新 session_id）。

### 7. 会话空闲超时 20s
- 需端侧确认：20s 超时后是否自动断开 + 进入低功耗（与 PRD 待机 7–10 天目标的关系）。

### 8. LID 阈值 —— 不再适用（重要）
- **历史**：早期 auto 模式是「LID 独立前置 + 软锁定」，其中「低置信度降级」需要 LID 置信度分数（阈值 0.8/0.95）。
- **现状**：Azure 语种判定**不返回置信度**，且 auto 模式已改为「一步 auto-detect」（Azure `AutoDetectSourceLanguageConfig`，边收边判语言+翻译），该方案不依赖置信度，软锁定低置信降级随之简化。
- **结论**：此参数从冻结清单**移除**。若未来客户对翻译准确性有更严要求，需换支持置信度的 LID 供应商，届时再定阈值。

### 9. 背压/流控 —— 1.0 暂不做
- 1.0 仅约定：断连时云端清理该会话的音频/翻译缓冲，不做显式流控。
- 量产阶段若出现高并发积压，再评估 TTS 下行缓冲上限、上行积压丢弃等机制。
