品牌词表白名单后台 · 测试指南
v1.0 · 2026-09-16 · 提交测试人员

一、功能概述

品牌词表（brand）和短词白名单（whitelist）改为后台可配置：运营/门店可通过 REST 接口增删查，动态生效（无需重启）。

作用：质量门控——游客说「品牌词」（如 iPhone、Dyson）或「白名单短句」（如 OK、ありがとう）时，不更新语言记忆，避免员工方向翻译被无效语音带偏。

说明：默认词表（application.yml 里的一批品牌词/白名单）仍然生效作为「基线」，后台添加的词在其上追加；词条统一按小写存储。

二、测试环境

  • 服务器：内网 10.0.189.32，端口 8080。
  • 鉴权：每个请求头须带租户标识 X-Customer-Id: 1 与 X-Store-Id: 1。

    • 三、API 操作（curl）

    3.1 查列表

    curl "http://10.0.189.32:8080/api/qualify-terms?type=brand" \
  -H "X-Customer-Id: 1" -H "X-Store-Id: 1"

    type 传 brand（品牌词）或 whitelist（白名单）。

    3.2 添加词条

    curl -X POST http://10.0.189.32:8080/api/qualify-terms \
  -H "Content-Type: application/json" \
  -H "X-Customer-Id: 1" -H "X-Store-Id: 1" \
  -d '{"type":"brand","term":"dyson"}'

    type 传 brand 或 whitelist；term 为词条（自动转小写）。返回 {"id":1,"type":"brand","term":"dyson"}，记下 id。

    3.3 删除词条

    curl -X DELETE http://10.0.189.32:8080/api/qualify-terms/1 \
  -H "X-Customer-Id: 1" -H "X-Store-Id: 1"

    路径末尾的 1 是要删词条的 id（从查列表/添加返回里拿）。

    五、动态生效验证

    改词表后无需重启。验证方法：添加一个品牌词后，在模拟器（https://aicard.seassoon.net/）按住说话说这个词，后端日志会出现「quality gate filtered」；删除该词后再说，则正常翻译（不再过滤）。

  • 验证点 1：添加品牌词 dyson → 模拟器说「Dyson」→ 日志出现 quality gate filtered（品牌词被门控拦截）。
  • 验证点 2：删除 dyson → 模拟器再说「Dyson」→ 正常翻译（门控不再拦截）。
