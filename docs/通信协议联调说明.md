# AI 工牌 1.0 · 通信协议联调说明（本地）

> 供 ODM 端侧固件（ESP32-P4 + C5 + IA8201）与甲方云端后端联调通信协议使用。
> 协议权威文档：《端云通信接口规范-v1.md》（内容为 v4 定稿）。
> 当前状态：协议层 + 翻译主链路（LID 软锁定 + 编排）已就绪；**供应商支持真实 Azure**（设 `AZURE_SPEECH_KEY` 启用），无 key 时回退 Mock。

---

## 一、本地启动

```bash
# 1. 起本地 PostgreSQL（含 pgvector）
docker compose up -d

# 2. 起云端后端（Java 17）
#    真实翻译：设 AZURE_SPEECH_KEY / AZURE_SPEECH_REGION 环境变量（值来自 Azure Speech 资源）
export AZURE_SPEECH_KEY="<你的 Speech 资源 Key>"
export AZURE_SPEECH_REGION="japaneast"
JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home mvn spring-boot:run

# 3. 验证健康（返回 {"status":"UP"}）
curl http://localhost:8080/actuator/health
```

> 不设 `AZURE_SPEECH_KEY` 时，翻译链路自动回退 Mock（回固定 beep，不调 Azure）。

## 二、连接信息

| 项 | 值 |
|---|---|
| 端点 | `ws://localhost:8080/ws`（本地联调用明文 ws；生产 `wss://` 由网关/LB 终止 TLS） |
| device_id | `demo-device-001` |
| token | `demo-token-001` |
| fw_version | `0.1.0` |
| proto_ver | `1` |

完整连接 URL：

```
ws://localhost:8080/ws?device_id=demo-device-001&token=demo-token-001&fw_version=0.1.0&proto_ver=1
```

- 鉴权失败 → 握手被拒（HTTP 403）。
- demo 静态 token；真实上线短期凭证轮换。

## 三、最小联调时序（翻译链路，scope=translate）

```
设备 ──握手（query 带鉴权参数）──► 云端
设备 ──session_init（JSON 文本帧）──► 云端
设备 ──0x01 音频分片 ×N（二进制帧）──► 云端
设备 ──eou（JSON 文本帧）──► 云端
云端 ──language_state（JSON）──► 设备
云端 ──0x81 TTS 分片（二进制帧）──► 设备
云端 ──tts_end（JSON）──► 设备
```

### 消息示例

`session_init`（建连后首条，必发）：

```json
{"type":"session_init","session_id":"s1","scope":"translate","staff_language":"ja-JP",
 "translation_mode":"auto","headset_state":"disconnected","input_source":"badge_far",
 "wifi_band":"5GHz","network_state":"good","config_version":123,
 "candidates":["ja-JP","zh-CN","en-US","ko-KR"]}
```

`eou`（尾包，该 turn 最后一条）：

```json
{"type":"eou","session_id":"s1","turn_id":"t1","source_side":"counterparty",
 "last_sequence":23,"utterance_duration_ms":1500,"input_source":"badge_far"}
```

## 四、当前翻译链路行为

翻译主链路已实现（LID 软锁定状态机 + LID→语音翻译→TTS 编排）。供应商二选一：

| 模式 | 触发条件 | 行为 |
|---|---|---|
| **真实 Azure** | 设 `AZURE_SPEECH_KEY` | LID（Azure Language Identification）+ 语音翻译（TranslationRecognizer）+ TTS（SpeechSynthesizer），真实出声 |
| Mock | 未设 key | 固定回 `zh-CN` + 200ms 440Hz beep，不调 Azure |

收到 `eou` 后云端回：

| 下行消息 | 内容 |
|---|---|
| `language_state` | 当前 visitor_language + `state`（locked） |
| `0x81 TTS` | 译文合成语音（真实 Azure 或 Mock beep） |
| `tts_end` | 流结束标记 |

- 不回 `final_text`（v4「端侧不显示文本，仅调试」）。
- 低置信 / 串音冲突 / 双方同语种 / 供应商全挂 → 回 `error`（`E_LID_LOW` / `E_CONFLICT` / `E_SAME_LANG` / `E_PROVIDER`）。
- 员工知识库（`scope_change` → `staff_qa`）仍是 stub（`StubSkbHandler` 回 `answer` + TTS + `tts_end`），P5 实现。
- ⚠️ Azure LID 不返回置信度，软锁定的「低置信降级」暂退化（置信度固定 1.0），联调实测后定方案。

## 五、帧结构速查（详见接口规范 §2）

| 帧 | 方向 | 编码 | frame_type |
|---|---|---|---|
| 音频分片 | 端→云 | 二进制 | `0x01` |
| TTS 音频 | 云→端 | 二进制 | `0x81` |
| 控制消息 | 双向 | JSON 文本 | — |

- 多字节整数**大端 big-endian**。
- 上行音频帧 `0x01`：`frame_type(1) + turn_id_len(1) + turn_id(N) + sequence(4) + timestamp(8) + source_side(1) + input_source(1) + audio_payload(...)`。
- 下行 TTS 帧 `0x81`：`frame_type(1) + turn_id_len(1) + turn_id(N) + tts_audio(...)`。
- JSON 字段 snake_case；`0x81` 二进制帧只带 turn_id，不带 session_id（靠连接关联会话）。

## 六、⚠️ 待冻结参数（联调需确认，见接口规范 §9）

采样率（建议 16kHz）、音频编码（PCM16 单声道）、上行帧长（100ms）、心跳（10s）、
会话空闲超时（20s）、LID 阈值（0.8/0.95）、背压/流控等——需 ODM 硬件能力 + EVT 验证后冻结。
