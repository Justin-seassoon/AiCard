# AI 工牌 · 投资人推介

> 一句话：把 AI agent 装进日本服务业一线员工的工牌里——翻译只是入口，真正价值是把「知识、推荐、调度」下沉到经营末梢，让一线数据回流形成「越用越聪明」的壁垒。

---

## 一、市场机会

- 日本少子高龄化、劳动力长期短缺，外国劳工持续增长，**部分服务/劳动密集行业占比已超 40%**
- 一线沟通 / 培训 / 管理是重活，且大模型热潮集中在办公室和软件，**没人做「戴在身上、帮店员干活」这件事**
- 服务业一线是 AI 尚未渗透的、最大的一块「经营末梢」

## 二、我们做什么

一个工牌大小的可穿戴 AI 终端（硬件轻量：音频采集 / 播放 / 按键 / 彩屏 / 低功耗；云端做重活：语种判定 / 翻译 / 知识库 / 广播 / 设备管理），给一线员工：

- **翻译**：多语种实时双向语音翻译（端到端 <1.5s）
- **知识**：总部知识下沉一线，问就答，答案带来源
- **推荐**：品牌词识别 + 专业推荐，帮一线卖货
- **广播**：多语种一键通知 / 调度 / 回执
- **数据**：一线交互回流 → 补知识 → 越用越聪明

---

## 三、为什么是我们（差异化 + 护城河）

1. **不是「又一台翻译机」**：翻译机是硬件一次性买卖，无数据、无粘性；我们卖的是「经营末梢的 agent」
2. **数据闭环壁垒**：一线交互 → 补知识 → 下次答得更好 → 迁移成本（换掉就丢数据）
3. **行业知识库壁垒**：已沉淀多行业日语知识库（员工 SKB + 游客/劳工 VKB），是积累不是技术
4. **四层租户隔离**：天然 SaaS，一客户一套数据，可规模化交付
5. **「成事」定位**：帮一线把事做成、不是监控一线 → 一线/中层不抵触、落地阻力小（对标德国面包店「去掉不信任 → 销售额涨 2.7%」）

---

## 四、商业模式

- **SaaS**：硬件（ODM 成本）+ 云端订阅（按设备 / 门店）
- **多供应商 API 抽象**：不锁死单一翻译供应商，成本可控、可替换
- **可扩展**：一套通用能力 × 多行业模板

---

## 五、增长路径

- 翻译 / 知识 / 推荐 / 广播是**通用能力**，行业差异做成**模板**（酒店 / 免税 / 机场 / 劳务派遣 5 细分 / 工地），横向扩张边际成本极低
- 从日本服务业 → 全球多语种服务场景（香港 / 新加坡 / 中东 / 欧美旅游城市）

## 七、竞争格局

| 对手 | 弱点 |
|---|---|
| 翻译机（硬件一次性） | 无数据、无粘性、不服务一线经营 |
| 语音大模型 App（手机） | 不佩戴、不解放双手、无行业知识 |
| **我们** | **佩戴式 + 行业知识 + 数据闭环** |

---

## 八、风险与应对

- **主动推送 vs 待机功耗矛盾**：正与端侧对齐「在线推送 + 离线补拉 / 定时轮询」方案
- **企业系统 API 缺失**：1.0 用云端自有台账 / 工单 / 通知兜底，对接 PMS/POS 等外部系统延后
- **隐私合规（APPI）**：采集数据明确用于「成事」（补知识 / 优化推荐 / 预警），不用于监控，降低合规与落地阻力
