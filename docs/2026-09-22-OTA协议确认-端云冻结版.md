# AI 工牌 OTA 升级协议 · 端云冻结版（云端确认）

> 致：端侧（ODM）同事
> 日期：2026-09-22
> 状态：**已冻结** —— 本文件为端云双方 OTA 联调与实现的权威依据
> 依据：端侧《AI 工牌 P4 / C5 固定配套版本 OTA 升级方案（端云评审稿）》

---

## 一、总体结论

云端**整体认可**端侧初稿。方案（固定配套发布 + A/B 分区 + 启动回滚 + 独立 HTTPS 通道）作为 1.0 OTA 的定稿方案，字段契约、状态机、失败恢复口径均按初稿执行。

核心分权确认：**云端决定「升到哪个版本、是否必须升」，端侧决定「当前是否具备安全升级条件」**。强制策略不能绕过端侧校验与供电保护。

---

## 二、通道定稿（本次评审的核心决策）

**废弃**：原规范 §8「云端通过 `config_update` 下发 ota 信息」。
**废弃**：原规范 §8「设备用 `button_event` / 专用 `ota_event` 上报进度/结果」。

**定稿**：统一为独立 HTTPS 通道 + 被动感知。

| 方向 | 通道 | 说明 |
|---|---|---|
| 检查更新 | `POST /api/v1/ota/check`（HTTPS） | 设备 → 云，携带 P4/C5 实际版本，返回固定配套目标 + 有序包清单 |
| 下载固件 | `GET {download_url}`（HTTPS 签名 URL） | P4 → 固件服务；C5 不直连云端，由 P4 经 SDIO 下发 |
| 结果感知 | 下次 check 的 `current_versions` | 云端被动感知设备实际运行版本，1.0 **不做**独立上报接口 |

> 升级进度 / 成功 / 失败 / 回滚由端侧本地显示与记录，云端不落过程日志（1.0 口径）。

## 三、接口契约（冻结）

### 3.1 检查更新 `POST /api/v1/ota/check`

鉴权：`Authorization: Bearer <device_token>`。云端校验凭证与 `device_id` 的绑定关系；租户、门店、灰度分组由云端设备档案推导，**不信任设备自报**。

请求字段（均必填）：

| 字段 | 类型 / 约束 | 含义 |
|---|---|---|
| `device_id` | string，1–64 | 云端已登记设备 ID |
| `product_model` | string，1–32 | 产品型号，须与设备档案一致 |
| `hardware_version` | string，1–32 | 板卡硬件版本；开发板与正式板必须区分 |
| `current_versions.p4` | string，1–31 | P4 自身运行镜像 `esp_app_desc.version` |
| `current_versions.c5` | string，1–31 | P4 经 SDIO 实时读取，禁止历史缓存猜测 |
| `trigger` | enum `boot` / `manual` / `pre_install` | 检查触发场景 |

> 无法读取 C5 版本时，显示模块通信异常并重试，不发送伪造版本、不启动依赖版本组合的升级。

`HTTP 200` 响应：

| 字段 | 类型 / 必填 | 含义 |
|---|---|---|
| `update_available` | boolean / 是 | 是否存在适用更新 |
| `update` | object 或 `null` / 是 | 有更新为下表清单对象，无更新固定为 `null` |
| `reason` | enum / 无更新时必填 | `UP_TO_DATE` 已是适用版本；`NO_APPLICABLE_RELEASE` 暂无适用发布（后者不能提示「已是最新」） |

`update` 对象：

| 字段 | 类型 / 约束 | 含义 |
|---|---|---|
| `update_id` | string，1–64 | 固定配套发布标识；目标组合、包内容、策略或顺序变化时更换；刷新 URL、按进度省略已完成模块时不变 |
| `policy` | `optional` / `mandatory` | 整份清单的普通 / 强制策略 |
| `target_versions.p4` | string，1–31 | P4 必须达到的准确运行版本 |
| `target_versions.c5` | string，1–31 | C5 必须达到的准确运行版本 |
| `packages` | array，1–2 | 仅含实际版本尚未达标的模块，按发布顺序排列，不遗漏、不重复 |
| `release_notes` | string，≤256 | 简短说明，不决定是否强制，屏幕可截断 |

`packages[]` 每项：

| 字段 | 类型 / 约束 | 含义 |
|---|---|---|
| `module` | `p4` / `c5` | 写入对象；其他模块拒绝 |
| `target_version` | string，1–31 | 必须等于 `target_versions[module]` 且逐字节等于镜像内版本 |
| `image_size` | integer | 最终 `.bin` 字节数；>0 且 ≤ 对应芯片备用 OTA 槽容量 |
| `sha256` | string，64 hex | 对实际下载的完整 `.bin` 计算的 SHA-256 |
| `download_url` | string，HTTPS，≤511 | 短期签名 URL；仅下载用，不落日志 / NVS |
| `expires_in_sec` | 正整数 | 自签发起有效秒数，建议 ≥3600，安装前重取 |

> **端侧清单校验**：实际 `current_versions` 与 `target_versions` 逐项比较，不相等的模块必须且只能各有一个包；包目标版本与配套目标一致；缺包 / 目标字段不全 / 重复模块 / 未知模块 / 版本不符 → 拒绝整份清单。执行前再次读本地版本，已变化则重查。

**查询错误约定**（任何错误都不能解释为「无更新」）：

| 状态码 | 场景 | 端侧行为 |
|---|---|---|
| `400` | 参数错误 | 停止盲目重试 |
| `401` | 凭证失效 | 先走设备凭证更新流程 |
| `403` | 设备无权限 | 停止盲目重试 |
| `429` | 限流 | 遵循 `Retry-After` |
| `5xx` / 网络错误 | 服务异常 | 按退避重试 |

统一 JSON：`{"error_code":"UNAUTHORIZED","message":"device credential expired"}`。

### 3.2 下载固件 `GET {download_url}`

输入为 `packages[]` 的 `download_url`，P4 发 HTTPS GET；鉴权由签名 URL 承载，**不向固件域名转发设备接口的 Bearer Token**。

| 输出 | 契约（首期冻结） |
|---|---|
| HTTP 状态 | 成功必须 `200` |
| `Content-Type` | `application/octet-stream` |
| `Content-Length` | 必须等于 `image_size`，实收字节数一致 |
| 响应体 | 与 `module` 匹配的完整 P4 / C5 应用 `.bin`；非整片 Flash 合并镜像、非 JSON/Base64 包装 |
| 传输限制 | 不使用重定向、chunked、压缩编码、Range 续传；中断整包重下 |

> 完整文件 SHA-256 用于一致性校验，不替代固件签名；量产前确认是否启用官方签名校验及密钥配置。

## 四、云端补充约定（定稿口径）

1. **鉴权统一**：Bearer `device_token` 复用现有设备 token，与 WSS 握手鉴权共用同一凭证体系与校验实现，**不分叉**。demo 阶段 token 静态，短期轮换统一后续排期（对应规范 §11.5）。
2. **设备档案**：云端以 `device_id` 定位档案，校验 `product_model` + `hardware_version` 一致；`customer_id / store_id / 灰度分组` 全部由档案推导。
3. **灰度分组**：1.0 字段预留、默认全量，后续后台按 store / group 圈定。
4. **固定配套与中间组合**：云端维护显式「起始组合 → 中间组合 → 目标组合」迁移表，check 按设备实际组合返回需补装模块；不做版本字典排序、不按版本号首位推断强制。
5. **image_size 校验**：发布时校验不超过对应芯片备用槽容量（P4 A/B 槽各 6 MiB 已知；C5 待端侧冻结容量后补齐）。
6. **IA8201 / Bootloader / 分区表**：1.0 不在本通道，另立（暂不做）。

## 六、联调交付物与验收

**交付**：
- 云端：固定配套目标样例（两模块都待升 / 单模块已达目标 / 半更新恢复清单）、`check` 接口、签名下载 URL、发布后台。
- 端侧：P4 / C5 测试包、已验证的起始 / 中间 / 目标组合。

**验收项**（全部通过方算冻结完成）：

1. 首次联网 / 手动检查、普通 / 强制策略、P4 自身 OTA 与 C5 经 SDIO OTA。
2. 必需包缺失、目标字段缺失、包版本错误、无安全中间组合时拒绝执行。
3. C5 成功后 P4 下载失败 / 启动回滚 / 断电；重启后限制仍在，只恢复未完成模块。
4. 相同目标版本但启动尚未确认时，不误判整次成功。
5. 半更新时撤销、降为普通、返回无更新或查询失败，不解除恢复状态。
6. 完整恢复起始组合时按普通 / 强制策略处理；完整目标组合验证通过后才恢复业务。
