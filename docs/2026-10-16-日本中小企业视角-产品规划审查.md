# AI 工牌 · 日本中小企业视角产品规划审查

> 日期：2026-10-16
> 审查角度：**日本中小企业（SME）的 AI / 大模型落地需求**
> 审查对象：aiCard 现有产品规划与设计（投资人推介 / 成事定位 / 主动与执行远景 / 项目说明 / 三条能力升级方向）
> 方法：以 WorkBuddy 项目《日本市场调研》的**已核实数据**为标尺，逐「落地门槛」审查，找出满足项与缺口
> 关联：`docs/2026-10-16-门槛2调整方案-硬件与产品两条腿.md`（本审查门槛2 的展开方案）

## 0. 审查标尺：日本 SME 的六道落地门槛

**已核实的市场数据（来自 WorkBuddy 日本市场调研，2026-10-11）**：

| 指标 | 数值 | 含义 |
|---|---|---|
| 企业生成 AI 利用率（日本） | **55.2%**，美 90.6% / 中 95.8% | 国际垫底，落后 35pt+ |
| **AI agent「利用中」的企业** | **仅 3.3%**（"信息收集中" 49.3%，矢野 2025） | agent 渗透率极低 |
| AI agent 导入/推进中（日本） | 33%，六国最低（PwC 2026） | — |
| 采用障碍 ① | **「不知道怎么有效使用」30.1%** | 不熟 AI |
| 采用障碍 ② | **安全风险 27.6%** | 合规信任 |
| 采用障碍 ③ | 运营成本 24.9% / 缺人才 41.3% | 无 IT 部门 |
| **生成 AI 方针「未定」的企业** | **50.9%**（東京商工リサーチ） | 治理空白 |
| 效果实绩 | 活用企业 **86.7% 感到有效果** | 价值真实 |

**叠加 SME 结构性特征**（人手不足、属人化、事業承継、IT 人材不足、稟議、价格敏感、补助金依赖、**无情报系统部门**），收敛为六道门槛：

| # | 门槛 | SME 的特殊性 |
|---|---|---|
| 1 | **痛点对齐** | 人手不足 / 属人化 / 事業承継 才是能上経営会議的痛 |
| 2 | **导入门槛（成本 + 技能）** | 无 IT 部门；**硬件 = 额外门槛**；预算靠补助金 |
| 3 | **安全合规信任** | 没情报系统部，但恐惧在；SaaS 稟議常要 Pマーク |
| 4 | **决策路径** | 社長可快拍板，但需 ROI + 试点材料 |
| 5 | **「不熟 AI」可用性** | 要零培训；概念要业务化 |
| 6 | **替代品** | 最大对手是**员工手机上的免费 ChatGPT 个人版** |

## 1. 门槛1 · 痛点对齐 —— ⚠️ 部分满足，存在「叙事 vs 实质」落差

**满足**：
- ✅ 对准真实痛点。外国劳工集中在**製造/農業/介護/建設/清掃/飲食**——**全 SME 密集行业**；培训/安全/合规下沉 + 「成事」定位（帮一线、不监控）心理适配很好（对齐德国面包店「去掉不信任 → +2.7%」洞察）。

**缺口**：
- ⚠️ **叙事与产品实质有落差**。投资人材料称「翻译只是入口、不是翻译机」，但**当前代码 90% 是翻译链路**（`gateway/` `translation/` `provider/`），知识库是配菜。对**外労占比不高的 SME**（大量纯日语的小売/飲食/事务所），「翻译入口」楔子几乎不成立，价值立刻变薄。

**含义**：必须按 **「外労占比 × 门店规模」细分客户**，而非笼统「日本服务业」。无外労或低外労的 SME，入口应是**知识 / 文书**，不是翻译。

---

## 2. 门槛2 · 导入门槛 —— ❌ **最大风险：硬件**

> 本节展开为独立方案：`docs/2026-10-16-门槛2调整方案-硬件与产品两条腿.md`

**缺口（核心）**：
- ❌ **工牌是硬件**。设备采购（固定资产 / 稟議）+ 充电 + 保管 + 丢失 + 维护，而 SME **没有 IT 部门**接手。对一个 5 人小売/飲食，买 N 个工牌是**实打实的摩擦**，远重于纯 SaaS。这可能是 SME 落地**最大的单点障碍**——两版对外材料（投资人推介 / 客户推介）都**未正面处理**。
- ❌ **补助金策略完全缺失**。SME 的 AI 预算高度依赖 **IT導入補助金** 等（需登録 IT ツール + 支援事業者経由），这是 SME 预算的解锁钥匙，目前 0 动作。

**满足**：
- ✅ 零运维方向正确：纯 SaaS（日本区）、不碰 on-prem——SME 本来也跑不了 Docker/PG。

**战略机会（已在门槛2 方案中展开）**：三条新方向（①自生长知识 / ②agent 执行 / ③文档处理）**全在后台、全无硬件**——等于给 aiCard 开出一条**无硬件、可直通 SME** 的产品线。

---

## 3. 门槛3 · 安全合规信任 —— ⚠️ 有敞口，销售侧必须能答

**满足**：
- ✅ 语音/文本走 Azure `japaneast`；采集数据明示「用于成事、不用于监控」——对齐「AI 利用方针未定 50.9%」的顾虑。

**缺口**：
- ❌ **实际敞口**：LLM 走 **aibridgex（deepseek）** 第三方网关。对**製造（技術情報）/ 介護（要配慮個人情報）**的 SME，一旦被问「数据去了哪」，是**信任雷**。方向④虽由**其他团队单独立项**，但**这是 SME 销售侧必须准备答案的问题**，不能用「话术统一」遮蔽。
- ❌ **「不用于训练」未明示**。WorkBuddy 将此列为**独立卖点**（日本企业核心关切），aiCard 材料中缺失。低成本、高回报，建议补。
- ❌ **无 Pマーク / ISMS**。SME 的 SaaS 稟議常要求 Pマーク。取证 6–12 个月，**若 SME 是目标须早启动**。

---

## 4. 门槛4 · 决策路径 —— ⚠️ 缺 SME 版稟議材料

**满足**：
- ✅ SME 社長可快拍板（比大企业快）；「成事」+ ROI 话术（事故↓ / 投诉↓ / 培训成本↓）是好原料。

**缺口**：
- ❌ **投资人材料 ≠ 客户稟議材料**。缺 SME 版的 **ROI 测算 / 试点方案 / 导入步骤 / 稟議书模板**。日本 SME 要的是「我怎么向社長 / 稟議説明」，不是 TAM。

---

## 5. 门槛5 · 「不熟 AI」可用性 —— ✅ 语音是优势，后台侧需警惕

**满足**：
- ✅ **语音交互是 SME 现场最低门槛的形态**（免培训、免键盘、解放双手）——这是工牌对 SME **最站得住的价值**。

**缺口**：
- ⚠️ 三条新方向**落在后台（PC/Web）**：对 SME 事务员可用，对现场不可用。且 WorkBuddy 的「事件流 / 依頼对象 / 任务状态机」**对 SME 用户太抽象**，必须**业务化**（按具体事项命名，不做「任务平台」概念）。
- ⚠️ **①的「人工审核」在 SME 无人干**——无专职知识管理者，审核落在社長/事务员且是兼职。**审核必须近零负担**（批量 / 一键），否则「自生长」死在最后一公里。

---

## 6. 门槛6 · 替代品 —— ❌ 未针对最大对手

- ❌ SME 最大的替代品**不是** Copilot，是**员工手机上的免费 ChatGPT 个人版**。aiCard 材料缺「**为什么企业要买你，而不是让员工用 ChatGPT**」的正面回答。
- SME 版答案其实很强：**现场 / 免培训 / 多语言 / 佩戴式 + 企业知识隔离 + 数据不进训练 + 合规**。**建议显式写入客户材料。**
- （本土垂类 LegalOn / LayerX / Stockmark 主攻中堅+，对 SME 直接威胁较小，不必过度担心。）

## 7. 三个能力升级方向 · SME 适配

| 方向 | SME 适配 | 结论 |
|---|---|---|
| **① 自生长知识** | **最强** | SME 恰恰**没人维护知识库**，「自生长」直击此点。**两步修正**：<br>① SME 的规程常在**老员工脑子里**（非数字文档）→ 起步应从**日常问答沉淀**，而非只从文档灌；<br>② 审核要**近零负担**（批量 / 一键） |
| **③ 文档处理** | **强** | 見積書 / 請求書 / 稟議書 / 議事録 / 回覧 是 SME 通用文书痛点，**无硬件**。须吃透日本文件现实（**和暦 / 全角 / 押印文化**） |
| **② agent 执行** | **弱（作为平台）** | SME **不买「通用 agent」，买「帮我做这件事」**。对 SME 必须**场景化包装**；但它是**最强的融资 / 叙事资产** → **对投资人讲平台，对客户讲场景** |

## 8. 关键结论

**A. 硬件是 SME 的坎，但 aiCard 不必只用硬件打 SME。**
三条新方向**全在后台、全无硬件** → aiCard 可做成**两条腿**：
- **工牌（重）**：一线、多语言、有外労的门店 / 连锁 / 派遣；
- **后台 agent（轻）**：知识 / 文书 / 事务，**零硬件门槛**，可卖给买不起 / 不需要工牌的绝大多数 SME。

两条腿**互相喂数据**（工牌一线交互 → 后台知识沉淀）。**这才是「吸收 WorkBuddy」真正的战略增量——它给了 aiCard 一个硬件之外、直通 SME 的入口**，不应只当成「三个新功能」。

> 注：后台 agent 线的目标用户（事务 / 总务职能）与本仓库定位的「一线」**不是同一批人**——这是需要产品层明确的边界，也是与 WorkBuddy 楔子（総務 AI 助理）真正的合流点。

**B. 客户细分必须从「日本服务业」细化到「外労占比 × 门店规模」。**
否则会对无外労 SME 讲翻译、对买不起硬件 SME 推工牌，**两头错位**。

---

## 9. 低成本高回报动作（与三方向独立，随时可做）

1. **补「不用于训练」明示**（对日企是独立卖点）。
2. **把「为什么不用免费 ChatGPT」写进客户材料**。
3. **准备 SME 版稟議材料**（ROI / 试点 / 导入步骤）。
4. **评估 Pマーク / ISMS 启动**（若 SME 为明确目标，取证周期长）。
