## 一、定义：什么是日本的「中小企业」

**法律定义（中小企業基本法）**——按「资本金 或 员工数」二选一：

| 行业 | 资本金 | 员工数 |
|---|---|---|
| 製造業 その他 | 3 億円以下 | 300 人以下 |
| 卸売業 | 1 億円以下 | 100 人以下 |
| 小売業 | 5 千万円以下 | **50 人以下** |
| サービス業 | 5 千万円以下 | **50 人以下** |
| （特例）ゴム製品製造 / ソフトウェア・情報処理 / 旅館業 | — | 各有放宽 ⚠️ |

**「小規模企業者」**（更小一档）：製造業その他 **20 人以下**、商業・サービス業 **5 人以下**。

**「中堅企業」**：**非法律概念**，泛指「比中小企业大、比大企业小」的中段规模（大企业未满的中规模企业）。这一档是**预算与组织成熟度**的分水岭（见 §五）。

---

## 二、规模：日本经济的绝对主体

- 中小企业数：约 **357 万家**，占全部企业的 **99.7%**；其中**小规模企业者占约 94%** ⚠️
- 中小企业雇员：约 **3,300 万人**，占私营部门雇佣的 **约 7 成** ⚠️
- 行业分布（事业所数）：**卸売・小売、サービス** 各约 1/4；**建設、製造** 各约 13–17%；其余运输/宿泊/饮食等 ⚠️（中小企業白書 口径，年份待核）

**含义**：谈「日本市场」几乎就等于谈 SME。**但「SME」内部差异极大——它是一个区间，不是一个市场**（见 §五）。

## 三、结构特征（决定 AI 落地土壤的四件事）

| 特征 | 内容 | 对 AI 落地的影响 |
|---|---|---|
| **① 人手不足** | 少子高龄化，劳动人口持续下降；**2024 年起「時間外労働上限規制」适用中小企业** ⚠️，用工合规压力上升 | **最硬的痛点**、最容易买单的理由 |
| **② 事業承継危机** | 经营者高龄化，**约 245 万家**中小企业经营者 70 岁以上、**约一半无后继**，面临廃業风险（中小企業庁测算） ⚠️ | **属人化 / 知识流失**是上経営会議的痛（= 沉淀面卖点） |
| **③ IT 人材不足 / DX 滞后** | 无 IT 部门是常态，**総務 / 経理 兼管 IT**；「2025 年的崖」遗留系统问题 | 产品必须**零运维、零培训**；日语支持是硬要求 |
| **④ 稟議 + 价格敏感 + 补助金依赖** | 决策靠稟議（社長或少数人拍板）；预算紧，**AI 预算高度依赖补助金** | 需要稟議材料 + 补助金通道（见 §六） |

## 四、AI 采纳现状（✅ 数据来自 WorkBuddy 已核实调研）

| 指标 | 数值 | 解读 |
|---|---|---|
| 企业生成 AI 利用率（日本） | **55.2%**，美 90.6% / 中 95.8% | 国际垫底 |
| **AI agent「利用中」** | **仅 3.3%**（"信息收集中" 49.3%） | agent 几乎空白 |
| AI agent 导入/推进中 | 33%，六国最低 | — |
| 采用障碍 | 不会用 30.1% / 安全 27.6% / 缺人才 41.3% | 对应 §三③④ |
| **生成 AI 方针「未定」** | **50.9%** | 治理空白 = 需要「指南/模板」 |
| 活用企业体感有效 | **86.7%** | 价值真实，缺的是「怎么用」 |

> ⚠️ **注意**：上述 55.2% 是「業務で利用」的广义口径，且**大企业与中小企业差距显著**（大企业远高于中小企业）——**不能把整体数字当成 SME 数字**。SME 的实际采用率更低。

## 五、SME 内部分层 —— 关键：SME 不是一个市场

| 层 | 规模（员工数，示意） | 组织特征 | 对 AI 的适配 |
|---|---|---|---|
| **小規模事業者** | 〜5（商业/服务）/ 〜20 | 社長一人、无专职事务、无 IT | **预算极小、无决策结构、走量成本高**；单靠免费工具可能够用 |
| **中小企業**（标准档） | 〜50–300 | 有総務/経理职能、有稟議、有预算 | **AI 甜点区候选**：有痛点、有预算、有职能（对齐 WorkBuddy 総務楔子） |
| **中堅企業** | 300+ | 多层组织、系统化、有 IT | 预算大、但决策慢、可能已有 Copilot / 本土 SaaS 竞品 |

**判断**：**「SME」作为目标市场太宽**。若做，**甜点区大概率是「中小企業（标准档）」而非极小规模**——
- 极小规模：连 SaaS 席位费都敏感，且**没有「总务/事务」职能**，方向①③无人用、无人审；
- 中坚：预算够但竞争激烈（Copilot / LegalOn / LayerX / Stockmark），且决策周期长。

> ⚠️ 上表规模阈值为示意，需按「行业 + 是否有事务职能 + 是否有外労」再校准。

## 六、决策与预算（SME 商业化落地的闸门）

| 项 | 内容 |
|---|---|
| **谁拍板** | 小规模：社長一人；标准档：社長 / 管理部門長（稟議） |
| **预算科目** | 総務費 / IT 予算 / **补助金**（三分天下） |
| **补助金（主通道）** | **IT導入補助金**（中小企業庁 / 中小機構）：补助 SME 导入 IT 工具，**须为登録 IT ツール + 经支援事業者申请**（⚠️ 各年度枠/上限会变，落地前核实） |
| **补助金（次通道）** | 事業承継 / デジタル化 相关、地方自治体独自补助 ⚠️ |
| **关键中介** | **認定支援機関**（税理士 / 会計士 / 商工会議所 / 商工会）——SME 信他们多于信厂商 |

**含义**：SME 落地 = **产品能否进补助 + 能否被认定支援機関 / 商工会議所 背书**。这是纯厂商直销接触不到的闸门。

## 七、买点与阻力

**买点（SME 会为此掏钱）**：
1. **人手不足对策**（最硬）；
2. **法令対応**（インボイス / 電子帳簿保存法 / 工时规制的文书与合规）；
3. **即效、低门槛**（当天能用、免培训）；
4. **同规模企业的实例**（peer case 说服力 >> 大企业案例）。

**阻力（SME 不买的原因）**：
1. 决策慢（稟議 1–3 个月）；
2. 价格敏感（席位费肉疼，除非有补助）；
3. **免费 ChatGPT 个人版**是最强替代；
4. **日语支持**是硬要求（无日语客服 = 直接出局）；
5. **走量成本高**（一家家谈，ARPU 低，销售/支持摊不平）。

## 八、渠道（怎么触达 SME）

| 渠道 | 说明 |
|---|---|
| **商工会議所 / 商工会** | 最广的 SME 触点，可做讲座 / 事例发布 |
| **認定支援機関**（税理士 / 会計士） | 既是顾问也是补助金通道 |
| **業界団体**（製造 / 建設 / 介護 等） | 同行业批量触达 |
| **販売代理店 / SI 被集成** | 借本土渠道（对齐 WorkBuddy 调研的「SI 被集成」） |
| **补助金 支援事業者** | 与 IT導入補助金 生态绑定 |

## 九、与 aiCard 的映射

把 SME 分层 × 我们的**两条腿**（工牌线 A / 后台 agent 线 B）× **外労占比** 叠加：

| SME 层 | 低外労 | 高外労 |
|---|---|---|
| 小規模事業者 | 腿 B（若预算允许） / 免费工具替代风险高 | 腿 B 起步，难长成腿 A |
| **中小企業（标准档）** | **腿 B（知识/文书）——最干净入口** | **腿 A 主战场（一线多语言刚需）** |
| 中堅企業 | 腿 B + 竞品（Copilot/本土） | 腿 A + 腿 B |

**两个结论**：
1. **腿 B（无硬件、纯软件）才是打 SME 的主力**——因为 SME 的闸门（补助金 / 无 IT 部门 / 价格）都是**软件更易过**。
2. **方向①「自生长知识」的甜点用户，就是 SME 标准档的総務/事务职能**——这与 WorkBuddy 楔子合流，也解释了为什么①优先是对的。

## 十、讨论要点（决策用）

**决策状态（2026-10-16）**：

| # | 事项 | 状态 |
|---|---|---|
| 1 | 做不做 SME | ✅ **已决：做** |
| 2 | 瞄准哪一层 | ✅ **已决：靶心收窄到「中小企業 标准档」，不碰极小规模** |
| 3 | 入场费（是否现在投入） | 🟡 **讨论中** — 见 §十一 详解 |
| 4 | 与「不专做 SME」的机会成本 | 🟡 讨论中（与 3 联动） |

**原讨论要点（保留备查）**：

1. **做不做 SME？**
   - 做：市场最大、人手不足是最硬痛、AI 空白（3.3%）；但走量成本高、ARPU 低、免费工具竞争。
   - 不做：只盯中坚 / 大企业 / 连锁——ARPU 高，但放弃 99% 的企业数。

2. **若做，瞄准哪一层？**
   - 建议：**「中小企業 标准档」**（有事务职能 + 有预算 + 有稟議），**不碰极小规模**（无职能、无预算，方向①③无人用）。
   - 是否同意把靶心从模糊的「SME」收窄到这一档？

3. **必要准备（入场费，若做 SME 就得真投入）**：详见 §十一。
   - ⚠️ **IT導入補助金 登记**（作为 登録 IT ツール + 对接支援事業者）；
   - ⚠️ **日语支持体系**（客服 / 文档 / 事例）；
   - ⚠️ **稟議材料**（ROI / 试点 / 导入步骤）；
   - ⚠️ **Pマーク**（取得 6–12 月，须早启动）。

4. **和「不专做 SME」相比的机会成本**：SME 需要的补助金 / 日语支持 / 走量销售，是**重运营**投入；若当前阶段目的是演示 / 融资，这些投入是否值得现在做、还是等能力（①②③）先跑出来？

## 十一、入场费详解（中文术语对照）

> 面向不读日语的读者。所谓「入场费」= **打 SME 必须自建的基础设施（产品之外）**，不是给谁交钱。

### 术语表（日语 → 中文）

| 日语 | 中文 | 一句话 |
|---|---|---|
| IT導入補助金 | IT 导入补助金 | 政府替 SME 出钱买 IT 工具的补贴 |
| 支援事業者 / 認定支援機関 | 支援事业者 / 认定支援机构 | 有政府资质的中间人（税理士/商会/银行） |
| 登録ITツール | 登记 IT 工具 | 只有登记在册的软件才能申请补助 |
| 稟議 | 稟議（书面请示审批） | 日本企业「多人盖章批准」的采购制度 |
| Pマーク | 隐私标章 | 日本民间隐私保护认证 |
| ISMS | 信息安全管理体系 | 即 ISO/IEC 27001，B2B 软件准入门槛 |

### 五项逐一

| # | 项 | 是什么 | 为什么 SME 非要 | 我们要做什么 | 成本/周期 |
|---|---|---|---|---|---|
| 1 | **IT 导入补助金** | 政府补助 SME 买 IT（补助率常约 1/2～3/4，⚠️每年变） | SME 的 AI 预算很大程度靠补助解锁，无补助不掏钱 | ①把产品登记为「登记 IT 工具」；②对接支援事业者 | 持续维护；⚠️硬件（工牌）能否纳入存疑 |
| 2 | **支援事业者 / 认定支援机构** | 有资质的第三方（税理士/会计士/商工会議所/银行） | SME 信他们 >> 信厂商；既是补助通道也是推荐渠道 | 与他们建合作（= WorkBuddy 调研的「被集成」路径） | 商务拓展 |
| 3 | **日语支持体系** | 全程日语客服 / 文档 / 培训 / 故障响应 / 事例 | SME 无 IT 部门，全靠厂商；无日语客服 = 直接出局 | 建日语支持团队或外包 | **重人力投入** |
| 4 | **稟議材料** | 客户拿去走内部审批的材料（ROI/试点/步骤/费用/安全说明） | 稟議要走 1–3 个月，无此材料客户推不动 | 专门做一套（≠ 投资人材料） | 一次性做，持续更新 |
| 5 | **Pマーク / ISMS** | 隐私认证 / 信息安全认证 | SME 采购 SaaS 走审批时经常被要求 | 申请认证 | **6–12 个月，须早启动** |

**关键区别**：这是**「重运营」投入**，与「把产品能力（①②③）做出来」是两条线。**先做哪个，是 §十-4 的机会成本问题。**

## 附：一句话小结

**SME 是日本市场的绝对主体（99.7%），人手不足与事業承継 是最硬的痛，AI 几乎空白（3.3%）——机会真实。但「SME」内部差异极大，且其商业化闸门（补助金 / 无 IT 部门 / 价格 / 免费工具）都在产品之外。若要打 SME，武器是「腿 B（软件）」、靶心是「中小企業 标准档」、前提是「补助金 + 日语支持 + 稟議材料」这三项真投入。**
