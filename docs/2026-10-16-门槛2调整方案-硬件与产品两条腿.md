# 门槛2 调整方案：硬件门槛、补助金策略与产品「两条腿」

> 日期：2026-10-16
> 来源：`docs/2026-10-16-日本中小企业视角-产品规划审查.md` 门槛2（导入门槛）
> 目标：把「**硬件是 SME 落地最大单点障碍**」这一风险，转为可执行的产品 / 商务调整
> 前提：三条能力升级方向（①自生长知识 / ②agent 执行 / ③文档处理）已确认**落在后台 / 云端侧**，优先级 **①→③→②**

---

## 一、问题重述

**SME 导入门槛 = 成本 + 技能，而 aiCard 当前形态把两者都顶到了最高：**

| 因素 | 现状 | 对 SME 的摩擦 |
|---|---|---|
| 支出形态 | **硬件（工牌）+ 云订阅** | 固定资产采购 → 进稟議、占预算科目；比纯 SaaS 重得多 |
| 运维 | 设备充电 / 保管 / 丢失 / 固件 OTA | SME **无 IT 部门**接手，落到店长 / 事务员身上 |
| 部署 | 纯 SaaS（日本区），不碰 on-prem | ✅ 这点对 SME 是对的（SME 本也跑不了 Docker/PG） |
| 预算解锁 | **无补助金策略** | SME 的 AI 预算高度依赖补助金，缺此一环 = 最贵的通道没开 |

**核心矛盾**：工牌对 SME 有**真价值**（现场免培训、多语言），但**采购形态**恰好撞上 SME 最无力的地方（无 IT 部门 + 价格敏感 + 预算靠补助）。

---

## 二、核心判断：产品做成「两条腿」

三条新方向**全在后台 / 云端、全无硬件** → 不必把 aiCard 绑死在一个形态上。

```
                 ┌── 腿 A：工牌线（重）───────────────────┐
                 │  一线 · 多语言 · 佩戴免培训           │
   一个云端核心 ──┤  客户：外労密集的门店/连锁/派遣       │
  （知识体 +      │  价值：现场沟通/培训/广播/回执        │
   任务引擎）     └──────────────────────────────────┘
                 ┌── 腿 B：后台 agent 线（轻）─────────────┐
                 │  知识 / 文书 / 事务 · 零硬件门槛        │
                 │  客户：绝大多数 SME（含无外労者）       │
                 │  价值：答问题、起草文书、自动沉淀知识    │
                 └──────────────────────────────────┘
                        ↑ 两腿互相喂数据 ↓
        腿A一线交互 → 后台知识沉淀 → 腿B更懂这家企业 → 反哺腿A
```

**这不是「分心做第二产品」，而是把**已经存在的**云端核心**（`gateway` + `skb` + `broadcast` + `report` + `maintenance` + `notification`）**显性化为可单独交付的价值**——工牌只是它的一个前端，后台是另一个前端。

> **战略增量**：腿 B 是「吸收 WorkBuddy」真正的落点。它给了 aiCard 一个**硬件之外、直通 SME** 的入口，并且其目标用户（事务 / 总务职能）正是 WorkBuddy 楔子（総務 AI 助理）的合流点。

---

## 三、产品架构调整（两条腿怎么分）

| 维度 | 腿 A · 工牌线 | 腿 B · 后台 agent 线 |
|---|---|---|
| 前端 | 工牌（ESP32-P4 固件 + 云） | 浏览器 / App（`static/admin.html` 一侧增长） |
| 入口能力 | 翻译、知识、广播 | **知识沉淀（①）、文书（③）、任务执行（②）** |
| 目标用户 | 一线员工（外労密集） | 事务 / 总务 / 店长 |
| 硬件依赖 | **有**（ODM + 电池 + OTA） | **无** |
| 交付摩擦 | 高（采购 / 运维 / 稟議） | 低（纯 SaaS / 席位） |
| 毛利结构 | 低（硬件成本） | 高（软件） |
| 上市速度 | 慢（依赖样机 / ODM） | **快**（纯软件，现有服务器即可） |

**关键点**：腿 B 的三项能力**已有代码落点**，不需要新硬件：

| 方向 | 落点（后台侧） | 状态 |
|---|---|---|
| ① 自生长知识 | 复用 `qa_log`(已含 `no_match`) + `KnowledgeStore`；新增 `skb/curation/` + 迁移 V18 + 后台审核页 | 零件齐备（见审查文档） |
| ③ 文档处理 | `report/`（已是数据聚合）**输出端升级**为文件生成（POI：xlsx/docx） | 需确认 `report/` 现输出形态 |
| ② agent 执行 | 新增 `agent/`（状态机 + 工具注册表），把 `report/maintenance/notification/broadcast/skb` 注册为 tool | 工程量最大 |

## 四、客户细分口径调整

**现状**：对外统称「日本服务业」——过粗，会两腿错位。

**建议改为二维细分**：

| | **低外労** | **高外労** |
|---|---|---|
| **小规模**（单店 / 数人） | 腿 B 为主（知识 / 文书） | 腿 B 起步 → 有预算再升腿 A |
| **中规模**（连锁 / 多据点） | 腿 B + 可能腿 A（管理侧） | **腿 A 主战场**（一线多语言是刚需） |

- **低外労 × 小规模**：翻译楔子不成立 → 卖腿 B（知识 / 文书）。
- **高外労 × 中规模**：工牌价值最实 → 腿 A，腿 B 做管理 / 沉淀。
- 判定「外労占比」的实操信号：行业（製造/農業/介護/建設/清掃/飲食）+ 是否雇用技能实习 / 特定技能外国人。

## 五、补助金策略（SME 预算的钥匙）

> ⚠️ **重要**：以下机制为方向性判断，**各年度的「枠 / 補助率 / 上限 / 登録要件 / 締切」都会变**，落地前须逐项核实（中小企業庁 / 中小機構 官网 + 支援事業者）。

**主通道：IT導入補助金**
- 性质：中小企業庁 / 中小機構 主办，补助 SME 导入 IT 工具（软件 / 服务）。
- **关键机制（决定我们要做什么）**：
  1. 补助对象是**登録 IT ツール**——**厂商（我们）须先登记**该工具；
  2. SME 须经**登録済み的 IT導入支援事業者**申请（我们需与其建立合作）；
  3. 有多个枠（通常枠 / セキュリティ対策推進枠 / デジタル化基盤導入枠 等），补助率与上限各异。
- **对我们的关键含义**：
  - ✅ **该通道对「软件」友好** → **腿 B（纯 SaaS）天然适配**，是最容易进的补助标的；
  - ⚠️ **硬件（可佩戴工牌）能否纳入补助，需单独核实**（部分枠覆盖硬件，但可穿戴设备归类存疑）→ **这本身又是一个「腿 B 优先」的理由**。
  - 🎯 **动作**：登记为 ベンダー + 把腿 B 做成 登録 IT ツール + 对接若干 支援事業者（可作为渠道，与 WorkBuddy 调研的「SI 被集成」一致）。

**次通道（需核实）**：事業承継 / デジタル化 相关补助、地方自治体独自补助（各地 SME 支援中心）。

## 七、分阶段落地建议

| 阶段 | 动作 | 依据 |
|---|---|---|
| **P0（现在）** | ① 做腿 B 的**第一个能力**（自生长知识，零件齐备）；② 定位 / 细分口径调整（本文档 §四/§六） | 优先级 ① 最靠前，且它同时是腿 B 的首发功能 |
| **P1** | ③ 文档处理（`report/` 输出端升级）；评估补助金登记 | ③ 无硬件、SME 通用痛点 |
| **P2** | ② agent 执行（通用编排） | 工程量最大；对外先讲场景不讲平台 |
| **并行** | 补助金：ベンダー登记 + 支援事業者对接；Pマーク / ISMS 启动评估 | 取证周期长，须提前 |

> **与当前阶段目的的契合**：当前目的是演示 / 融资（见 [[development-purpose-2026-09]]）。腿 B 的 ①「自生长知识」既是最省力的 SME 入口，又强化「数据闭环 = 壁垒」的融资叙事——**一箭双雕**。

## 八、风险与开放问题

1. **两条腿是否会稀释「佩戴式」的差异化叙事？**
   - 判断：不会。腿 B 是**把已存在的云端核心显性化**，不是新做一块。叙事上：**工牌是入口形态，云是能力本体**。
   - 但需明确**主次**：对外主打差异化仍是工牌（重 / 难复制），腿 B 是**扩大可触达的 SME 面**。
2. **腿 B 的目标用户（事务/总务）与「一线」定位是否冲突？**
   - 需产品层拍板边界（审查文档 §8 已标）。倾向：**不冲突，但需分别命名**（一线 = 现场；后台 = 事务）。
3. **补助金登记的 ROI**：登记与维护有成本，需先确认腿 B 是否真面向 SME 走量。
4. **硬件在补助中的可纳性**：若工牌真无法纳入补助，腿 A 对 SME 的吸引力将进一步受限 → 更坚定「腿 B 优先」。
