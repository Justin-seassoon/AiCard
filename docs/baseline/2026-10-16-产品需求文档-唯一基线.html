1 · 定位与价值主张

愿景：面向日本市场的「一线经营末梢 agent」——翻译是入口，核心是让一线把事做成。

腿 A · 重

工牌线

一线员工（外劳密集）· 可佩戴设备 · 现场多语言 / 知识下沉 / 广播
腿 B · 轻

后台 AI 线

事务 / 总务职能 · 浏览器/App · 知识沉淀 / 文书 / 任务执行

靶心：日本「中小企業 标准档」（约 50–300 人，有事务职能、有预算、有稟議），不碰极小规模。

价值主张：效率 × 沉淀 —— 使用者为「效率」来用，顺手零边际成本沉淀进企业知识；知识越用越准 → 效率更高 → 更多人用。
产品红线：「成事」而非「防人」 —— 帮一线把事做成、守住红线、帮中层协调；不做实时定位、未告知/未同意的录音、摸鱼监控、承诺账簿式盯人。
会议录音是员工主动发起、明确告知的公开录音，与「暗中录音」不同：录音中有视觉/听觉提示、不可远程静默开启、访问留痕，并提供录音告知/同意话术模板。

三项新能力的优先级按零件齐备度排序：① → ③ → ②（见 §8）。本轮 demo 范围见 docs/baseline/两腿demo-范围界定.md：①②③ 全做，另加「会议纪要」云端 P0；仅排除「用户/登录/鉴权」与「多租户硬化」（故上方「后台多用户 / 登录鉴权」本轮不做，按单租户运行）。

会议纪要范围：P0 = 云端全链路（分片上传 / 转写 / 结构化纪要 / 待办 / 审核 / 导出）+ 模拟器演示 + WAV 音频导入（无麦克风/HTTP 环境）；P1 = 真机长按 + 断点续传 + 周报聚合；P2 = 说话人分离、业务分析报告。定位为「个人视角的会议笔记」（匹配工牌 0.5–1.5m 收音规格），不作会议室级正式纪要承诺。

验证状态（2026-10-23）：云端 P0 已部署测试服，并以真实 Azure 转写 + LLM 跑通「WAV 导入 → 纪要 + 待办 → 审核 → docx 导出」；HTTP 环境麦克风需 HTTPS，故测试服走 WAV 导入路径。

P1-a 状态（2026-10-30）：云端设备接口已按协议 §4 落地并部署测试服——/api/v1/meetings + Bearer、GET status、end 缺片保持 uploading、补片自动转写、统一 E_MEETING_* 错误码；真实日语语音端到端跑通。真机长按/固件录音仍待硬件。

5 · 核心场景

腿 A（0804 §3.2 为准）：酒店前台接待 / 免税店导购 / 机场服务 / 餐饮接客 / 展会接待——多语种双向沟通 + 知识即时答 + 广播调度。

腿 B（新）：

  • 「経費精算の締め日は？」→ 带依据即时答（知识沉淀）；
  • 「来月の会議の案内文を作って」→ 文书草稿作成；
  • 「今週の異常を整理して」→ 多步汇总 → 交付文档。
  • 会议场景（新增）：员工长按工牌录音 → 转写 → 标准纪要 + 待办（负责人/期限不明显示「要確認」）→ 审核 → 「本周参加的五场会」汇总为个人周报。
