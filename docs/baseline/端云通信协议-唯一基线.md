### 0.4 兼容规则

> **开发阶段约定**：项目仍在开发，现场没有旧固件 / 旧数据；所有设备统一升级到最新固件，**不保留旧版本兼容分支**。以下规则用于协议自身的持续演进。

## 1. 传输、鉴权与通用约定

### 1.1 传输分工

| 场景 | 通道 | 连接特征 | 状态 |
|---|---|---|---|
| 翻译 / 员工问答 / 广播 | WSS 会话 | 会话级短连接 | ✅ v1 |
| OTA 检查与下载 | HTTPS REST | 按需请求 | ✅ v1 |
| 会议录音 | HTTPS REST | 按需请求，不依赖 WSS | ✅ 口径已定 |
| 通知 / 待办 / 报表推送 | WSS（复用会话）或后续 HTTP | 设备在线时推送，离线补拉 | 🟡 规划 |
| 维修 / 点检任务 | 待定 | 待设计 | ⬜ 规划 |

> 原则：**实时语音走 WSS；文件、分片、任务类走 HTTPS**。会议录音不占用 WSS 长连接，避免功耗与断线重连问题。

### 1.2 鉴权

| 通道 | 当前实现 | 目标口径 | 状态 |
|---|---|---|---|
| WSS 握手 | query：`device_id` / `token` / `fw_version` / `proto_ver` | 保持（ESP32 WebSocket 方便） | ✅ |
| OTA | `Authorization: Bearer <device_token>` | 保持 | ✅ |
| 会议录音 | `Authorization: Bearer <device_token>` + `X-Device-Id` | 保持 | ✅ 已实现 |

- 设备身份由云端档案推导 `customer_id` / `store_id`；**不接受设备自报租户**。
- demo 阶段 token 静态；真实上线走短期凭证轮换（OTA 401 时先刷新凭证）。
- 生产环境必须 `wss://` / `https://`；`ws://` 仅限本地联调。

### 1.3 错误格式

**WSS**：

```json
{"type":"error","session_id":"s1","turn_id":"t1","code":"E_LID_LOW","message":"请再说一遍","fallback_action":"ask_repeat"}
```

**HTTP**：

```json
{"error_code":"E_MEETING_SEQ_CONFLICT","message":"chunk exists with different content","retryable":false}
```

- 设备按 `code` / `error_code` 处理，不解析 `message` 文案。
- WSS 错误码见 §2.9；HTTP 错误码见 §7。

### 1.4 时间、幂等与重试

- 设备时间可能不准：`started_at` 等字段云端会校正（会议录音只接受近 1 天 ~ 未来 5 分钟）。
- 写操作必须支持幂等键：会议用 `client_key` + 分片 `seq`；OTA 检查无副作用。
- 重试：网络错误 / 5xx / 429 按指数退避；4xx 参数错误不盲目重试；OTA 401 先刷新凭证。
- 音频分片建议带 SHA-256；云端按校验值判断坏片与重复片。

## 2. WSS 会话协议 v1（✅ 已冻结）

> 本节为原《端云通信接口规范 v1~v5》的合并版，字段与语义保持不变。
> 传输：全双工 WebSocket（WSS）。**音频走二进制帧，控制消息走 JSON 文本帧。**

### 2.1 连接与鉴权

- 协议：WebSocket over TLS（`wss://`）。
- 建连时机：短按翻译键 → 建连（`scope=translate`）；无活跃会话时短按问答键 → 建连（`scope=staff_qa`）；会话结束 / 空闲超时 → 断开。**会话级短连，不维持长连接。**
- 端点：

```
wss://<host>/ws?device_id=<id>&token=<t>&fw_version=<v>&proto_ver=1
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `device_id` | string | 设备唯一标识，云端签发 |
| `token` | string | 设备短期凭证（demo 静态；上线短期轮换） |
| `fw_version` | string | 端侧主固件版本（P4） |
| `proto_ver` | int | 协议版本，当前 `1` |

- 握手云端用 `device_id + token` 鉴权，失败拒绝握手（HTTP 403）。
- 鉴权成功云端由设备身份推导 `customer_id` / `store_id`；会话内消息不再带 token、不接受租户字段。

### 2.2 session_id 与 turn_id

- `session_id`：一次会话的唯一标识，设备生成（UUID），会话内所有消息带同一值。**断线重连必须生成新 session_id。**
- `turn_id`：会话内一轮对话的唯一标识，设备生成（UUID），随新 utterance 更换。
- 同一 turn 内，音频分片、对应 TTS、对应 `stop_tts` 使用同一 `turn_id`；打断后新 turn 换新 `turn_id`，`stop_tts` 指向被停的旧 `turn_id`。
- `sequence` 仅在 turn 内从 0 递增，不跨 turn 复用。

### 2.3 scope 与 translation_mode

两个独立概念：

| 概念 | 取值 | 切换消息 | 是否清 visitor_language |
|---|---|---|---|
| `scope`（会话业务域） | `translate` / `staff_qa` | `scope_change`（会话内） | **不清** |
| `translation_mode`（语言对模式） | `auto` / `fixed` | `translation_mode_change` | **清** |

`query_scope` 由 `scope` 派生：`translate → customer`、`staff_qa → staff`。端侧只传 `scope`，云端从 scope 派生（不信任端侧传的 query_scope）。

**键 → 状态迁移表（写死）**：

| 当前状态 | 按键 | 动作 |
|---|---|---|
| 待机（无会话） | 短按翻译键 | 建连，`scope=translate` |
| 待机（无会话） | 短按问答键 | 建连，`scope=staff_qa` |
| translate 会话中 | 短按问答键 | `scope_change → staff_qa`（保留 visitor_language） |
| staff_qa 会话中 | 短按翻译键 | `scope_change → 返回进入前状态`（从 translate 进→回 translate；从待机直进→结束会话回待机），保留 visitor_language |
| staff_qa 等待中 | 短按问答键 | 取消本轮提问，保持 staff_qa |
| staff_qa 播放中 | 短按问答键 | `stop_tts` 停止当前答案播放，保持 staff_qa |
| translate 会话中 | 短按翻译键 | 结束会话（断开，清 visitor_language） |
| 任一状态 | 空闲超时 | 结束会话（断开，清 visitor_language） |

**staff_qa 约束**：

- staff_qa 内**不执行 LID、不建立/更新 visitor_language**（冻结语言记忆）。
- staff_qa 内 `translation_mode_change` **非法，云端忽略**。

### 2.4 帧结构总览

| 帧类型 | 方向 | 编码 | frame_type |
|---|---|---|---|
| 音频分片 | 端 → 云 | 二进制帧 | `0x01` |
| TTS 音频 | 云 → 端 | 二进制帧 | `0x81` |
| 控制消息 | 双向 | JSON 文本帧（UTF-8） | — |

- 帧头多字节整数 **大端 big-endian**；音频 PCM 采样值 **小端 little-endian**（与 WAV 一致）。
- frame_type 高 4 位分方向：`0x0x` 上行、`0x8x` 下行。

#### 2.4.1 上行音频帧（`0x01`）

```
偏移  长度      字段
0     1 byte    frame_type = 0x01
1     1 byte    turn_id_len = N（1~255）
2     N bytes   turn_id（UTF-8，UUID）
2+N   4 bytes   sequence（uint32 大端，turn 内从 0 递增）
6+N   8 bytes   timestamp（uint64 大端，会话内相对毫秒，自建连起）
14+N  1 byte    source_side：0=wearer 1=counterparty 2=uncertain
15+N  1 byte    input_source：0=badge_near 1=badge_far 2=headset_mic 3=uncertain
16+N  剩余       audio_payload（裸 PCM：PCM16 · 16kHz · 单声道 · little-endian，不含 WAV/RIFF 头）
```

> `input_source` 以帧级为准；`eou` / `session_init` 的 input_source 为句级/会话级参考，冲突时以帧级为准。

#### 2.4.2 下行 TTS 帧（`0x81`）

```
偏移  长度      字段
0     1 byte    frame_type = 0x81
1     1 byte    turn_id_len = N
2     N bytes   turn_id（UTF-8，UUID）
2+N   剩余       tts_audio（RIFF/WAV：44 字节 WAV 头 + PCM16 · 16kHz · 单声道 · little-endian，流式分片）
```

> 流结束由 JSON `tts_end` 标记，TTS 帧本身不带结束标记。`0x81` 只带 turn_id，不带 session_id。

#### 2.4.3 JSON 控制消息

- UTF-8 JSON，以 `type` 区分；字段 snake_case；未出现字段视为 null / 缺省。
- JSON 控制消息统一带 `session_id`（`0x81` 二进制帧例外）。

### 2.5 上行消息

#### 2.5.1 会话初始化 `session_init`（建连后首条，必发）

> 示例中的 `features` 为新增字段；新固件必须上报。其余字段已冻结。

```json
{
  "type": "session_init",
  "session_id": "s1",
  "scope": "translate",
  "staff_language": "ja-JP",
  "translation_mode": "auto",
  "lang_pair": "zh-ja",
  "headset_state": "disconnected",
  "input_source": "badge_far",
  "wifi_band": "5GHz",
  "network_state": "good",
  "config_version": 123,
  "candidates": ["ja-JP", "zh-CN", "en-US", "ko-KR"],
  "features": ["meeting_recording"]
}
```

| 字段 | 说明 |
|---|---|
| `scope` | `translate` / `staff_qa`（会话初始业务域） |
| `staff_language` | 当前员工语言（双向翻译锚点；员工问答也按此语言识别与回答，知识库为日语时云端自动翻译） |
| `translation_mode` | `auto` / `fixed` |
| `lang_pair` | `fixed` 时填写（如 `zh-ja`）；auto 可空 |
| `headset_state` | `disconnected` / `connected` / `input_error` / `output_error` |
| `input_source` | 当前主输入通道 |
| `wifi_band` / `network_state` | 网络状态（运营分析用） |
| `config_version` | 设备当前配置版本号（pull 比对用） |
| `candidates` | 当前门店候选语种集 |
| `features` | 设备支持的能力列表（如 `meeting_recording`）；新固件必须上报 |

> `query_scope` 由 `scope` 派生，端侧不传。

#### 2.5.2 二进制音频帧（`0x01`）

见 §2.4.1。持续流式上传，每帧一个分片。

#### 2.5.3 尾包 `eou`

```json
{"type":"eou","session_id":"s1","turn_id":"t1","source_side":"counterparty",
 "last_sequence":23,"utterance_duration_ms":1500,"input_source":"badge_far"}
```

| 字段 | 说明 |
|---|---|
| `source_side` | 该句说话方 |
| `last_sequence` | 该 turn 最后分片 sequence 号（收齐校验） |
| `utterance_duration_ms` | 有效语音时长（质量门控用） |
| `input_source` | 该句实际输入通道（与帧级冲突时帧级为准） |

#### 2.5.4 打断上报 `stop_tts`

```json

```

`reason`：`voice`（语音抢占）/ `button`（按键停止）。

#### 2.5.5 睡眠上报 `sleep_notice`

```json
{"type":"sleep_notice","session_id":"s1"}
```

#### 2.5.6 按键事件 `button_event`

```json
{"type":"button_event","session_id":"s1","button":"ok"}
```

> `button:"ok"` 为 VKB 候选确认：游客提问翻译成日语后，云端先撞 VKB，命中则「嘀嘀」提示服务人员，服务人员按 OK 后云端把答案反向翻译成游客语言播放；未命中 / 超时回退播翻译原文。

#### 2.5.7 播放事件 `playback_event`

#### 2.5.8 业务域切换 `scope_change`

> `query_scope` 由 `scope` 派生，端侧不传。



### 2.6 下行消息

#### 2.6.1 二进制 TTS 帧（`0x81`）

见 §2.4.2。流式下发，首帧即播。

#### 2.6.2 TTS 流结束 `tts_end`

```json

```

#### 2.6.3 错误 `error`

```json
{"type":"error","session_id":"s1","turn_id":"t1","code":"E_LID_LOW","message":"请再说一遍","fallback_action":"ask_repeat"}
```

> `turn_id` 在会话级错误（E_AUTH / E_NET / E_SESSION）可缺省；`session_id` 必带。

#### 2.6.4 文本 `final_text` / `partial_text`

```json
{"type":"final_text","session_id":"s1","turn_id":"t1","text":"你好"}
```

> 端侧不显示，仅调试 / 日志。

#### 2.6.5 知识库答案 `answer`

```json
{"type":"answer","session_id":"s1","turn_id":"t1","text":"早餐时间为 7:00-10:00","source_refs":["早餐FAQ@v1#42"]}
```

> 员工知识库（SKB）答案，TTS 音频随后用 `0x81` 帧下发。

#### 2.6.6 语言状态 `language_state`

```json
{"type":"language_state","session_id":"s1","turn_id":"t1","visitor_language":"zh-CN","lid_language":"zh-CN","confidence":0.92,"state":"locked"}
```

`state`：`unknown` / `locked` / `updating` / `reset` / `conflict`。

> `translation_mode=fixed` 时：`visitor_language` 显示为 `lang_pair` 对端语种（固定，不跑 LID）；`translation_mode_change` 后云端回 `language_state(state=reset)`，端侧据此刷新屏幕。

#### 2.6.7 配置下发 `config_update`

```json
{"type":"config_update","session_id":"s1","config_version":124,"config":{...}}
```

config 结构见 §5。

#### 2.6.8 输出路由 `output_route`

```json
{"type":"output_route","session_id":"s1","turn_id":"t1","route":"speaker"}
```

> 耳机 P1 后置，字段预留；`output_route` 必须先于 TTS 首帧到达。

#### 2.6.9 广播 `broadcast`

```json
{"type":"broadcast","broadcast_id":42,"text":"Thông báo an toàn","target_language":"vi-VN"}
```

| 字段 | 说明 |
|---|---|
| `broadcast_id` | 广播 ID（回执 `broadcast_ack` 用） |
| `text` | 该设备母语的译文（彩屏显示） |
| `target_language` | 译文语言 |

> - 广播是**设备级**消息，不绑定翻译会话，`session_id` 可缺省。
> - 随后译文 TTS 用 `0x81` 帧下发，`turn_id = "bc"+broadcast_id`（如 `bc42`），以 `tts_end` 结束。
> - 收到后设备显示译文 + 播放 TTS；用户按 OK 回执 `broadcast_ack`。

### 2.7 关键时序

#### 2.7.1 翻译链路

```
设备 ──(握手鉴权)──► 云端
设备 ──session_init──► 云端
设备 ──0x01 音频分片×N──► 云端
设备 ──eou──► 云端（last_sequence 收齐校验）
云端：说话方判定 → LID → ASR → MT → TTS
云端 ──0x81 TTS 分片×N──► 设备
云端 ──tts_end──► 设备
设备 ──playback_event(completed)──► 云端
```

- 员工发言（source_side=wearer）→ 翻译为 visitor_language 外放；游客发言（counterparty）→ LID 判向、翻译为 staff_language。
- 固定语言对（translation_mode=fixed）→ 跳过 LID，按 lang_pair 双向翻译。

#### 2.7.2 VKB 自动应答

```
游客 ──0x01 音频×N──► 云端（auto 一步翻译）
云端：翻译成日语译文 → 撞 VKB 知识库
  ├─ 命中：
  │    云端 ──0x81「嘀嘀」提示音──► 设备（不播翻译原文）
  │    云端 ──language_state──► 设备
  │    服务人员按 OK → button_event(button:ok) ──► 云端
  │    云端：答案反向翻译成游客语言 → 0x81 播放 + tts_end
  │    或 5s 超时未确认 → 回退播翻译原文(0x81) + tts_end
  └─ 未命中：
       云端 ──0x81 翻译原文 + tts_end──► 设备
```

#### 2.7.3 员工知识库问答（scope=staff_qa）

```
设备 ──scope_change(staff_qa)──► 云端（同一 session，保留 visitor_language）
设备 ──0x01 音频分片×N──► 云端
设备 ──eou──► 云端
云端：ASR(staff_language) → 向量检索 → 受控 RAG → LLM 受限生成 → 校验
云端 ──answer(JSON: text + source_refs)──► 设备
云端 ──0x81 TTS 分片×N──► 设备
云端 ──tts_end──► 设备
设备 ──scope_change(translate) / 短按翻译键退出问答──► 云端
```

> **多语言问答（2026-10-31）**：知识库正文为日语。非日语员工按 `staff_language` 识别问题，云端先把问题翻译成日语再检索，回答通过既有校验后再翻译回 `staff_language` 并用对应音色播报；日语员工走原链路，不增加额外调用。`staff_language` 由设备档案 / `session_init` 决定，不是自动语种判定——员工换语言时需切换对应档案或会话语言。

#### 2.7.4 TTS 打断

```
设备播放中：检测到新语音 / 按键
  ├─ 本地：停播 + 清缓存 + 复位拾音（≤100ms，断网可用）
  └─ 异步：stop_tts(旧 turn_id) ──► 云端（停合成 + 释放 + 记账，不再补发 tts_end）
```

- **严禁以断开 WSS 实现打断。**
- 迟到 TTS 分片 / tts_end 按 turn_id 丢弃；云端容忍中途停流。

#### 2.7.5 断线重连

- 网络断线 = 会话结束、visitor_language 清空；重连必须生成新 session_id 重新握手，回到 UNKNOWN。
- 1.0 不做会话恢复窗口，2.0 再评估。

#### 2.7.6 广播链路

```
管理员 ──REST 发广播（群 + 源文本 + 源语言）──► 云端
云端：查群成员 → 按 target_language 去重 → 每种语言翻译一次 + TTS 一次
  ├─ 在线成员：broadcast(JSON) → 0x81 TTS 分片 → tts_end（实时推，标已投递）
  └─ 离线成员：标「未投递」，重连后补拉
设备：显示译文 + 播放 TTS → 用户按 OK
设备 ──broadcast_ack(broadcast_id)──► 云端（回执）
```

- 离线补拉：设备 `session_init` 后，云端查未投递广播 → `broadcast` → `0x81` → `tts_end`。
- 广播**不保证离线实时到达**；待机 Deep Sleep 不维持长连接，下次唤醒 / 建连补拉。
- 同语言成员共享同一份译文 + TTS（去重，省成本）。

### 2.9 WSS 错误码

| 错误码 | 场景 | 设备端行为 |
|---|---|---|

| `E_QA_OUT_OF_SCOPE` | 范围外问题 | 播兜底话术（可配置） |
| `E_CONFLICT` | 输入来源 / 语言冲突、重叠讲话 | 提示「请依次说话 / 重新说」；不播放 |

### 2.10 已冻结参数

| 参数 | 冻结值 | 说明 |
|---|---|---|
| 采样率 | 16kHz | 端侧 / 云端一致 |
| 音频编码 | PCM16 单声道；上行裸 PCM（不含头），下行 TTS 带 44 字节 WAV 头 | v1 固定；Opus 需协商 |
| 上行帧长 | 100ms | 每 `0x01` 帧约 100ms 音频 |
| TTS 下行分片 | ≤8KB（约 100ms） | 首帧即播 |
| 单帧上限 | ≤8KB | 音频分片上限 |
| 心跳 | 10s | WS ping/pong，连续 2–3 次无 pong 判死 → 断线重连 |
| 会话空闲超时 | 20s | 无有效语音 / 按键自动结束并断开 |
| LID 阈值 θ / θ_super | 不适用（移除） | auto 模式用一步 auto-detect，不依赖置信度 |

### 2.11 甲方硬性要求（TTS 打断三条）

1. 端侧打断四步 ≤100ms、断网可用（产品级验收）。
2. P4 ↔ IA8201 必须有 AEC 播放参考通路（语音抢占打断的前提）。
3. 迟到 TTS 分片按 turn_id 丢弃、云端容忍中途断流不记错。

## 3. OTA 协议 v1（✅ 已冻结）

> 通道：独立 HTTPS REST + 签名下载，不经 WSS。OTA 不依赖翻译会话、不维持常驻连接。
> 权威依据：原《OTA 协议确认 · 端云冻结版》（2026-09-22）。

### 3.1 分权原则

- **云端决定**：升到哪个版本、是否必须升。
- **端侧决定**：当前是否具备安全升级条件（电量、存储、回滚槽等）。
- 强制策略不能绕过端侧校验与供电保护。

### 3.2 检查更新 `POST /api/v1/ota/check`

鉴权：`Authorization: Bearer <device_token>`。云端校验凭证与 `device_id` 绑定；租户、门店、灰度分组由云端设备档案推导，不信任设备自报。

请求字段（均必填）：

| 字段 | 类型 / 约束 | 含义 |
|---|---|---|
| `device_id` | string，1–64 | 云端已登记设备 ID |
| `product_model` | string，1–32 | 产品型号，须与设备档案一致 |
| `hardware_version` | string，1–32 | 板卡硬件版本；开发板与正式板必须区分 |
| `current_versions.p4` | string，1–31 | P4 自身运行镜像 `esp_app_desc.version` |
| `current_versions.c5` | string，1–31 | P4 经 SDIO 实时读取，禁止历史缓存猜测 |
| `trigger` | enum `boot` / `manual` / `pre_install` | 检查触发场景 |

> 无法读取 C5 版本时，显示模块通信异常并重试，不发送伪造版本、不启动依赖版本组合的升级。

`HTTP 200` 响应：

| 字段 | 类型 / 必填 | 含义 |
|---|---|---|
| `update_available` | boolean / 是 | 是否存在适用更新 |
| `update` | object 或 `null` / 是 | 有更新为下表对象，无更新固定 `null` |
| `reason` | enum / 无更新时必填 | `UP_TO_DATE` 已是适用版本；`NO_APPLICABLE_RELEASE` 暂无适用发布（不能提示「已是最新」） |

`update` 对象：

| 字段 | 类型 / 约束 | 含义 |
|---|---|---|
| `update_id` | string，1–64 | 固定配套发布标识；目标组合、包内容、策略或顺序变化时更换；刷新 URL、按进度省略已完成模块时不变 |
| `policy` | `optional` / `mandatory` | 整份清单的普通 / 强制策略 |
| `target_versions.p4` | string，1–31 | P4 必须达到的准确运行版本 |
| `target_versions.c5` | string，1–31 | C5 必须达到的准确运行版本 |
| `packages` | array，1–2 | 仅含实际版本尚未达标的模块，按发布顺序排列 |
| `release_notes` | string，≤256 | 简短说明，不决定是否强制，屏幕可截断 |

`packages[]` 每项：

| 字段 | 类型 / 约束 | 含义 |
|---|---|---|
| `module` | `p4` / `c5` | 写入对象；其他模块拒绝 |
| `target_version` | string，1–31 | 必须等于 `target_versions[module]` 且逐字节等于镜像内版本 |
| `image_size` | integer | 最终 `.bin` 字节数；>0 且 ≤ 对应芯片备用 OTA 槽容量 |
| `sha256` | string，64 hex | 对完整 `.bin` 计算的 SHA-256 |
| `download_url` | string，HTTPS，≤511 | 短期签名 URL；仅下载用，不落日志 / NVS |
| `expires_in_sec` | 正整数 | 自签发起有效秒数，建议 ≥3600，安装前重取 |

**端侧清单校验**：实际 `current_versions` 与 `target_versions` 逐项比较，不相等的模块必须且只能各有一个包；包目标版本与配套目标一致；缺包 / 目标字段不全 / 重复模块 / 未知模块 / 版本不符 → 拒绝整份清单。执行前再次读本地版本，已变化则重查。

**查询错误约定**（任何错误都不能解释为「无更新」）：

| 状态码 | 场景 | 端侧行为 |
|---|---|---|
| `400` | 参数错误 | 停止盲目重试 |
| `401` | 凭证失效 | 先走设备凭证更新流程 |
| `403` | 设备无权限 | 停止盲目重试 |
| `429` | 限流 | 遵循 `Retry-After` |
| `5xx` / 网络错误 | 服务异常 | 按退避重试 |

统一 JSON：`{"error_code":"UNAUTHORIZED","message":"device credential expired"}`。

### 3.3 下载固件 `GET {download_url}`

输入为 `packages[]` 的 `download_url`，P4 发 HTTPS GET；鉴权由签名 URL 承载，**不向固件域名转发设备接口的 Bearer Token**。

| 输出 | 契约 |
|---|---|
| HTTP 状态 | 成功必须 `200` |
| `Content-Type` | `application/octet-stream` |
| `Content-Length` | 必须等于 `image_size`，实收字节数一致 |
| 响应体 | 与 `module` 匹配的完整 P4 / C5 应用 `.bin`；非整片 Flash 合并镜像、非 JSON / Base64 包装 |
| 传输限制 | 不使用重定向、chunked、压缩编码、Range 续传；中断整包重下 |

> 完整文件 SHA-256 用于一致性校验，不替代固件签名；量产前确认是否启用官方签名校验及密钥配置。
> **C5 不直连云端**：P4 下载 C5 固件后，经 SDIO 下发给 C5。

### 3.4 后台发布接口（内部）

| 接口 | 用途 |
|---|---|
| `POST /api/ota/releases` | 发布 / 登记固定配套版本（元数据 + 云端复核 sha256 / size） |
| `GET /api/ota/releases` | 发布列表 |
| `POST /api/ota/releases/{id}/revoke` | 撤销发布 |

- 同一时刻只有一个 `active` 发布；发布新 release 自动撤销旧的。
- `packages[]` 只放实际版本还没达标的模块（1–2 项），顺序即执行顺序。
- 云端发布时重新读文件复核 sha256 / size，不一致返回 400。

### 3.5 平台前提与联调验收

待端侧冻结：

1. C5 出厂 SDIO OTA 能力、备用槽（A/B）实际容量
2. P4 暂存空间位置与容量（不得占用运行 / 回滚槽）
3. 电量门槛、SDIO 超时、两侧自检与回滚条件
4. 固件下载域名 + CA 证书链
5. 设备凭证获取 / 刷新流程（对应 401 处理）
6. 首次查询失败放行规则、强制更新交互细节

验收项：

1. 首次联网 / 手动检查、普通 / 强制策略、P4 自身 OTA 与 C5 经 SDIO OTA
2. 必需包缺失、目标字段缺失、包版本错误、无安全中间组合时拒绝执行
3. C5 成功后 P4 下载失败 / 启动回滚 / 断电；重启后限制仍在，只恢复未完成模块
4. 相同目标版本但启动尚未确认时，不误判整次成功
5. 半更新时撤销、降为普通、返回无更新或查询失败，不解除恢复状态
6. 完整恢复起始组合时按普通 / 强制策略处理；完整目标组合验证通过后才恢复业务

> **范围**：升级进度 / 成功 / 失败 / 回滚由端侧本地显示与记录，云端不落过程日志；IA8201 参数、Bootloader、分区表 1.0 不在本通道，另立。

### 3.6 OTA 实现差异（需确认）

| 项 | 冻结稿要求 | 当前实现 | 影响 |
|---|---|---|---|
| 固定配套 | 维护「起始组合 → 中间组合 → 目标组合」迁移表 | 只按唯一 active release 的目标版本返回待装包 | 若芯片存在「必须先升中间版本」依赖，需补迁移表 |
| 灰度 | 字段预留、默认全量 | 一致 | — |
| 结果感知 | 下次 check 被动感知 | 一致 | — |
| 错误格式 | `{error_code, message}` | 一致 | — |

> **结论**：开发阶段无旧版本，**1.0 不做中间组合迁移表**；发布时保证任意支持版本可直达目标。若端侧确认 P4 / C5 存在「必须先升中间版本」的依赖，再补迁移表。

## 4. 会议录音 HTTP API v1（✅ 云端已实现，待端侧联调确认）

> 设备接口：`/api/v1/meetings`，鉴权 `Authorization: Bearer <device_token>` + `X-Device-Id`。
> 实现状态（2026-10-30）：`start / chunk / end / status` 已按本节实现并部署测试服；旧路径 `/api/meetings/*` 与 `X-Device-Token` 已移除。
> 错误信封：`{"error_code","message","retryable"}`。

### 4.1 流程

```
长按开始
  → 本地提示（提示音 / 指示灯 / 屏幕「录音开始」）
  → POST /api/v1/meetings（client_key 幂等）
  → 按协商分片时长（端侧按 PSRAM 选择 5–30 秒）录音分片
  → PUT /chunks/{seq}（sha256，失败重试）
  → 长按结束
  → POST /end（last_seq 必填）
  → 返回缺片列表 → 补传
  → 设备显示「上传完成 / 转写中」
  → 可选：云端通知「纪要已生成」
```

### 4.2 鉴权

- `Authorization: Bearer <device_token>` + `X-Device-Id: <device_id>`
- 与 OTA 共用同一套设备凭证。

### 4.3 开始 `POST /api/v1/meetings`

请求：

| 字段 | 必填 | 说明 |
|---|---|---|
| `client_key` | 是 | 设备生成的幂等键；重试用同一个 |
| `started_at` | 否 | 设备本地时间；云端校正 |
| `codec` | 否 | v1 固定 `pcm16` |
| `sample_rate` | 否 | v1 固定 `16000` |
| `chunk_sec` | 是 | 端侧按 PSRAM 预算选择 5/10/15/20/30（优先 15；≥2MB 可用 30） |
| `title` | 否 | 会议标题 |
| `fw_version` | 是 | 设备固件版本；云端按最低版本拦截 |
| `features` | 是 | 设备能力列表，如 `["meeting_recording"]` |
| `trigger` | 是 | 固定 `long_press`（现场按键触发，禁止远程静默开启） |
| `notice_played` | 是 | 开始录音提示是否已播放（合规留痕） |
| `notice_version` | 否 | 提示话术版本 |

> 当前后端 `codec` 字段接受 `pcm16 / opus / adpcm`，但转写链路只按 PCM16 处理；v1 协议冻结为 `pcm16`，Opus 需先补解码。
> 现场提示话术与是否二次确认待产品 / 合规；v1 技术方案为本地提示 + `notice_played` 留痕。
> `fw_version` 必填；云端配置 `meeting.min-fw-version` 暂留空（只校验非空、不做版本比较），端侧给出首个支持版本后再启用拦截。

响应：

| 字段 | 说明 |
|---|---|
| `meeting_id` | 会议 ID |
| `status` | `recording` |
| `chunk_sec` | 实际分片时长 |
| `max_chunk_bytes` | 单片上限（当前 2MB） |
| `retention_days` | 音频保留天数（当前 30） |
| `chunk_url` | 分片地址模板 |
| `audio_expires_at` | 音频到期时间 |

### 4.4 上传分片 `PUT /api/v1/meetings/{id}/chunks/{seq}`

- `Content-Type: application/octet-stream`
- `X-Chunk-Sha256`：建议必填
- 成功 `204`
- 重复上传同内容幂等；同序号不同内容 `409`
- 超过 `max_chunk_bytes` → `413`
- 会议已结束 / 已过期 → `409 / 410`

### 4.5 结束 `POST /api/v1/meetings/{id}/end`

请求：`{ "last_seq": 123 }`（**必填**）

响应（有缺片时保持可补传状态）：

```json
{
  "meeting_id": "mtg-...",
  "status": "uploading",
  "expected_last_seq": 123,
  "missing_seqs": [7, 8],
  "auto_finalize_after_sec": 600,
  "duration_sec": 3720
}
```

- `missing_seqs` 为空 → 云端可直接转写，返回 `status: "transcribing"`。
- `missing_seqs` 非空 → 保持 `status: "uploading"`，设备按列表补传，补传后**再次调用 `end`**；10 分钟无新分片自动转写。
- 不传 `last_seq` 时云端只能按已收到的最大序号处理，**无法发现末尾丢片**，所以协议层必填。
- 重复调用 `end` 时，`last_seq` 取已记录的最大值；不允许减小。

> ✅ **实现状态（2026-10-29）**：`end` 有缺片时保持 `uploading` 并返回 `missing_seqs`；补片期间只接受 `seq <= expected_last_seq`；补齐后云端自动转写（设备再次调用 `end` 也幂等）。
> **已定口径**：`end` 有缺片保持 `uploading`；设备补片后**再次调用 `end`**；10 分钟无新片自动转写；不新增 `finalize` 接口。

### 4.6 状态查询 `GET /api/v1/meetings/{id}`

返回：`status`、`last_seq`、`expected_last_seq`、`missing_seqs`、`uploaded_count`、`audio_expires_at`、`error_message`。

用途：设备重启、断网重连、上传失败后恢复。

### 4.7 取消 `POST /api/v1/meetings/{id}/abort`（可选）

用于用户取消、录音作废；是否删除已上传音频需产品 / 合规确认。

### 4.8 状态机

```
recording → uploading → transcribing → drafting → draft → reviewed
                                  ↘ failed
```

- `recording` / `uploading` 接受分片。
- `end` 无缺片 → `transcribing`；有缺片 → 保持 `uploading`（10 分钟无新片自动转写），仍接受补片。
- 补片期间只接受补片，不接受新 turn / 超出 `expected_last_seq` 的序号；补齐或超时 → `transcribing`。
- `failed` 可由后台重试。

> 补片窗口已实现：`end` 有缺片保持 `uploading`，补齐或超时后转写。

### 4.9 限制

| 项 | 值 |
|---|---|
| 音频格式 | PCM16 / 16kHz / 单声道（v1） |
| 分片时长 | 默认 30 秒，允许 5–30（受 PSRAM 约束） |
| 单片上限 | 2MB（传输上限；30 秒 PCM16 约 960KB） |
| 本地缓存 | 1–2 个分片（按分片时长，约 10–60 秒），不做长时间离线缓存 |
| PSRAM 预算 | 待端侧确认；按预算在 5/10/15/20/30 秒中选择分片 |
| 单会议时长 | 建议 ≤2 小时（WAV 导入上限） |
| 音频保留 | 30 天（到期删除音频，保留转写与纪要） |
| 无新分片自动结束 | 10 分钟 |

> **P4 资源约束**：16MiB Flash + 16MiB PSRAM；Flash 已用于应用、双 OTA 槽、NVS、coredump，不能作为会议录音长期缓存；PSRAM 需与应用 / 音频 / 网络 / 显示共享。因此只保留 1–2 个分片，不做 5–10 分钟离线缓存。

### 4.10 设备侧行为

- 同一设备同一时刻只允许一个进行中的会议；重复 `start` 用同一 `client_key` 返回原会议。
- 本地录音缓存：只缓存 1–2 个分片（按分片时长，约 10–60 秒）；不做长时间离线缓存。
- 网络中断超过缓存时：停止录音并提示用户；已录分片尽量上传，缺片通过 `missing_seqs` 反映。
- 分片时长：端侧按可用 PSRAM 在 5/10/15/20/30 秒中选择，`start` 时传入；云端按实际值处理。
- 上传失败：指数退避（1s / 2s / 4s / 8s，最多 5 次），仍失败则本地保留并在下次联网补传。
- 结束前必须把本地缓存全部分片尝试上传；`end` 返回缺片后按列表补传。
- 设备屏幕只显示「录音中 / 上传中 / 已完成 / 失败」，不显示转写文本。
- **只能由现场按键触发**；开始录音必须有本地提示；**不提供远程静默开启接口**。

### 4.11 HTTP 错误码

| 错误码 | 场景 | 设备行为 |
|---|---|---|
| `E_MEETING_AUTH` | 鉴权失败 | 刷新凭证，不重试上传 |
| `E_MEETING_INVALID_ARGUMENT` | 参数缺失 / 非法（`last_seq` 缺失、`trigger` 非 `long_press`、`notice_played=false`、`codec`/`sample_rate` 不支持） | 停止，修正请求 |
| `E_MEETING_UNSUPPORTED_FW` | 固件低于最低版本 / 缺少 `meeting_recording` | 升级固件后重试 |
| `E_MEETING_FEATURE_DISABLED` | 云端未开启会议功能 | 停止，提示未开通 |
| `E_MEETING_NOT_FOUND` | 会议不存在 / 不属于该设备 | 停止，提示 |
| `E_MEETING_STATE` | 已结束 / 不接受分片 | 查状态后决定 |
| `E_MEETING_EXPIRED` | 音频已过期 | 停止，提示 |
| `E_MEETING_TOO_LARGE` | 单片超限 | 减小分片后重传 |
| `E_MEETING_SEQ_CONFLICT` | 同序号不同内容 | 停止该片，人工确认 |
| `E_MEETING_SHA_MISMATCH` | 校验失败 | 重传该片 |
| `E_MEETING_RATE_LIMIT` | 限流 | 退避重试 |

```json
  }

```

| 类型 | 字段 | 生效时机 |
|---|---|---|
| 静态配置 | `staff_language` / `lang_pairs` / `lid_theta` / `lid_theta_super` / `min_utt_duration_ms` / `kws_whitelist` / `brand_words` / 数字过滤 / `idle_timeout_ms` / 音量 / `endpoint` | 设备唤醒 pull 时生效 |
| 会话动态 | 兜底话术更新 / 强制扬声器 | 会话中 `config_update` 推，低频 |

- 静态配置：设备唤醒 / 重连 `config_pull` 时生效。
- 会话动态：兜底话术、强制扬声器，低频 `config_update` 推。
- `features` 为新增字段，新固件必须上报；`meeting` 由云端下发。

> ⚠️ LID 策略仍缺「第三语言处理」「软锁定连续 N 次 / 更新阈值」等可配置项，联调前在后台 LID 策略域补齐（架构 §11 语言策略域）。

### 5.2 能力协商

> 我方口径已定；当前 `session_init` 尚未解析 `features`，云端也未做最低版本拦截，需按 §8.2 实现。

| 字段 | 方向 | 说明 |
|---|---|---|
| `features` | 设备 → 云（`session_init`） | 设备支持的能力，如 `meeting_recording` |
| `features` | 云 → 设备（`config_update`） | 云端开启的能力 |
| `fw_version` | 设备 → 云（握手） | 云端按最低版本拦截功能 |
| `config_version` | 双向 | 配置版本比对 |

- 云端双重校验：`features` 包含能力 + `fw_version ≥ 最低版本`。
- 设备未上报 `features` 视为实现错误；云端拒绝相关新功能（开发阶段不做旧固件回退）。
- OTA 只负责发固件，不承载功能开关。

### 6.1 设备诊断日志 `POST /api/v1/device/logs`（✅ 2026-10-30）

用途：端侧上传排障日志（会议录音、OTA、WSS 均可），云端留存供远程诊断。

鉴权：`Authorization: Bearer <device_token>` + `X-Device-Id`。

请求头（除鉴权外均可选）：

| 头 | 说明 |
|---|---|
| `Content-Encoding: gzip` | 请求体为 gzip |
| `X-Meeting-Id` | 关联会议 ID（`[A-Za-z0-9_-]{1,64}`） |
| `X-Fw-Version` | 固件版本，≤32 |
| `X-Log-Level` | `debug` / `info` / `warn` / `error`，默认 `info` |
| `X-Log-From` / `X-Log-To` | ISO-8601 时间范围 |

请求体：纯文本 / JSONL，**压缩后 ≤256KB**；gzip 解压后 ≤1MB。

响应 `201`：

```json
{"log_id":"dlog-...","size_bytes":1234,"raw_size_bytes":5678,"expires_at":"2026-11-06T00:00:00Z"}
```

限制：

| 项 | 值 |
|---|---|
| 单设备频率 | 1 次/分钟（`429 E_DEVICE_LOG_RATE_LIMIT`） |
| 保留 | 7 天（到期删文件与索引） |
| 存储 | 共享卷 `/data/device-logs`，DB 只存索引 |

后台：

- `GET /api/device-logs?device_id=&meeting_id=&from=&to=&limit=` 列表（租户隔离）
- `GET /api/device-logs/{log_id}` 下载文本（gzip 自动解压）

> 合规：日志中**不得**包含设备 token、音频、转写正文、用户个人信息；云端只做存储与下载，不做内容回传。
