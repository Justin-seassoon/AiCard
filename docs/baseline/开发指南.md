## 2. 包结构与分层

按**领域**分包（`com.aicard.*`），非按技术层：

```
gateway/      设备接入（WSS 网关 / 协议 / 会话 / 状态 / 推送）
translation/  翻译主链路（编排 / LID / 质量门控）
provider/     供应商抽象（SpeechProvider + azure/mock/routing）
skb/          知识库（受控 RAG：service / store / provider / seed / handler / web）
broadcast/    分组多语言广播（群组 / 广播 / 投递）
notification/ 运营通知（定时推送）
report/       周报/月报聚合
maintenance/  维护 / 点检
ota/          固件发布
ingestion/    旁路采集（数据飞轮）
admin/        运营后台 REST（controller / dto / auth）
common/       租户 / 领域实体 / 仓储 / 配置 / web
scheduling/   调度配置
```

**约定**：新增能力**开新包**（如 ① → `skb/curation/`，② → `agent/`），不要塞进已有包。

## 3. 租户（最重要，最容易踩坑）

**模型**：`customer → store → device`；`TenantContext`（`common/tenant/`）是 **ThreadLocal**，由 filter 在请求处理期间写入。

**规则**：
1. **Servlet 请求内**：用 `TenantContext.require()` 取租户；由 `AdminContextFilter`（后台）或 gateway 鉴权写入。
2. **⚠️ 异步 / 后台任务里 `TenantContext` 是空的**——`@Async` 线程、`@Scheduled` 任务**取不到**租户，`require()` 会抛 `IllegalStateException`。
3. **因此**：异步/后台代码必须**显式传 `customerId`/`storeId` 参数**（见 `IngestionService`、`ReportService.generateDue`、`NotificationPollingJob`），**不要**依赖 ThreadLocal。

> 这是**技术基线 C5**（② agent 落地前必须设计「租户跨异步传递」机制）。当前**没有**该机制——新写异步代码请照现行做法显式传参。

**仓储约定**：仓储查询**强制**带 `customer_id`（+ `store_id`），从 `TenantContext` 取，不信任请求体（见 `DeviceScopedRepository`）。

## 4. 数据访问

| 场景 | 用什么 | 例 |
|---|---|---|
| 租户实体 CRUD | Spring Data JPA | `common/domain` + `*Repository` |
| 知识库 / 报表 / 复杂聚合 | `JdbcTemplate`（含 pgvector） | `skb/store/KnowledgeStore`、`report/repository/ReportQueryService` |

- **改 schema 一律加 Flyway 迁移**（`V{next}__xxx.sql`），`ddl-auto=validate` 会在启动时校验实体与库一致。
- 新表记得写 `customer_id`/`store_id` + 复合索引（租户过滤是常态）。

## 5. 供应商抽象

- `provider/api/SpeechProvider`（语音：LID/ASR/MT/TTS）、`skb/provider/LLMProvider`、`skb/provider/EmbeddingProvider`。
- **无 key 时装配 Mock**（`MockSpeechProvider` / `MockLlmProvider` / `MockEmbeddingProvider`）——本地开发无需真实凭证即可跑通。
- 复用而非新造：腿 B 的 LLM 调用直接注入 `LLMProvider`。

---

## 6. 异步与定时

- `@EnableAsync`（`AiCardApplication`）、`@EnableScheduling`（`SchedulingConfig`，`ThreadPoolTaskScheduler` pool=2）。
- **旁路/非关键**任务用 `@Async` + **静默降级**（失败不影响主链路，见 `IngestionService`）。
- **定时任务**：cron 走 `${app.schedule.*}`，可由 `system_config` 覆盖。
- ⚠️ **定时任务靠 `DeviceRepository.findDistinctTenantPairs()` 遍历租户 = 从 device 取**（技术基线 **C4**）——**没有设备的租户对定时任务不可见**。腿 B 的批处理不能照抄这个模式。

---

## 7. 测试

- JUnit 5 + Mockito + AssertJ + **Testcontainers**（pgvector 集成测试，需 Docker）。
- 真实 Azure/aibridgex 的 SmokeTest **无 key 自动跳过**。
- **新能力应带测试**——测试既是质量保证，也是「能力确实做了」的**行为证据**（锚点只证存在性，测试证行为）。

## 8. 新增能力 Checklist（照着做）

1. **先登记**：在**两份基线文档**（`产品需求文档-唯一基线` / `两条腿-技术需求文档`）登记需求与状态（⬜）。
2. **加迁移**：如需表 → `V{next}__xxx.sql`（现为 **V18**）；更新 `docs/baseline/数据库说明.md` §3/§5。
3. **写代码**：开新包（§2）；租户按 §3；数据访问按 §4。
4. **加代码锚点**：在技术基线 §7「代码锚点核对」表登记锚点，并**同步更新 `scripts/status-audit.sh`**。
5. **加测试**（行为证据）。
6. **更新状态**：跑 `bash scripts/status-audit.sh` → 无漂移后，把两文档状态 `⬜ → ✅`。
7. **提交**：conventional commit（`feat(scope): …`，scope 用包名）。

> **原则：先登记，再开工**；改完**必须回写基线**——否则就是漂移。

## 9. 已知坑清单（写代码前先看）

| # | 坑 | 对应 |
|---|---|---|
| 1 | 异步/定时里 `TenantContext.require()` 会抛异常——必须显式传租户 | **C5** |
| 2 | 后台**无真实鉴权**（信任 `X-Customer-Id` header）——**切勿**当生产安全边界 | **C2** |
| 3 | 租户**强制绑 store**；无门店概念的场景会别扭 | **C3** |
| 4 | 报表/定时任务**按 device 遍历**——腿 B（无设备）数据会漏 | **C4** |
| 5 | `app.role` **只决定首页路由**，不控制模块装配——腿 B 独立部署需另做 profile | **C6** |
| 6 | 用 JDK ≠ 17 → Lombok 失效、编译报 `cannot find symbol` | — |
