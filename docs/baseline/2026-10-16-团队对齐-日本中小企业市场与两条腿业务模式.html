AI 工牌 · 团队对齐

日本中小企业市场 与「两条腿」业务模式

日期 2026-10-16  ·  用途 团队内部统一认识，供讨论  ·  性质 方向共识 + 决策记录，非最终商业计划

一页结论
  1. 把 AI 工牌从「一台设备」升级为「一套云端 AI 能力」——用两条腿打日本市场。
  2. 腿 A · 工牌线（重）：现场多语言，面向高外劳的门店 / 连锁 / 派遣公司。
  3. 腿 B · 后台 AI 线（轻）：纯软件、零硬件，做知识 / 文书 / 事务，面向绝大多数中小企业。
  4. 重点市场 = 日本中小企业（SME）；但「SME」太宽——靶心收窄到「中小企業 标准档」（有事务职能、有预算、有审批），不碰极小规模。
  5. 先能力、后入场费：先做产品能力（① 自生长知识 → ③ 文档处理 → ② agent 执行），暂不投属地化运营。
  6. 一个必须统一的认识：打 SME 的主力是腿 B（软件），不是工牌；工牌是护城河，软件是入口。

1 · 为什么聚焦日本中小企业

机会：数据摆在这里

指标数值解读
中小企业占企业数约 99.7%（就业约 7 成）谈「日本市场」几乎等于谈 SME
企业生成 AI 利用率（日本）55.2%，美 90.6% / 中 95.8%国际垫底
AI agent「利用中」的企业仅 3.3%（"信息收集中" 49.3%）agent 几乎空白

口径提醒：55.2% 是广义口径，且大企业远高于中小企业，不能当成 SME 数字——SME 实际更低。

SME 的四个结构性痛点（= 落地的土壤）

痛点内容对 AI 的意义
① 人手不足少子高龄化；2024 年起工时上限规制适用中小企业最硬的买单理由
② 事業承継危机约 245 万家经营者 70 岁+、约一半无后继属人化 / 知识流失——正是「沉淀」卖点
③ IT 人材不足无 IT 部门是常态，総務 / 経理兼管 IT产品必须零运维、零培训
④ 稟議 + 补助金依赖决策靠稟議，AI 预算高度靠补助金需要稟議材料 + 补助金通道
一句话：机会真实（市场最大、痛点最硬、AI 几乎空白），但闸门在产品之外（见 §6）。

2 · 厘清：SME 不是一个市场

法律上按「资本金 或 员工数」定义：製造等 3 億円/300 人以下；卸売 1 億円/100 人以下；小売・サービス 5 千万円/50 人以下。「小規模事業者」是更小一档。但真正的分野不在大小，而在有没有事务职能：

层规模（示意）特征AI 适配
小規模事業者〜5（商业/服务）/ 〜20社長一人、无专职事务、无 IT❌ 无预算、无职能
中小企業（标准档）〜50–300有総務 / 経理职能、有稟議、有预算靶心
中堅企業300+系统化、有 IT预算够但竞品密集、决策慢

结论：靶心 =「中小企業 标准档」。不碰极小规模——那档没有「总务/事务」职能，我们最看好的「自生长知识」在那里根本没人审、没人用。也暂不主攻中坚——竞争激烈（Copilot / LegalOn / LayerX / Stockmark）且决策慢。

3 · 产品做成「两条腿」

腿 A · 金标（重）

工牌线

客户：高外劳的门店 / 连锁 / 派遣公司

  • 现场多语言、佩戴免培训
  • 有硬件（ODM / 电池 / OTA）
  • 交付摩擦高、毛利低、上市慢
腿 B · 轻（软件）

后台 AI 线

客户：绝大多数中小企业（含无外劳者）

  • 知识 / 文书 / 事务，零硬件
  • 纯 SaaS，浏览器 / App
  • 交付摩擦低、毛利高、上市快
这不是「分心做第二个产品」——是把已经存在的云端核心（知识库 + 广播 + 报表 + 工单 + 通知）显性化为可单独交付的价值。工牌是它的一个前端，后台是另一个。

4 · 两条腿的业务模式

腿 A · 工牌线

项内容
客户高外劳的连锁 / 门店 / 派遣公司（製造 / 農業 / 介護 / 建設 / 清掃 / 飲食）
卖什么工牌硬件 + 云端服务（翻译 / 知识 / 广播 / 回执）
怎么收钱硬件一次性（或含在月租内）+ 云订阅（按设备 / 门店）
交付ODM 硬件 + 云 SaaS（日本区）
价值现场免培训多语言、安全合规下沉、一线数据回流
局限硬件摩擦（采购 / 运维）、毛利低、上市慢

腿 B · 后台 AI 线

项内容
客户中小企业标准档的事务 / 总务职能（不限行业、不限外劳）
卖什么纯软件：知识自动沉淀（①）、文书作成（③）、多步任务执行（②）
怎么收钱SaaS 席位 / 月订阅（日本锚点：月额数千～1 万日元 / 席）
交付浏览器 / App，零硬件、零运维
价值无硬件门槛、毛利高、可快速起量；知识越用越强
局限ARPU 低、易被免费 ChatGPT替代、需日语支持
两腿的关系：腿 A 的一线交互 → 沉淀进云端知识 → 腿 B 更懂这家企业 → 反哺腿 A。腿 B 是入口，腿 A 是护城河。

5 · 已定决策（团队统一口径）

#决策结论理由
1产品定位两条腿：工牌线 + 后台 AI 线三条新能力全在后台、全无硬件，不必绑死一个形态
2目标市场做 SME市场最大、痛点最硬、AI 空白
3靶心中小企業 标准档，不碰极小规模那档无事务职能，方向①③无人用
4细分口径「外劳占比 × 门店规模」二维「日本服务业」太粗，会两腿错位
5能力优先级① 自生长知识 → ③ 文档处理 → ② agent 执行按「零件齐备度」排
6投入节奏先能力、后入场费见 §6

6 · 为什么「先能力、后入场费」

打 SME 不能像卖大企业那样直接把产品递过去——中间要走几套日本特有的机制，这就是「入场费」（产品之外的基础设施）：

#项是什么为什么 SME 非要
1IT 导入补助金政府替 SME 出钱买 IT（补助率常约 1/2～3/4）SME 的 AI 预算很大程度靠补助解锁
2支援事业者 / 认定支援机构有资质的中间人（税理士 / 商工会議所 / 银行）SME 信他们 >> 信厂商；既是补助通道也是推荐渠道
3日语支持体系全程日语客服 / 文档 / 培训SME 无 IT 部门，无日语客服 = 直接出局
4稟議材料客户拿去走内部审批（ROI / 试点 / 步骤）稟議要走 1–3 个月，没材料推不动
5Pマーク / ISMS隐私 / 信息安全认证采购 SaaS 走审批时常被要求（取证 6–12 月）
  • 这 5 项全是「重运营」投入，和「把产品能力做出来」是两条线。
  • 当前阶段目的是演示 / 融资——先烧钱铺属地化运营不划算。
  • 能力本身就是腿 B 的 SME 入口：先跑出来既能验证市场、又不耽误。
  • 例外：若「对投资人讲 SME 故事」当下就很关键，Pマーク / ISMS 要提前启动（周期最长）。

7 · 这对团队意味着什么

优先级（统一）

① 自生长知识 → ③ 文档处理 → ② agent 执行。共同内核：记忆（①积累）→ 产出（③交付）→ 编排（②干活），即从「通道」变「agent」。

细分口径（统一）

对外不再笼统说「日本服务业」，改用「外劳占比 × 门店规模」：低外劳 × 小规模 → 腿 B；高外劳 × 中规模 → 腿 A 为主；不碰极小规模。

不同场合讲不同话（统一）

对客户讲具体场景（「帮你答这个问题」「帮你写这份文书」），不讲「通用 agent 平台」；对投资人讲平台 / 数据闭环 / 两条腿。

需要统一的四个口径

  • 一句话定位：从「佩戴式翻译终端」→「一线 agent 助手 + 后台 AI 助手」。
  • 为什么不用免费 ChatGPT：现场 / 免培训 / 多语言 / 佩戴式 + 企业知识隔离 + 数据不进训练 + 合规。
  • 合规表述：用「模型可替换 + 数据驻留分层」，不要讲「数据不出日本」。
  • 两条腿主次：腿 B 是 SME 入口，腿 A 是护城河——不互相取代。
