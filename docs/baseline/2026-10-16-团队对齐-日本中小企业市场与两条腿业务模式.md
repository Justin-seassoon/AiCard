# 团队对齐：日本中小企业市场 与「两条腿」业务模式

> 日期：2026-10-16
> 用途：**团队内部统一认识**，供讨论
> 性质：方向共识 + 决策记录，**非最终商业计划**
> 关联：`docs/2026-10-16-日本中小企业-市场画像与契合分析.md`、`docs/2026-10-16-门槛2调整方案-硬件与产品两条腿.md`、`docs/2026-10-16-日本中小企业视角-产品规划审查.md`

---

## 0. 一页结论（TL;DR）

1. **把 AI 工牌从「一台设备」升级为「一套云端 AI 能力」**——用**两条腿**打日本市场。
2. **腿 A · 工牌线**（重）：现场多语言，面向**高外労**的门店 / 连锁 / 派遣公司。
3. **腿 B · 后台 AI 线**（轻）：**纯软件、零硬件**，做知识 / 文书 / 事务，面向**绝大多数中小企业**。
4. **重点市场 = 日本中小企业（SME）**；但「SME」太宽——**靶心收窄到「中小企業 标准档」**（有事务职能、有预算、有审批制度），**不碰极小规模**。
5. **先能力、后入场费**：先把产品能力（① 自生长知识 → ③ 文档处理 → ② agent 执行）做出来，暂不投入补助金登记 / 日语支持体系 / Pマーク 等属地化运营。
6. **一个必须统一的认识**：打 SME 的主力是**腿 B（软件）**，不是工牌；工牌是差异化护城河，软件是打 SME 的入口。

## 1. 我们为什么聚焦日本中小企业（SME）

### 1.1 机会：数据摆在这里

| 指标 | 数值 | 解读 |
|---|---|---|
| 中小企业占企业数 | **约 99.7%**（就业约 7 成） | 谈「日本市场」几乎等于谈 SME |
| 企业生成 AI 利用率（日本） | **55.2%**，美 90.6% / 中 95.8% | 国际垫底 |
| **AI agent「利用中」的企业** | **仅 3.3%**（"信息收集中" 49.3%） | agent 几乎**空白** |
| 采用障碍 | 不会用 30.1% / 安全 27.6% / 缺人才 41.3% | 门槛是「不会用」而非「不需要」 |
| **生成 AI 方针「未定」** | **50.9%** | 治理空白 |
| 活用企业体感有效 | **86.7%** | 价值真实，缺的是「怎么用」 |

> 口径提醒：55.2% 是广义口径，且**大企业远高于中小企业**，不能当成 SME 数字——SME 实际更低。

### 1.2 SME 的四个结构性痛点（= AI 落地的土壤）

| 痛点 | 内容 | 对 AI 的意义 |
|---|---|---|
| **① 人手不足** | 少子高龄化；2024 年起工时上限规制适用中小企业 | **最硬的买单理由** |
| **② 事業承継危机** | 约 245 万家经营者 70 岁+、约一半无后继 | **属人化 / 知识流失**——正是「沉淀」卖点 |
| **③ IT 人材不足** | **无 IT 部门是常态**，総務/経理兼管 IT | 产品必须**零运维、零培训** |
| **④ 稟議 + 价格敏感 + 补助金依赖** | 决策靠稟議，AI 预算高度靠补助金 | 需要稟議材料 + 补助金通道 |

**一句话**：机会真实（市场最大、痛点最硬、AI 几乎空白），**但闸门在产品之外**（§6）。

## 2. 厘清：SME 不是一个市场

### 2.1 定义与规模

- **法律定义**（按「资本金 或 员工数」二选一）：製造等 3 億円/300 人以下；卸売 1 億円/100 人以下；**小売・サービス 5 千万円/50 人以下**。
- **小規模事業者**（更小一档）：製造等 20 人以下、商業/サービス 5 人以下。
- **中堅企業**：非法律概念，泛指比中小企业大、比大企业小的中段。

### 2.2 分层与靶心

| 层 | 规模（示意） | 特征 | AI 适配 |
|---|---|---|---|
| **小規模事業者** | 〜5（商业/服务）/ 〜20 | 社長一人、**无专职事务、无 IT** | ❌ 无预算、无职能 |
| **中小企業（标准档）** | 〜50–300 | **有総務/経理职能、有稟議、有预算** | ✅ **靶心** |
| **中堅企業** | 300+ | 系统化、有 IT | 预算够但**竞品密集**、决策慢 |

**结论**：**靶心 =「中小企業 标准档」**。
- **不碰极小规模**——那档**没有「总务/事务」职能**，我们最看好的「自生长知识」在那里**根本没人审、没人用**。
- 也暂不主攻中坚——竞争激烈（Copilot / LegalOn / LayerX / Stockmark）且决策慢。

## 3. 产品做成「两条腿」

### 3.1 全景

```
                ┌── 腿 A：工牌线（重）────────────────────┐
                │  现场 · 多语言 · 佩戴免培训             │
   一个云端核心 ─┤  客户：高外労的门店/连锁/派遣          │
  （知识体 +     │  有硬件（ODM/电池/OTA）                │
   任务引擎）    └─────────────────────────────────────┘
                ┌── 腿 B：后台 AI 线（轻）─────────────────┐
                │  知识 / 文书 / 事务 · 零硬件            │
                │  客户：绝大多数中小企业（含无外労者）    │
                └─────────────────────────────────────┘
                       ↑ 两腿互相喂数据 ↓
```

### 3.2 两腿对比

| 维度 | 腿 A · 工牌线 | 腿 B · 后台 AI 线 |
|---|---|---|
| 前端 | 工牌（硬件 + 云） | 浏览器 / App（纯软件） |
| 目标客户 | 高外労的门店 / 连锁 / 派遣 | 中小企業事务 / 总务职能 |
| 核心能力 | 翻译、知识、广播、回执 | 知识沉淀、文书生成、任务执行 |
| 硬件依赖 | **有** | **无** |
| 交付摩擦 | 高（采购 / 运维 / 稟議） | 低（纯 SaaS） |
| 毛利结构 | 低（硬件成本） | 高（软件） |
| 上市速度 | 慢（依赖样机 / ODM） | **快** |

> **这不是「分心做第二个产品」**——是把**已经存在的云端核心**（知识库 + 广播 + 报表 + 工单 + 通知）显性化为可单独交付的价值。工牌是它的一个前端，后台是另一个。

## 4. 两条腿的业务模式

### 4.1 腿 A · 工牌线

| 项 | 内容 |
|---|---|
| **客户** | 高外労的连锁 / 门店 / 派遣公司（製造 / 農業 / 介護 / 建設 / 清掃 / 飲食） |
| **卖什么** | 工牌硬件 + 云端服务（翻译 / 知识 / 广播 / 回执） |
| **怎么收钱** | 硬件一次性（或含在月租内）+ 云订阅（按设备 / 门店） |
| **交付** | ODM 硬件 + 云 SaaS（日本区） |
| **价值** | 现场**免培训多语言**、安全合规下沉、一线数据回流 |
| **局限** | 硬件摩擦（采购 / 运维）、毛利低、上市慢 |

### 4.2 腿 B · 后台 AI 线

| 项 | 内容 |
|---|---|
| **客户** | 中小企业标准档的**事务 / 总务职能**（不限行业、不限外労） |
| **卖什么** | 纯软件：**知识自动沉淀**（①）、**文书作成**（③）、**多步任务执行**（②） |
| **怎么收钱** | SaaS 席位 / 月订阅（对齐日本锚点：月额数千～1 万日元 / 席） |
| **交付** | 浏览器 / App，**零硬件、零运维** |
| **价值** | **无硬件门槛**、毛利高、可快速起量；知识越用越强 |
| **局限** | ARPU 低、易被**免费 ChatGPT** 替代、需日语支持 |

### 4.3 两腿的关系

- **数据互喂**：腿 A 的一线交互 → 沉淀进云端知识 → 腿 B 更懂这家企业 → 反哺腿 A。
- **分工**：**腿 B 是打 SME 的入口**（门槛低、起量快），**腿 A 是差异化护城河**（重、难复制）。

## 6. 为什么「先能力、后入场费」

### 6.1 「入场费」是什么

打 SME 不能像卖大企业那样直接把产品递过去——中间要走几套**日本特有的机制**，这就是入场费（**产品之外的基础设施**）：

| # | 项 | 是什么 | 为什么 SME 非要 |
|---|---|---|---|
| 1 | **IT 导入补助金** | 政府替 SME 出钱买 IT（补助率常约 1/2～3/4） | SME 的 AI 预算很大程度靠补助解锁 |
| 2 | **支援事业者 / 认定支援机构** | 有资质的中间人（税理士 / 商工会議所 / 银行） | SME 信他们 >> 信厂商；既是补助通道也是推荐渠道 |
| 3 | **日语支持体系** | 全程日语客服 / 文档 / 培训 | SME 无 IT 部门，无日语客服 = 直接出局 |
| 4 | **稟議材料** | 客户拿去走内部审批（ROI / 试点 / 步骤） | 稟議要走 1–3 个月，没材料推不动 |
| 5 | **Pマーク / ISMS** | 隐私 / 信息安全认证 | SME 采购 SaaS 走审批时常被要求（**取证 6–12 月**） |

### 6.2 为什么先不投

- 这 5 项全是**「重运营」投入**，和「把产品能力做出来」是**两条线**。
- 当前阶段目的是**演示 / 融资**——先烧钱铺属地化运营不划算。
- **能力本身就是腿 B 的 SME 入口**：先跑出来既能验证市场、又不耽误。
- **例外**：若「对投资人讲 SME 故事」当下就很关键，**Pマーク / ISMS 要提前启动**（周期最长）。

## 7. 这对团队意味着什么

### 7.1 优先级（统一）

**① 自生长知识 → ③ 文档处理 → ② agent 执行**。
三者共同内核：**记忆（①积累）→ 产出（③交付）→ 编排（②干活）**，即从「通道」变「agent」。

### 7.2 细分口径（统一）

对外**不再笼统说「日本服务业」**，改用 **「外労占比 × 门店规模」**：
- **低外労 × 小规模** → 卖腿 B（知识 / 文书）；
- **高外労 × 中规模** → 腿 A 为主，腿 B 做管理 / 沉淀；
- **不碰极小规模**（无事务职能）。

### 7.3 不同场合讲不同话（统一）

- **对客户**：讲**具体场景**（「帮你答这个问题」「帮你写这份文书」），**不讲「通用 agent 平台」**。
- **对投资人**：讲**平台 / 数据闭环 / 两条腿**（壁垒与延展性）。

### 7.4 需要统一的几个口径

1. **一句话定位**：从「佩戴式翻译终端」→「**一线 agent 助手 + 后台 AI 助手**」（两条腿）。
2. **为什么不用免费 ChatGPT**：现场 / 免培训 / 多语言 / 佩戴式 + **企业知识隔离 + 数据不进训练 + 合规**。
3. **合规表述**：用「**模型可替换 + 数据驻留分层**」，**不要**讲「数据不出日本」。
4. **两条腿的主次**：腿 B 是 SME 入口，腿 A 是护城河——不互相取代。
