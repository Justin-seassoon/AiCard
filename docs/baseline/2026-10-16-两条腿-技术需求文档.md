## 1. 定位与范围

产品按「**两条腿**」交付，**共用同一套云端核心**：

- **腿 A · 工牌线（重）**：可佩戴设备（ESP32-P4）→ 云端 → TTS 外放。现场多语言、知识、广播。
- **腿 B · 后台 AI 线（轻）**：**纯软件、零硬件**，后台用户（浏览器/App）→ 云端。知识沉淀、文书处理、多步任务执行。

本文档回答三件事：**① 两条腿各自的模块需求是什么；② 现已完成哪些；③ 哪些要后续开发、前置依赖是什么。**

## 3. 技术需求分解

### 3.1 共享云端核心（两腿共用）

| 模块 | 需求 | 现状 | 状态 | 缺口 |
|---|---|---|---|---|
| 设备接入网关 | WSS + 鉴权 + 协议 + 会话 | 已实现（`gateway/`） | ✅ | — |
| 翻译链路 | 连续对话流式、LID、质量门控、供应商路由 | 已实现（`translation/` `provider/`） | ✅ | — |
| 知识库 SKB/VKB | 受控 RAG（检索→生成→非 LLM 校验） | 已实现（`skb/`） | ✅ | 检索为纯向量，无 hybrid（非阻塞） |
| 广播 | 分组多语言广播 + 回执 + 离线补拉 | 已实现（`broadcast/`） | ✅ | — |
| 运营通知 | 定时/群发通知，多语言翻译 + TTS | 已实现（`notification/`） | ✅ | — |
| 报表 | 周报/月报聚合 | 已实现但**按设备**（`report/`） | 🟡 | **聚合维度需泛化到「按租户/用户」**（C4，卡 ③） |
| 维护/点检 | 维修单 + 点检任务/记录 | 已实现（`maintenance/`） | ✅ | — |
| OTA | 固件发布/包管理 | 已实现（`ota/`） | ✅ | — |
| 采集 | 翻译/问答旁路脱敏落库 | 已实现（`ingestion/`） | ✅ | — |
| 后台管理 | 设备/文档 REST + RBAC | 有接口，**无真实鉴权/用户** | 🟡 | C1 ★ / C2 ★ |
| 供应商抽象 | Speech / LLM / Embedding 接口 | 已实现（多实现可换） | ✅ | — |
| 配置 | system_config + 运行时配置 | 已实现 | ✅ | — |

## 4. 横向能力需求（跨两腿，腿 B 前置）

> 由架构冲突核查得出（逐条对照现有代码）。其中 **C1/C2 为「卖给真实客户」的商业化硬前置**——**本轮 demo 按单租户运行、不做 C1/C2，不阻塞开发**（见 `docs/两腿demo-范围界定.md`）。

| # | 需求 | 现状 | 状态 | 等级 |
|---|---|---|---|---|
| **C1** | **用户/账户模型**（`app_user`；device.staff_* 与 user 关联） | 无 user 表；`AdminContext` 是未接线占位 | ⬜ | **🔴 商业化硬前置**（本轮 demo 不做） |
| **C2** | **真实鉴权**（登录/会话/token；租户由鉴权推导，不信 header） | 信任 `X-Customer-Id` header，无 Spring Security | ⬜ | **🔴 商业化硬前置**（本轮 demo 不做） |
| **C4** | **报表/聚合泛化到按租户/用户**；租户枚举改从 `customer` 取 | 按 device 聚合；`findDistinctTenantPairs()` 从 device 取 | ⬜ | 🟡 卡 ③ |
| **C5** | **租户跨异步/长任务传递**机制 | **已落地**：租户从任务行取 → 显式传给工具（`agent/AgentContext`） | ✅ | — |
| **C3** | 企业级 domain（跨门店知识）或 store=虚拟门店约定 | 租户强制绑 store | ⬜ | 🟢 可延后 |
| **C6** | 腿 A / 腿 B 部署切分（profile/条件装配） | `app.role` 仅选首页 | ⬜ | 🟢 可延后 |

> **运行结果（2026-10-16）**：一致 20 项 / 漂移 0 项。
> **边界**：锚点验证的是「**存在性 / 结构**」（覆盖约 80% 的「做没做」）；「行为对不对」靠测试 + 人复核。
