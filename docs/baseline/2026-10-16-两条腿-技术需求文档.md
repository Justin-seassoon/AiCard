## 1. 定位与范围

产品按「**两条腿**」交付，**共用同一套云端核心**：

- **腿 A · 工牌线（重）**：可佩戴设备（ESP32-P4）→ 云端 → TTS 外放。现场多语言、知识、广播。
- **腿 B · 后台 AI 线（轻）**：**纯软件、零硬件**，后台用户（浏览器/App）→ 云端。知识沉淀、文书处理、多步任务执行。

本文档回答三件事：**① 两条腿各自的模块需求是什么；② 现已完成哪些；③ 哪些要后续开发、前置依赖是什么。**

## 3. 技术需求分解

| 知识库 SKB/VKB | 受控 RAG（检索→生成→非 LLM 校验） | 已实现（`skb/`） | ✅ | 检索为纯向量，无 hybrid（非阻塞） |
| 广播 | 分组多语言广播 + 回执 + 离线补拉 | 已实现（`broadcast/`） | ✅ | — |

| 后台登录/鉴权 | 信任请求头 | ⬜ | C2 ★ |

### 3.4 会议域（新增 · 云端 P0）

```
长按录音（真机 P1 / 模拟器 P0 / 后台 WAV 导入）
  → 30 秒分片 HTTP PUT（seq + sha256，幂等 / 断点续传）
  → meeting_end(last_seq) → 完整性核对（missing_seqs，缺片仍可转写）
  → 异步：转写 → 结构化纪要 JSON（带时间戳根拠）→ 待办落库
  → 后台编辑 / 人工审核 → docx 导出；录音 30 天到期删除（保留转写/纪要）
```

| 项 | 设计 |
|---|---|
| 设备接口 | `POST /api/meetings/start` → `meeting_id`；`PUT /api/meetings/{id}/chunks/{seq}`；`POST /api/meetings/{id}/end`；鉴权 `X-Device-Id` + `X-Device-Token` |
| 音频导入 | `POST /api/meetings/import`（multipart WAV，PCM16；自动下混/重采样到 16k mono）→ 同一套分片/转写/纪要；用于**无麦克风（HTTP 环境）**或会议系统/手机录音 |
| 后台接口 | `GET /api/meetings`、`GET /{id}`、`PUT /{id}/minutes`、`POST /{id}/approve`、`POST /{id}/regenerate`、`GET /{id}/export.docx`、`GET /{id}/audio` |
| 状态机 | `recording → uploading → transcribing → drafting → draft → reviewed`；异常 `failed`；缺片记录在 `missing_seqs`，不改变状态 |
| 数据 | `meeting` / `meeting_chunk` / `meeting_action_item`（V22）；租户 `customer_id + store_id` |
| 存储 | 音频落共享卷 `meeting.storage-dir`（默认 `/data/meetings`），**多容器必须挂同一卷**；文件按 `{customerId}/{meetingId}/{seq}.pcm` |
| 异步/租户 | 处理进程从会议行取租户（C5），不依赖 `TenantContext`；失败只影响本会议 |
| 转写 | P0：Mock（演示）或现有 `SpeechProvider.transcribe` 按 60 秒分组；P1：Azure Batch Transcription（长音频 + diarization） |
| 纪要 | LLM 输出 JSON → 归一化（缺字段「要確認」）→ `DocxRenderer` 确定性排版；人工编辑后回到 `draft` 重新审核 |
| 兜底 | 10 分钟无新分片自动 finalize；录音 30 天到期删除；`@Scheduled` 任务幂等 |
| 测试 | 全量 **199 项**（会议 17 项：WavPcm 5 / Service 5 / Minutes 2 / AudioStore 2 / Integration 3）；测试服浏览器 E2E：后台 13/13、WAV 导入 6/6 |
| 部署 | 测试服 4 容器共享 `/data/meetings`；V22 自动迁移；HTTP 环境麦克风需 HTTPS，已提供 **WAV 导入**兜底 |
| P0 / P1 / P2 | P0 云端 + 模拟器；P1 真机长按/断点续传/周报聚合；P2 说话人分离/业务分析（需数据白名单） |
