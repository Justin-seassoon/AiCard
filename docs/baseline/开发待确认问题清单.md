# 开发待确认问题清单

> 用途：记录开发过程中遇到的需求不明确、口径不清、行为未定的问题，避免阻塞开发或遗漏。
> 维护方式：
> - **新增**：发现问题时在对应分类下追加一行，填写提出日期、问题、影响和建议默认值，状态为「待确认」。
> - **推进**：开发不因待确认而停摆；没有额外风险时，先按「建议默认值」实现。
> - **确认**：定期统一过（建议每两周或周会后）；确认后填写结论、确认人和日期，状态改为「已确认」。
> - **归档**：已确认条目不删除，作为决策记录；涉及产品 / 技术口径的，同步更新两份基线文档。
> - **编号**：连续递增，不复用。
