## 1. 定位与价值主张

**两个层面（分层表述）**：

- **`[愿景]`** 面向日本市场的「一线经营末梢 agent」——翻译是入口，核心是让一线**把事做成**（知识 / 推荐 / 广播 / 数据闭环）。
- **`[落地]`** 以「**两条腿**」交付：

| | 腿 A · 工牌线（重） | 腿 B · 后台 AI 线（轻） |
|---|---|---|
| 用户 | 一线员工（外劳密集场景） | 中小企业事务 / 总务职能 |
| 载体 | 可佩戴设备（ESP32-P4） | 浏览器 / App（纯软件） |
| 价值 | 现场多语言、知识下沉、广播 | 知识沉淀、文书作成、多步任务 |

**靶心**：**日本「中小企業 标准档」**（约 50–300 人，有事务职能、有预算、有稟議），不碰极小规模。

**价值主张：效率 × 沉淀**（同一次使用，同时产生两面）——使用者为「效率」来用，顺手零边际成本沉淀进企业知识；知识越用越准 → 效率更高 → 更多人用（护城河 = 抄不走的知识本体）。

**产品红线：「成事」而非「防人」**——帮一线把事做成（翻译 / 知识 / 推荐）、守住红线（安全 / 合规 / 卫生）、帮中层协调（调度 / 派工 / 回执）；**不做**实时定位、暗中录音、摸鱼监控、承诺账簿式盯人。

## 5. 核心场景

**腿 A**（0804 §3.2 为准）：酒店前台接待 / 免税店导购 / 机场服务 / 餐饮接客 / 展会接待——多语种双向沟通 + 知识即时答 + 广播调度。

**腿 B**（新）：
- 「経費精算の締め日は？」→ **带依据**即时答（知识沉淀）；
- 「来月の会議の案内文を作って」→ 文书草稿作成；
- 「今週の異常を整理して」→ 多步汇总 → 交付文档。

## 6. 非功能需求

| 类别 | 要求 | 状态 |
|---|---|---|
| **性能（腿 A）** | 翻译会话启动 ≤1s；TTS 打断 ≤500ms；翻译响应延迟 VAD 尾包→TTS 首帧 ≤2s（理想 ≤1.5s） | ✅ 已实现（0804 §12.1） |
| **可靠性** | 长稳 12h+；网络恢复不快重启；异常安全降级 | ✅ |
| **合规** | 口径统一为「**模型可替换 + 数据驻留分层**」；「**不用于训练**」明示；**禁用**「数据不出日本」绝对表述（方向④由其他团队立项，本仓库只统一话术） | ⬜ 待统一话术 |
| **安全** | 租户隔离不跨客户/门店/scope；**后台真实鉴权** | 🟡（隔离✅ / 鉴权⬜） |
| **可用性（腿 B）** | 零培训、零运维；日语支持 | ⬜ |
