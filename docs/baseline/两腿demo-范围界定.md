# 两腿 demo · 范围界定

> 日期：2026-10-16（v2：依范围调整重写）
> 用途：**界定本轮 demo 的开发范围**（做什么 / **明确不做什么**），供开发（含 AI agents）照此执行
> 关联：`docs/baseline/2026-10-16-产品需求文档-唯一基线.md`、`docs/baseline/2026-10-16-两条腿-技术需求文档.md`
> 分工前提：**真机联调由硬件团队主导**；**客户触达由商务团队推进**；全职硬件负责人**已有**

---

## 0. 一句话

本轮把**两条腿做到「完整可用」**：
- **腿 A**：软件**可迭代**（协议/OTA 已真机调通，联调=硬件功能完善，云端工作量小，不受影响）；
- **腿 B**：**①②③ 三项全做**，**仅排除「用户/登录/鉴权」与「多租户硬化」**。

目的：真机稳定演示 + 完整 B 腿演示 → **让投资人/客户相信我们更专业** + 撬动真实对话。

---

## 1. 范围原则

1. **完整**：①③② 都要端到端可用（不做半成品）；仅 §3.2 两项除外。
2. **顺序即优先级**：**① → ③ → ②**（按「零件齐备度」）。时间紧时，**② 先让位**——它最重、demo 价值最弱，不应拖累 ①③ 的完成度。
3. **每项有「完成标准」**（§4）——达标才算做完，避免「看起来做了」。
4. **人工审核是硬门**（① 的候选**绝不自动入库**）。

---

## 2. 腿 A · 可迭代 + 配合联调

腿 A **软件不再冻结**——因**协议、OTA 等已真机调试过**，联调只是硬件功能完善，**云端几乎无额外工作量**，故可并行做功能迭代。

| 类别 | 内容 |
|---|---|
| **配合联调** | 待冻结参数 9 项（等 ODM 反馈定稿）、VKB 真机链路（依赖端侧 `button_event(ok)`）、耳机输出路由 |
| **功能迭代** | 按需（具体项另行登记）。**不影响联调**——协议/OTA 已冻结且真机验证过 |

> 腿 A 的 demo 成功标准：真机上核心场景**稳定**演示（连续对话翻译 / SKB 问答 / VKB 撞库确认 / 广播）。

---

## 3. 腿 B · ①②③ 全做

### 3.1 做什么

**① 自生长知识**（端到端闭环）
```
qa_log(status=no_match) → 缺口池聚合 → LLM 起草候选(带出处)
  → 后台审核(通过/编辑/驳回) → 入库(document.status: draft → published)
```
落点：迁移 **V18** `knowledge_gap` + 新模块 `skb/curation/` + 后台审核页；复用 `qa_log` / `KnowledgeStore` / `LLMProvider`。

**③ 文档/文书处理**
- **读取**：上传 Excel / CSV → 解析（合并表头 / 全角 / 多 Sheet / 和暦 / 底部备注 / 前導零）；**文件当不可信数据**（注入检测与中和）；不确定处只给 warning；
- **生成**：**6 类模板**——通知 / 回覧 / 報告 / 議事録（docx）、見積書 / 請求書（xlsx）；内容由 LLM 起草、排版由模板确定性渲染；
- **报表输出**：周报/月报导出 xlsx（C4 聚合泛化：deviceId 可空）；
- ⚠️ 优先走**结构化抽取 + 模板填充**（POI），**不引入代码沙箱**（重资产、Java 单体异构）。

**② agent 执行**
- **自然语言指令 → LLM 规划工具序列**（`auto`：LLM 主 + 规则兜底；`llm`；`rule`）+ `plan→act→observe→reflect`；
- 工具集固定、路径自由：`search_knowledge` / `list_maintenance_orders` / `list_inspection_tasks` / `usage_summary` / `list_knowledge_gaps` / `compose_docx` / `write_xlsx` / `list_capabilities` 等（共 10 个）；
- 前置 **C5 已落地**：租户从任务行取 → 显式传给工具（不依赖 `TenantContext`）；
- ⚠️ **确定性校验优先**（数字对账 / 产物非空）+ **重试/幂等**；**假完成检测**（要求文件却无产物 → 失败）；**最终答复**（ResultComposer）；
- 用 **eval**（`scripts/agent-eval.sh`，15 条日语指令）量化成功率。

### 3.2 **仅两项不做**

- ❌ **用户体系 / 登录 / 鉴权**（C1 / C2）
- ❌ **多租户硬化**

> demo 期按**单租户 / 显式传租户参数**运行。其余横向能力（**C3 企业级 domain、C4、C5**）**按需要做**——③ 需要 C4、② 需要 C5，属范围内。

### 3.3 内容（够用就好）

- 総務场景日语规程 + 1~2 类社内文书模板 → seed 进 SKB；
- 用**公开规章抜粋 / 假数据**，**不用真实社内事案**。

### 3.4 UI

- 复用 `admin.html`：**知识缺口审核页**（①）+ **文书生成入口**（③）+ **任务视图**（②）；
- **不做**登录页 / 角色 / 复杂交互。

### 3.5 会议录音与智能纪要（新增 · 云端先行）

> 2026-10-23 决定：**云端 P0 先做，真机不阻塞 demo**；定位**「个人视角的会议笔记」**（匹配工牌 0.5–1.5m 收音规格），不作会议室级正式纪要承诺；音频**保留 30 天**。

**P0（本轮）· 纯云端**
- 30 秒分片上传（幂等 / 断点续传 / 完整性核对 / 缺片标记）；
- 转写（Mock 演示 + 现有 ASR 按片兜底；Azure 批式转写为 P1）；
- 结构化纪要 JSON（决定事項/保留事項/アクション，带时间戳根拠；缺字段「要確認」）→ docx；
- 待办落库 + 状态（周报的数据基础）；
- 后台「会议纪要」页签：列表 / 详情 / 编辑 / 审核 / 导出 / 回听；
- **模拟器「会议模式」**演示全链路——不等真机；**后台 WAV 导入**覆盖无麦克风（HTTP）环境。

**P1**：真机长按 + 分片上传 + 断电续传；周报聚合（已审核纪要 + 待办状态）；Azure Batch Transcription。
**P2**：说话人分离与姓名映射；业务分析报告（需数据白名单）。

> **当前状态（2026-10-23）**：P0 云端已部署测试服并通过验证（后台 13/13、WAV 导入 6/6，真实 Azure 转写 + LLM 纪要）。测试服为 HTTP，浏览器麦克风需 HTTPS，故测试路径为「后台 → 会议纪要 → 音频导入（WAV）」。

> **合规**：只做**公开录音**（员工主动发起 + 现场提示 + 出席者知情）；不可远程静默开启；音频到期自动删除。产品红线由「不做暗中录音」改为「**不做未告知/未同意的录音**」。

## 4. 完成标准（每项都要达标）

| 能力 | 完成标准 |
|---|---|
| **①** | 一条 `no_match` 现场走完「捕获→起草→审核→入库」，入库后**可被检索命中** |
| **③** | Excel/CSV **上传解析正确**（合并表头 / 全角 / 多 sheet / 备注 / 和暦）+ **6 类模板各生成可下载** + 报表导出 xlsx |
| **②** | 自然语言指令 → 多步执行 → 交付文件 / 答复；**含失败重试 + 确定性校验 + 假完成检测**；eval 15 条指令完成率 ≥ 60% |
| **会议纪要（新增 P0）** | 模拟器录一段会 → 分片上传 → 转写 → 结构化纪要 + 待办 → 审核 → docx 下载；缺片/失败有明确状态；音频 30 天到期清理 |
| **腿 A** | 真机核心场景稳定演示 |
| **整体** | **换来 N 场真实客户对话**（demo 的真正交付物） |

## 5. 时间线（到 12 月融资）

```
10/20 前后  样机到货 → 硬件团队联调（软件配合）；B 腿并行开工
10月下      ① 自生长知识端到端（约 1–2 周）
11月上      ③ 文档处理（含 C4）；商务带 demo 敲门（5–8 家 SME）
11月下      ② agent 执行（含 C5）；收集客户反馈
            会议纪要 P0（云端 + 模拟器）并行；真机长按 P1 依硬件进度
12月        融资包：真机 demo + 完整 B 腿 demo + 客户证据
```

> 腿 A（硬件主导）与腿 B（代码主导）**并行、互不占人**。

## 6. 护栏（给执行者 / agents）

1. 动手前**先在本文件确认范围**；超出 §3.1 的，**先问，不做**。
2. **保持 ①→③→② 顺序**——时间紧先保 ①③，② 是可让位项。
3. 每完成一项 → **回写基线状态**（技术基线 §6/§7 + 产品基线 §4/§9）+ **更新 `scripts/status-audit.sh` 锚点**。
4. **不引入**：代码沙箱、自动入库、登录/角色、多租户硬化——除非另行登记。
5. **会议录音只做公开录音**：员工主动发起 + 现场提示 + 出席者知情；不可远程静默开启；音频 30 天到期删除。
