## 二、下周规划：真机完整跑通业务链 + 欠账启动

**目标**：用真机（非模拟器）把工牌核心业务链从「配网」到「排障」端到端跑通一遍，逐环节验收；同时启动真机到位后解锁的维修 / 点检欠账。

### 1. 设备接入与配网（打底）

- 配网（AP / 扫码）、鉴权（`device_id` + token + `fw_version`）、状态上报（在线 / 睡眠 / 离线）
- 云端已就绪，真机连上即验；重点确认固件版本与能力上报字段

### 2. 翻译对话（核心，优先级最高）

- 短按翻译键 → 会话级流式 → VAD 断句 → LID 判向 → TTS 外放 → 连续轮流对话 → 20s 熔断
- 真机重点验证：auto 判向、无音频、采播互斥（AEC 防啸叫）、高频/低频语言对切换

### 3. 员工问答（staff_qa）

- 问答键 → 知识库检索 → 流式 TTS 播放
- 真机重点验证提速后的兼容：首帧 WAV 头跳过（R2）、`stop_tts` 后丢帧（R4）、每轮 `eou`（R5）、弱网首帧延后（T5）

### 4. 会议录音

- 长按开始/结束 → 5–30s 分片上传 → 缺片补传 / 断网续传 / 状态查询续传 → 转写纪要
- 真机重点验证：断电续传、补片后再结束、10 分钟超时收尾

### 5. 分组广播

- 云端下发多语言广播 → 真机接收并 TTS 播放；离线重连补发

### 6. OTA + 诊断日志（排障闭环）

- 真机 OTA 升级（版本比较不降级）；日志上传 + 云端一键下载，形成「出问题 → 传日志 → 取日志」的闭环

### 7. 异常与兜底场景（细化）

> 真机跑全链时，每个异常都要求「**端侧有提示、云端有状态**」，出问题能当场定位。下表按通道分列，兜底原则：**4xx 参数错不盲目重试、网络 / 5xx 按指数退避、鉴权错先刷新凭证**（协议 §1.3）。

#### 7.1 接入 / 连接层

| 场景 | 触发 | 真机提示 | 云端状态 |
|---|---|---|---|
| 鉴权失败（WSS） | 握手 `device_id + token` 校验失败 | 握手被拒（HTTP 403），屏幕提示「重新鉴权 / 检查 token」，建议断开重连 | 拒绝握手、不建会话；`E_AUTH` 记日志；租户/门店由设备档案推导，不信设备自报 |
| 鉴权失败（HTTP） | OTA / 会议 / 日志 `Bearer` 过期 | 收到 `401 UNAUTHORIZED` / `E_MEETING_AUTH` / `E_DEVICE_LOG_AUTH` | 拒绝请求，要求走设备凭证刷新流程；**不重试上传**，先刷新凭证 |
| 断网 / 心跳超时 | WS ping/pong 10s，连续 2–3 次无 pong 判死 | `E_NET` 提示音 + 重连；**本地打断仍可用**（≤100ms 断网可用） | 断连清理会话缓冲；1.0 无会话恢复窗口（2.0 再评估）；广播/通知记「未投递」待补拉 |
| 20s 会话空闲熔断 | 连续 20s 无有效语音 / 按键（`idle_timeout_ms=20000`） | 自动结束会话、回待机、进低功耗 | `E_SESSION` 强制终止并回收会话；**这是正常自动结束，非故障** |

#### 7.2 翻译链路

| 场景 | 触发 | 真机提示 | 云端状态 |
|---|---|---|---|
| LID 低置信降级 | `conf < θ(0.8)` 且未命中白名单 | `E_LID_LOW` 播「请再说一遍」，**不外放译文** | 记低置信日志，不返回高风险译文；命中短词白名单（OK / はい / ありがとう）则直通翻译、不漂移 |
| 语言漂移防护 | 高置信新语言 ≠ 已锁定语言 | 本句照译；屏幕语言待连续 2 次或 `conf ≥ θ_super(0.95)` 才切 | pending 软锁定累加，防单句误判切换记忆 |
| 供应商全挂 | 已降级仍失败 | `E_PROVIDER` 播「服务暂不可用，稍后再试」 | 多供应商路由已穷尽，记日志 |
| ASR 失败 | 单供应商 ASR 出错 | `E_ASR_FAIL` 提示重试 | 云端切备选供应商重试 |
| 输入冲突 | 重叠讲话 / 来源语言冲突 | `E_CONFLICT` 播「请依次说话 / 重新说」，不播放 | 丢弃该轮，等下一 `eou` |
| 双方同语言 | 游客说员工语言 | `E_SAME_LANG` 不翻译 / 直通 / 提示重说 | 判为 no_translate |

#### 7.3 员工问答（staff_qa）

| 场景 | 触发 | 真机提示 | 云端状态 |
|---|---|---|---|
| 知识库无匹配 | 向量检索未命中 | `E_QA_NO_MATCH` 播「暂无明确说明」 | 记 `qa_log(no_match)` → 进知识缺口池（自生长知识 ① 的入口） |
| 范围外问题 | 超出员工知识库范围 | `E_QA_OUT_OF_SCOPE` 播可配置兜底话术 | 记日志，不生成答案 |

#### 7.4 会议录音

| 场景 | 触发 | 真机提示 | 云端状态 |
|---|---|---|---|
| 缺片补传 | `end` 有缺片 | 收到 `missing_seqs`，保持 `uploading` 可补传 | 补片只接受 `seq ≤ expected_last_seq`；补齐自动转写；`end` 幂等 |
| 断网 / 断电续传 | 长录音中途断连 | 重连后按 seq 幂等续传 | 10 分钟无新分片自动 finalize（按已声明 `expected_last_seq` 收尾，保留缺片记录） |
| 转写失败 | ASR / LLM 出错 | 后台该会议显示 `failed` | 处理进程状态置 `failed`，失败只影响本会议；后台 `POST /{id}/regenerate` 重转写 |
| 分片校验失败 | 同序号内容不一致 / sha 不符 | `E_MEETING_SHA_MISMATCH` 重传该片；`E_MEETING_SEQ_CONFLICT` 停该片人工确认 | 幂等 + 校验，不吞错片 |
| 音频过期 | 30 天到期 | `E_MEETING_EXPIRED` 停止 | 到期删音频，**保留转写与纪要** |

#### 7.5 广播 / OTA / 诊断日志

| 场景 | 触发 | 真机提示 | 云端状态 |
|---|---|---|---|
| 广播离线补拉 | 广播下发时设备离线 | 重连 `session_init` 后收到补发广播 | 离线成员标「未投递」，重连后补发；同语言成员共享译文 + TTS（去重） |
| OTA 版本不降级 | 设备版本 ≥ 目标版本 | `update_available=false` + `reason` | `UP_TO_DATE`（已是适用版本）/ `NO_APPLICABLE_RELEASE`（暂无适用发布，**不能提示「已是最新」**）；P4/C5 一新一旧也回 `NO_APPLICABLE_RELEASE` |
| OTA 下载校验 | 下载后 sha256 不符 | 端侧对完整 `.bin` 比对，不符丢弃重取 | 签名 URL 短期有效（`expires_in_sec ≥ 3600`），安装前重取 |
| 日志频率 / 超限 | 1 分钟内重复上传 / 超 256KB | `E_DEVICE_LOG_RATE_LIMIT` 退避；`E_DEVICE_LOG_TOO_LARGE` 减日志重传 | 单设备 1 次/分钟、压缩后 ≤256KB、保留 7 天 |

> **下周验收口径**：上表每个「真机提示」都要在真机上肉眼确认一遍；「云端状态」用后台「诊断日志」页签 + `E_*` 错误码远程核对。凡出现「端侧无提示」或「云端无状态」的，即为待修缺口，当场登记。

### 8. 维修与点检现场闭环（真机到位，欠账启动）

真机到位后，《开发欠账清单》中依赖「真机按键/语音、通知下发通道」的维修 / 点检闭环可启动（原 10 条 ⬜）：

- **派单 / 接单 / 验收**：指派维修人员 → 接单确认 → 处理记录 → 报修人或主管验收
- **异常转维修**：点检不合格项自动生成维修单
- 下周先跑通「现场报修 → 后台建单」「点检下发 → 真机确认」两条最小闭环，其余按清单逐步补

## 三、后台功能闭环全景（所有业务都指向闭环）

> 依据《后台功能闭环差距梳理》（10-24）更新，覆盖后台 9 个页签；按「真实业务闭环」判断，多数停在「记录 + 状态」层，缺「人、责任、触达、反馈」。

### 总览

| 功能 | 现状 | 闭环缺口 | 计划 |
|---|---|---|---|
| 周报 / 月报 | 自动生成 / 查看 / 导出 | 按人 / 店维度、异常预警、分发 + 已读、从报表生待办 | 可演示 5–7 人日 |
| 运营通知 | 单次群发 + 投递记录 | 审批、周期执行、目标预览、已读回执、失败重试 | 5–6 人日 |
| 维修单 | 后台建单 + 状态流转 | 现场上报、派单接单、过程验收 | 真机到位，下周启动 |
| 点检任务 | 后台建任务 + 记录 | 下发、现场执行、异常转维修 | 真机到位，下周启动 |
| 知识缺口 | 捕获 / 起草 / 审核 / 入库 | 定时捕获、相似合并、编辑审核、发布验证、复发重开 | 6–8 人日 |
| 社内文书 | 上传解析 / 模板生成 / 下载 | 审批、版本、归档、发送 | 4–6 人日 |
| 会议纪要 | 录音 / 转写 / 纪要 / 待办 / 审核 / 导出 | 待办提醒催办、周报聚合、回执行 | 3–5 人日 |
| AI 任务 | 自然语言 → 执行 → 产物 | 人工确认、权限、审计 | 3–5 人日 |
| 诊断日志 | 上传 → 云端下载 | —（已形成排障闭环） | 已可用 |

### 结论

后台 9 项功能中，**8 项停在「记录 + 状态」层**，唯一相对闭环的是本周新增的诊断日志。要真正「形成闭环」，缺的不是页面，而是四类连接：**角色权限、审批责任、触达回执、执行反馈**（详见《后台功能闭环差距梳理》）。

### 推进顺序

1. **阶段一 · 横向基础**（4–6 人日）：通用审批状态、统一分发、审计日志、定时调度
2. **阶段二 · 三个重点补闭环**（10–12 人日）：知识缺口、运营通知、周报 / 月报
3. **阶段三 · 执行侧闭环**（5–8 人日 + 硬件）：维修 / 点检、会议待办、设备已读回执
4. **阶段四 · 生产化**（3–4 月）：用户体系（C1）、登录鉴权（C2）、角色权限、SLA

> 下周优先级：真机跑业务链 > 维修 / 点检最小闭环 > 阶段二启动；阶段一横向基础视资源穿插。
