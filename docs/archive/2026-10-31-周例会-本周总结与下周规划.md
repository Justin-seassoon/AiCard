## 一、本周完成

### 1. 会议录音端云协议完成对齐与拍板（10-24）

把会议录音从“云端自己能用”推进到“端侧可以照着实现”。

- 与端侧逐项对齐 14 个协议问题，其中 **12 项我方口径已定**，**2 项待产品 / 合规**（现场提示话术、取消会议后音频保留范围）
- 关键结论：
  - 会议走 HTTP，不占用翻译的 WSS 长连接
  - 分片改为 **5–30 秒**（端侧按 PSRAM 预算选），60 / 120 秒不支持
  - 结束必须上报 `last_seq`，否则末尾丢片发现不了
  - 结束返回缺片列表；有缺片时保持“上传中”，补完再转写；10 分钟无新片自动收尾
  - 新增状态查询接口，设备重启 / 断网后可续传
  - HTTP 鉴权统一为 Bearer + 设备 ID；音频只支持 PCM16 / 16kHz / 单声道
  - 新增固件版本与能力上报，缺失视为实现错误
- 输出：《端云协议 14 项拍板结论与端侧确认清单》《端云协议对齐与迭代梳理》
- 仍需端侧确认：首个支持会议录音的固件版本、PSRAM 预算 / 功耗、补片后再调 `end` 是否可行

### 2. 后台功能闭环差距梳理（10-24）

对周报、通知、知识缺口、维修点检、文档处理、会议纪要、AI 任务 7 项功能做了一次“离真实业务闭环还差什么”的盘点。

- 结论：多数功能停在“有表、有页面、有状态流转”，还缺 **角色权限、审批责任、触达回执、执行反馈** 四类连接
- 按“可演示闭环”估算，三个重点功能合计约 16–21 人日；先补共用基础（审批、分发、回执、审计）约 14–18 人日
- 按“生产可用”估算，每项约 2–4 周，且必须先补用户体系与登录鉴权
- 用途：作为下一阶段排期输入，本轮演示范围不变

### 3. 会议录音 P1-a（云端设备接口）完成并上线（10-29 ~ 10-30）

在上周云端 P0 的基础上，把设备侧真正需要的能力补齐，端侧硬件连上即可联调。

- **4 个设备接口**：开始会议、上传分片、结束会议、状态查询
- **鉴权与协议统一**：`Authorization: Bearer` + 设备 ID，旧路径与旧鉴权头已停用
- **结束逻辑改为可补传**：有缺片时保持“上传中”并返回缺片列表；补完自动转写，10 分钟无新片自动收尾
- **开始参数强校验**：固件版本、能力列表、触发方式（只能现场长按）、提示已播放、分片时长 5–30 秒
- **错误码统一**：设备按 `E_MEETING_*` 处理，不再依赖默认错误格式
- **留痕**：固件版本、能力、触发方式、提示播放情况入库，满足合规审计需要
- 数据升级 V23（只加字段，无破坏性变更）
- 验证：
  - 单元测试 27 项全部通过
  - 测试服用真实日语语音跑通“开始 → 分片 → 结束 → 转写 → 纪要 → 待办”，最终生成 Word 可导出
  - 缺片场景实测：结束返回缺片列表 → 补传 → 自动转写
  - 4 个服务容器重建完成，健康检查全部正常

### 4. 通用设备诊断日志完成并上线（10-30）

端侧提出“会议录音缺少日志上传接口”，核实属实后按**通用能力**立项，不绑死会议场景。

- 新增设备日志上传接口：文本 / JSONL，支持 gzip，单次 ≤256KB
- 限制：同一设备 1 次/分钟；保留 7 天，到期自动删除
- 日志正文存共享卷，数据库只存索引；后台可按设备、会议、时间查询并下载
- 已用真实上传验证：无凭证被拒、gzip 上传成功、1 分钟内重复上传被限流、后台下载内容与原始日志完全一致
- 数据升级 V24（只新增表，无破坏性变更）
- 意义：以后会议、OTA、翻译的端侧问题都能远程拿到日志，不再只能靠串口或猜

### 5. 端侧文档与协议基线同步

- 新增《端侧联调测试文档-会议录音》：连接信息、4 个接口、8 组测试用例、错误码、限制
- 新增《端侧诊断日志上传说明》：上传方式、大小 / 频率限制、错误码、推荐上传时机
- 新增《端侧回复-OTA 型号与硬件版本字段》：明确 `product_model` / `hardware_version` 填什么、命名规则，以及云端当前尚未做档案比对的现状
