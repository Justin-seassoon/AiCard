二、下周规划：真机完整跑通业务链 + 欠账启动

目标：用真机（非模拟器）把工牌核心业务链从「配网」到「排障」端到端跑通一遍，逐环节验收；同时启动真机到位后解锁的维修 / 点检欠账。

1. 设备接入与配网（打底）

  • 配网（AP / 扫码）、鉴权（device_id + token + fw_version）、状态上报（在线 / 睡眠 / 离线）
  • 云端已就绪，真机连上即验；重点确认固件版本与能力上报字段

2. 翻译对话（核心，优先级最高）

  • 短按翻译键 → 会话级流式 → VAD 断句 → LID 判向 → TTS 外放 → 连续轮流对话 → 20s 熔断
  • 真机重点验证：auto 判向、无音频、采播互斥（AEC 防啸叫）、高频/低频语言对切换

3. 员工问答（staff_qa）

  • 问答键 → 知识库检索 → 流式 TTS 播放
  • 真机重点验证提速后的兼容：首帧 WAV 头跳过（R2）、stop_tts 后丢帧（R4）、每轮 eou（R5）、弱网首帧延后（T5）

4. 会议录音

  • 长按开始/结束 → 5–30s 分片上传 → 缺片补传 / 断网续传 / 状态查询续传 → 转写纪要
  • 真机重点验证：断电续传、补片后再结束、10 分钟超时收尾

5. 分组广播

  • 云端下发多语言广播 → 真机接收并 TTS 播放；离线重连补发

6. OTA + 诊断日志（排障闭环）

  • 真机 OTA 升级（版本比较不降级）；日志上传 + 云端一键下载，形成「出问题 → 传日志 → 取日志」的闭环

7. 异常与兜底场景

  • 鉴权失败、断网重连、转写失败、低置信度降级、20s 熔断——每个场景给出真机提示与云端状态

8. 维修与点检现场闭环（真机到位，欠账启动）

真机到位后，《开发欠账清单》中依赖「真机按键/语音、通知下发通道」的维修 / 点检闭环可启动（原 10 条 ⬜）：

  • 现场报修：员工在工牌上语音 / 按键报修 → 自动生成维修单（门店、位置、描述、上报人、时间）
  • 点检下发与执行：任务下发到责任人工牌（语音提醒 + 按键确认）→ 现场逐项确认 → 提交结果
  • 派单 / 接单 / 验收：指派维修人员 → 接单确认 → 处理记录 → 报修人或主管验收
  • 异常转维修：点检不合格项自动生成维修单
  • 下周先跑通「现场报修 → 后台建单」「点检下发 → 真机确认」两条最小闭环，其余按清单逐步补

结论

后台 9 项功能中，8 项停在「记录 + 状态」层，唯一相对闭环的是本周新增的诊断日志。要真正「形成闭环」，缺的不是页面，而是四类连接：角色权限、审批责任、触达回执、执行反馈（详见《后台功能闭环差距梳理》）。

推进顺序

  1. 阶段一 · 横向基础（4–6 人日）：通用审批状态、统一分发、审计日志、定时调度
  2. 阶段二 · 三个重点补闭环（10–12 人日）：知识缺口、运营通知、周报 / 月报
  3. 阶段三 · 执行侧闭环（5–8 人日 + 硬件）：维修 / 点检、会议待办、设备已读回执
  4. 阶段四 · 生产化（3–4 月）：用户体系（C1）、登录鉴权（C2）、角色权限、SLA
下周优先级：真机跑业务链 > 维修 / 点检最小闭环 > 阶段二启动；阶段一横向基础视资源穿插。
