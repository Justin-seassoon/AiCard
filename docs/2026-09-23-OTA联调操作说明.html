适用：测试、端侧（ODM）同事
日期：2026-09-23
协议依据：《OTA 协议确认 · 端云冻结版》（docs/2026-09-22-OTA协议确认-端云冻结版.md）

1. 概述

云端 OTA 服务已上线，采用「独立 HTTPS 检查 + 签名下载」通道，不依赖翻译 WSS。三个接口：

接口方向用途
POST /api/v1/ota/check设备 → 云上报 P4/C5 实际版本，返回固定配套目标 + 待装固件清单
GET /api/v1/ota/files/{key}?expires=&sig=设备 → 云下载固件（短期签名 URL，无需 Bearer）
POST /api/ota/releases后台 → 云发布 / 登记固定配套版本（登记元数据 + 云端复核 sha256/size）
  • GET /api/ota/releases 查发布列表；POST /api/ota/releases/{id}/revoke 撤销。
  • 同一时刻只有一个 active 发布；发布新 release 自动撤销旧的。

3. 联调前置：放固件 + 算校验值

运维把 ODM 提供的 .bin 放到服务器 /tmp/aicard/ota/ 下，记下字节数和 sha256：

# Linux 服务器上
wc -c   /tmp/aicard/ota/p4-2.0.bin        # 字节数（image_size）
sha256sum /tmp/aicard/ota/p4-2.0.bin      # sha256

# macOS 本地
wc -c   p4-2.0.bin
shasum -a 256 p4-2.0.bin
发布时云端会重新读文件复核 sha256/size，对不上会 400 拒绝——这是防放错文件的保护。

4. 完整联调流程（curl）

4.1 发布 release（后台登记元数据）

curl -X POST http://10.0.189.32:8083/api/ota/releases \
  -H 'Content-Type: application/json' \
  -d '{
    "update_id": "badge-20260923-r1",
    "policy": "optional",
    "target_p4_version": "2.0",
    "target_c5_version": "1.5",
    "release_notes": "联调第一版",
    "packages": [
      {"module":"p4","target_version":"2.0","image_size":1024,
       "sha256":"<p4 的 sha256>","storage_key":"p4-2.0.bin"},
      {"module":"c5","target_version":"1.5","image_size":512,
       "sha256":"<c5 的 sha256>","storage_key":"c5-1.5.bin"}
    ]
  }'
  • packages[] 只放实际版本还没达标的模块（1~2 项），顺序即执行顺序。
  • policy = optional（可稍后）或 mandatory（必须升）。

4.2 设备检查更新

curl -X POST http://10.0.189.32:8083/api/v1/ota/check \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer demo-token-001' \
  -d '{"device_id":"demo-device-001","current_versions":{"p4":"1.0","c5":"1.0"},"trigger":"boot"}'

返回（示例，两芯片都待升）：

{
  "update_available": true,
  "update": {
    "update_id": "badge-20260923-r1",
    "policy": "optional",
    "target_versions": {"p4": "2.0", "c5": "1.5"},
    "packages": [
      {"module":"p4","target_version":"2.0","image_size":1024,"sha256":"...",
       "download_url":"http://.../api/v1/ota/files/p4-2.0.bin?expires=...&sig=...",
       "expires_in_sec": 3600}
    ]
  },
  "reason": null
}

4.3 下载固件

直接把 download_url 交给 curl 下载即可（签名已含在 URL 里，无需额外鉴权）：

curl -o p4-2.0.bin "<check 返回的 download_url>"

4.4 撤销 / 查列表

curl -X POST http://10.0.189.32:8083/api/ota/releases/1/revoke   # 撤销 id=1
curl http://10.0.189.32:8083/api/ota/releases                    # 列表

5. 典型返回值

场景返回
无 active 发布{"update_available":false,"update":null,"reason":"NO_APPLICABLE_RELEASE"}
全部达标{"update_available":false,"update":null,"reason":"UP_TO_DATE"}

6. 配置说明（运维）

OTA 相关环境变量在服务器 /tmp/aicard.env：

变量值说明
OTA_STORAGE_DIR/data/ota（容器内）固件目录，宿主机 /tmp/aicard/ota 挂载
OTA_SIGN_SECRET随机签名 URL 密钥（服务器生成，不落盘外）
OTA_PUBLIC_BASE_URLhttps://120.253.215.108:58083⚠️ 公网地址待核对
OTA_PUBLIC_BASE_URL 决定返回给设备的 download_url 前缀。当前按联调同源地址填了 120.253.215.108:58083，但这个公网 IP 此前有 .108/.110/.100 多种记录，联调前请确认实际公网 IP 与端口。若不对，改 /tmp/aicard.env 后 docker restart aicard-ota 即可。
