2. 软件产品原则
原则
软件行为要求
翻译优先
普通翻译是首要主链路。游客知识库、员工知识库或耳机增强发生异常时，不得导致普通翻译被无关功能阻塞或永久退出。
关键对客回答由员工确认
游客知识库产生的标准答案候选，在员工确认前不得直接向游客播报。
不确定时不猜测
语言、语音、知识、权限或状态无法可靠判断时，应提示重说、保持当前状态、静默降级或返回暂无资料，不输出看似确定的错误结果。
语音优先，屏幕辅助
主要交互通过自然说话完成；屏幕用于模式、语言、网络、电量、候选和状态提示，不显示实时翻译全文。
安全优先于便利
客户承诺、退款赔偿、内部规则、敏感资料、权限和异常处理应优先保证可控、可追溯和不越权。
耳机为可选增强
无耳机时必须保留完整翻译和知识服务；耳机接入、拔出或异常不得让主链路卡死或造成私密内容突然高音量外放。

3.1 实时翻译与会话管理
ID
等级
功能点
实现效果
SW-TR-001
P0
翻译会话启动
员工短按翻译键后进入连续轮流翻译状态；再次短按可结束。启动后应明确显示当前模式。
SW-TR-002
P0
员工语言
系统保存并使用 staff_language。首次使用、班次切换或更换员工时可修改；日常每轮对话不重复要求选择。
SW-TR-003
P0
自动/固定语言模式
同时支持 AUTO 与固定语言对。自动识别不可靠时，员工应可切换固定语言对作为稳定性兜底。
SW-TR-004
P0
游客语言识别
AUTO 模式下，系统仅在当前门店启用的候选语种中识别游客语言。首版至少覆盖日语、中文、英语、韩语。
SW-TR-005
P0
游客语言记忆
visitor_language 采用会话内软锁定；短词、数字、品牌名、低置信度或偶发第三语言不得轻易导致语种漂移。
SW-TR-006
P0
语言更新边界
只有质量合格的完整新语言语句满足既定更新条件时，才允许更新 visitor_language；判断不可靠时保持当前语言或提示重说。
SW-TR-007
P0
双向翻译效果
游客发言翻译为 staff_language；员工发言翻译为 visitor_language。双方按自然轮流说话完成沟通。
SW-TR-008
P0
同语种/来源冲突
当双方语言相同、输入来源与语言明显冲突或无法可靠判断说话方时，不得强行翻译或猜测播放方向。
SW-TR-009
P0
重叠讲话
两路同时触发、双方抢话或重叠明显时，应提示依次说话/重新说，必要时进入更受控的半双工交互。
SW-TR-010
P0
会话结束与重置
会话结束、空闲超时、人工模式切换或设备重启后清空 visitor_language；staff_language 按配置保留。
SW-TR-011
P0
播放打断
TTS 播放期间出现新的有效语音或员工执行停止操作时，应停止当前播放并允许继续后续交互。
SW-TR-012
P0
空闲处理
连续翻译会话空闲达到系统设定的超时条件后，应自动结束并进入低功耗/待机状态；具体超时时长由产品配置或后续验收冻结。

P1

P1

8. 数据、知识与权限边界
边界项
要求
客户/门店隔离
设备、知识、日志与权限不得跨客户或跨门店错误调用。
双知识库隔离
游客知识库不得调用员工内部资料；员工知识库不得进入游客自动候选链路。
回答依据
游客知识使用审核后的标准答案；员工知识回答必须依据授权资料，资料缺失时明确未命中。
敏感内容
高风险对客承诺不进入首版自动可播放候选；敏感员工资料按权限控制。
日志最小化
日志应满足问题定位和追溯需要，但避免长期保留无必要的完整敏感语音、明文个人信息。
隐私提示
语音留存、隐私告知、数据存储区域等规则在试点前由甲方进一步确认，并落实为相应软件开关/提示。
