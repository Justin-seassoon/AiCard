# 端侧诊断日志上传说明

> 面向：ODM / 端侧固件开发
> 日期：2026-10-30
> 接口：`POST /api/v1/device/logs`（通用，不限于会议录音）
> 协议依据：《[端云通信协议-唯一基线](../docs/baseline/端云通信协议-唯一基线.md)》§6.1

---

## 1. 用途

端侧在联调 / 现场排障时，把设备日志上传到云端，便于云端远程定位问题。会议录音、OTA、WSS 翻译都可以用同一个接口。

**日志不会自动上传**，由端侧在需要时主动调用（例如：会议结束失败、连续上传失败、用户报障时）。

---

## 2. 请求

```http
POST /api/v1/device/logs
Authorization: Bearer <device_token>
X-Device-Id: <device_id>
Content-Type: text/plain
Content-Encoding: gzip          # 可选，建议开启
X-Meeting-Id: mtg-...           # 可选，关联会议
X-Fw-Version: 1.0.0             # 可选
X-Log-Level: warn               # 可选：debug/info/warn/error，默认 info
X-Log-From: 2026-10-30T10:00:00Z  # 可选
X-Log-To: 2026-10-30T10:05:00Z    # 可选
```

请求体：纯文本 / JSONL，例如：

```
2026-10-30T10:00:01Z INFO  meeting start client_key=...
2026-10-30T10:00:32Z WARN  chunk seq=1 upload failed http=504 retry=1
2026-10-30T10:00:35Z INFO  chunk seq=1 upload ok
2026-10-30T10:05:02Z ERROR end last_seq=12 http=409 error_code=E_MEETING_STATE
```

---

## 3. 限制

| 项 | 值 |
|---|---|
| 单次大小 | 压缩后 ≤256KB；gzip 解压后 ≤1MB |
| 频率 | 同一设备 **1 次/分钟** |
| 保留 | 7 天（到期云端自动删除） |
| 鉴权 | 与 OTA / 会议录音同一套设备 token |
| 内容 | **不得**包含 token、音频、转写正文、用户个人信息 |

---

## 4. 响应

成功 `201`：

```json
{
  "log_id": "dlog-...",
  "size_bytes": 107,
  "raw_size_bytes": 90,
  "expires_at": "2026-11-06T00:00:00Z"
}
```

请端侧记录 `log_id`，报障时一并提供。

错误：

| HTTP | error_code | 说明 | 端侧动作 |
|---|---|---|---|
| 401 | `E_DEVICE_LOG_AUTH` | token / device_id 无效 | 刷新凭证 |
| 400 | `E_DEVICE_LOG_INVALID_ARGUMENT` | 头字段非法（时间格式、meeting_id、level） | 修正请求 |
| 413 | `E_DEVICE_LOG_TOO_LARGE` | 超过 256KB（或解压后 1MB） | 截断/压缩后重传 |
| 429 | `E_DEVICE_LOG_RATE_LIMIT` | 1 分钟内重复上传 | 退避重试 |
| 403 | `E_DEVICE_LOG_DISABLED` | 云端关闭了日志上传 | 停止 |

## 5. curl 示例

明文：

```bash
curl -X POST https://aicard.seassoon.net:58083/api/v1/device/logs \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Device-Id: $DEVICE_ID" \
  -H "X-Meeting-Id: mtg-123" \
  -H "X-Fw-Version: 1.0.0" \
  -H "Content-Type: text/plain" \
  --data-binary @device.log
```

gzip（推荐）：

```bash
gzip -c device.log > device.log.gz
curl -X POST https://aicard.seassoon.net:58083/api/v1/device/logs \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Device-Id: $DEVICE_ID" \
  -H "Content-Encoding: gzip" \
  -H "Content-Type: text/plain" \
  --data-binary @device.log.gz
```

## 6. 后台查看

运维 / 云端可以用以下接口查询与下载（需后台租户头）：

```bash
# 列表
curl "https://aicard.seassoon.net:58083/api/device-logs?device_id=demo-device-001&limit=50" \
  -H "X-Customer-Id: 1" -H "X-Store-Id: 1"

# 下载（gzip 自动解压为文本）
curl "https://aicard.seassoon.net:58083/api/device-logs/<log_id>" \
  -H "X-Customer-Id: 1" -H "X-Store-Id: 1"
```

---

## 7. 建议的上传时机

- 会议 `end` 返回 `failed`，或上传分片连续失败（附 `meeting_id`）；
- OTA 检查/下载连续失败；
- 用户报障、现场演示前主动导出最近 5 分钟日志；
- 设备重启后需要保留上一轮异常现场时（先落本地，再上传）。

> 当前设备本地日志存储能力由固件决定；云端只负责接收、留存与下载。
