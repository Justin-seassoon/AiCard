# OTA 版本发布 · 后台操作说明（端侧）

> 面向：端侧固件开发 / 测试（ODM）
> 日期：2026-11-07
> 入口：运营后台「版本发布」页签
> 协议依据：《[端云通信协议-唯一基线](../docs/baseline/端云通信协议-唯一基线.md)》§3

---

## 1. 用途

端侧开发在**后台直接上传 P4 / C5 固件并发布新版本**，设备 `check` 更新即可拿到。

本说明替代旧的手动流程（scp 放文件 + 手算 sha256/size + curl 发布）——上传后云端自动算 size 与 sha256，发布时再复核一次，防放错文件。

---

## 2. 入口与环境

| 项 | 值 |
|---|---|
| 发布后台 | `https://aicard.seassoon.net:58081/admin.html` → 顶部「**版本发布**」页签 |
| 设备联调（check / 下载） | `https://aicard.seassoon.net:58083`（见《OTA 联调操作说明》） |
| 固件目录 | 后台与设备侧共享同一存储卷，后台传的固件设备可直接下载 |

> 后台（58081）发布、设备（58083）检查下载，两边共用同一份发布数据与固件文件，无需重复上传。

---

## 3. 操作流程

### 3.1 上传固件

1. 打开「版本发布」页签，在「上传固件」区选择 **P4 固件** / **C5 固件**（可只传其中一个，也可两个都传）。
2. 点「上传固件」。
3. 上传成功后，下方显示每个模块的：文件名、字节大小、sha256 前 16 位。

> 上传即生成一次固件文件，未发布前可重复上传覆盖；每次发布用「当前已上传」的文件。

### 3.2 发布新版本

在「发布新版本」表单填写：

| 字段 | 必填 | 说明 |
|---|---|---|
| 更新 ID | ✅ | 本次发布唯一标识，建议 `ota-YYYYMMDD-N`，如 `ota-20261107-1` |
| 策略 | ✅ | `普通`（optional，可稍后升）/ `强制`（mandatory，必须升） |
| 目标 P4 版本 | ✅ | 如 `2.0`；须与上传的 P4 固件对应 |
| 目标 C5 版本 | ✅ | 如 `1.5`；须与上传的 C5 固件对应 |
| 发布说明 | — | 本次更新内容，给设备侧 / 团队看的备注 |

点「**发布**」。

### 3.3 查看 / 撤销

- 「发布历史」表格列出所有发布：更新 ID、策略、P4/C5 版本、说明、状态、创建时间。
- 状态「生效中」的发布可点「撤销」；撤销后设备不再收到该版本。
- **同一时刻只有一个「生效中」发布**：发布新版本会自动撤销上一个。

---

## 4. 关键规则（务必理解）

| 规则 | 说明 |
|---|---|
| 单 active 语义 | 发布新版本 = 自动撤销旧 active；设备只看到当前 active 的发布 |
| 版本不降级 | 设备当前版本**高于或等于**目标版本时，云端不下发（`UP_TO_DATE`），不会把设备降级 |
| sha256/size 自动算 | 上传时云端计算；发布时再复核，与固件实际不符会 400 拒绝 |
| 固定配套 | P4 + C5 一起发布，目标版本各自独立；`packages` 只含需要升级的模块 |
| 文件格式 | `.bin` 等任意二进制，单文件上限 200MB（云端 multipart 配置） |

---

## 5. 发布后设备验证

发布成功后，设备侧走原有检查流程即可拿到新版本：

```bash
curl -X POST https://aicard.seassoon.net:58083/api/v1/ota/check \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <device_token>' \
  -d '{"device_id":"<device_id>","current_versions":{"p4":"1.0","c5":"1.0"},"trigger":"boot"}'
```

返回 `update_available: true` 即含新版本与签名下载 URL（详见《OTA 联调操作说明》）。

---

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 发布报「sha256 mismatch」/「image_size mismatch」 | 上传的固件与登记信息不一致；重新上传对应模块的固件再发布 |
| 设备 check 返回 `NO_APPLICABLE_RELEASE` | 没有「生效中」的发布，或设备版本高于目标（不降级），检查后台发布状态与版本号 |
| 设备 check 返回 `UP_TO_DATE` | 设备版本已 ≥ 目标版本，无需升级 |
| 发布后想撤回 | 在发布历史点「撤销」；再发布新版本时旧版也会自动撤销 |
