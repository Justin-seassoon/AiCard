## 0. 先回答：协议变了吗？

| 通道 | 是否变化 | 说明 |
|---|---|---|
| WSS 会话协议 v1（翻译 / 问答） | **未变** | 仍按《端云通信协议-唯一基线》§2 |
| OTA v1 | **未变** | 仍按 §3 |
| 会议录音 HTTP API | **协议基线未变，实现口径已对齐** | 如果端侧之前按旧 P0 代码联调，需要改；如果已按基线 §4 实现，则无需改 |

**旧 P0 → 现在的差异（只影响会议录音）**

| 项 | 旧 P0 | 现在 |
|---|---|---|
| 路径 | `/api/meetings/start`、`/api/meetings/{id}/end` | `POST /api/v1/meetings`、`POST /api/v1/meetings/{id}/end` |
| 鉴权 | `X-Device-Id` + `X-Device-Token` | `Authorization: Bearer <token>` + `X-Device-Id` |
| 结束 | `last_seq` 可选，缺片仍直接转写 | `last_seq` **必填**；有缺片保持 `uploading`，可补传 |
| 缺片返回 | 只有 `missing_count` | 返回 `missing_seqs` 列表 |
| 状态查询 | 无 | 新增 `GET /api/v1/meetings/{id}` |
| 开始字段 | `client_key / chunk_sec` 等 | 新增必填 `fw_version / features / trigger / notice_played` |
| 错误格式 | Spring 默认 | `{"error_code","message","retryable"}` |
| 分片时长 | 5–120 秒 | **5–30 秒**（60/120 不支持） |

> 结论：WSS / OTA 不用改；会议录音请按本文档实现，旧的 `/api/meetings` 与 `X-Device-Token` 已不可用。

## 3. 接口速查

### 3.1 开始会议

`POST /api/v1/meetings`

```json
{
  "client_key": "设备生成的唯一键，重试必须相同",
  "started_at": "2026-10-30T10:00:00Z",
  "codec": "pcm16",
  "sample_rate": 16000,
  "chunk_sec": 5,
  "title": "定例会議",
  "fw_version": "1.0.0",
  "features": ["meeting_recording"],
  "trigger": "long_press",
  "notice_played": true,
  "notice_version": "v1"
}
```

必填与约束：

| 字段 | 要求 |
|---|---|
| `client_key` | 必填，≤64 字符；同设备重试复用同一值 |
| `chunk_sec` | 必填，**5–30**（按 PSRAM 预算选 5/10/15/20/30） |
| `fw_version` | 必填，非空 |
| `features` | 必填，必须包含 `meeting_recording` |
| `trigger` | 必填，固定 `long_press` |
| `notice_played` | 必填，必须为 `true` |
| `codec` | 只能 `pcm16`（不传默认 `pcm16`） |
| `sample_rate` | 只能 `16000`（不传默认 `16000`） |
| `title` / `started_at` / `notice_version` | 可选 |

成功响应：

```json
{
  "meeting_id": "mtg-...",
  "status": "recording",
  "chunk_sec": 5,
  "max_chunk_bytes": 2097152,
  "retention_days": 30,
  "chunk_url": "/api/v1/meetings/mtg-.../chunks/{seq}",
  "audio_expires_at": "2026-11-29T10:00:00Z"
}
```

### 3.2 上传分片

`PUT /api/v1/meetings/{meeting_id}/chunks/{seq}`

- `Content-Type: application/octet-stream`
- 可选头 `X-Chunk-Sha256: <hex>`；带上则云端校验
- 成功 `204`
- 同一 `seq` 重复上传相同内容 → 幂等；不同内容 → `409 E_MEETING_SEQ_CONFLICT`
- 单片 >2MB → `413 E_MEETING_TOO_LARGE`
- 音频格式：PCM16 / 16kHz / 单声道

### 3.3 结束会议

`POST /api/v1/meetings/{meeting_id}/end`

```json
{"last_seq": 12}
```

- `last_seq` **必填**，为最后一片的序号（从 0 开始）
- 无缺片 → `status: "transcribing"`，云端开始转写
- 有缺片 → `status: "uploading"`，返回缺片列表：

```json
{
  "meeting_id": "mtg-...",
  "status": "uploading",
  "expected_last_seq": 12,
  "missing_seqs": [3, 7],
  "auto_finalize_after_sec": 600,
  "duration_sec": 65
}
```

- 按 `missing_seqs` 补传后，云端**自动转写**，也可以再次调用 `end`（幂等）
- 10 分钟无新分片 → 自动转写（仍保留缺片记录）

### 3.4 状态查询（重启 / 断网恢复）

`GET /api/v1/meetings/{meeting_id}`

```json
{
  "status": "uploading",
  "last_seq": 12,
  "expected_last_seq": 12,
  "missing_seqs": [3, 7],
  "uploaded_count": 11,
  "audio_expires_at": "2026-11-29T10:00:00Z",
  "error_message": null
}
```

用途：设备重启后先查状态，再补传 `missing_seqs`；不要重新 `start`（同 `client_key` 会返回原会议）。

### 3.5 错误码

| HTTP | error_code | 场景 | 端侧动作 |
|---|---|---|---|
| 401 | `E_MEETING_AUTH` | token / device_id 无效 | 刷新凭证，不盲目重试 |
| 400 | `E_MEETING_INVALID_ARGUMENT` | 参数缺失/非法（`last_seq` 缺失、`trigger` 非 long_press、`notice_played=false` 等） | 修正请求 |
| 400 | `E_MEETING_UNSUPPORTED_FW` | `features` 缺少 `meeting_recording` | 升级/修正固件 |
| 403 | `E_MEETING_FEATURE_DISABLED` | 云端未开启会议功能 | 停止，提示未开通 |
| 404 | `E_MEETING_NOT_FOUND` | 会议不存在/不属于该设备 | 停止 |
| 409 | `E_MEETING_STATE` | 会议已结束、补片超过 `expected_last_seq` | 查状态后决定 |
| 409 | `E_MEETING_SEQ_CONFLICT` | 同序号不同内容 | 停止该片，人工确认 |
| 400 | `E_MEETING_SHA_MISMATCH` | SHA-256 校验失败 | 重传该片 |
| 413 | `E_MEETING_TOO_LARGE` | 单片 >2MB | 减小分片 |
| 410 | `E_MEETING_EXPIRED` | 音频已过期 | 停止 |

响应统一为：

```json
{"error_code":"E_MEETING_STATE","message":"...","retryable":false}
```

端侧按 `error_code` 处理，不要解析 `message` 文案；`retryable=true` 才自动重试。

## 4. 测试用例清单

### A. 连通与鉴权

- [ ] `GET /actuator/health` 返回 `{"status":"UP"}`
- [ ] 正确 `device_id` + token → `start` 成功
- [ ] 错误 token → `401 E_MEETING_AUTH`
- [ ] 缺少 `X-Device-Id` → `401 E_MEETING_AUTH`
- [ ] 使用旧头 `X-Device-Token` → `401`（确认旧口径已停用）

### B. 开始参数校验

- [ ] 缺 `client_key` → `400 E_MEETING_INVALID_ARGUMENT`
- [ ] 缺 `chunk_sec` → `400 E_MEETING_INVALID_ARGUMENT`
- [ ] `chunk_sec=4` 或 `31` → `400`（确认 5–30 边界）
- [ ] 缺 `fw_version` → `400 E_MEETING_INVALID_ARGUMENT`
- [ ] `features` 不含 `meeting_recording` → `400 E_MEETING_UNSUPPORTED_FW`
- [ ] `trigger` 不是 `long_press` → `400`
- [ ] `notice_played=false` → `400`
- [ ] `codec=opus` 或 `sample_rate=8000` → `400`
- [ ] 同一 `client_key` 重复 `start` → 返回同一个 `meeting_id`

### C. 分片上传

- [ ] 正常上传 `seq=0,1,2` → 均 `204`
- [ ] 重复上传同一片相同内容 → `204`（幂等，不重复计费/不报错）
- [ ] 同一 `seq` 传不同内容 → `409 E_MEETING_SEQ_CONFLICT`
- [ ] 带错误 `X-Chunk-Sha256` → `400 E_MEETING_SHA_MISMATCH`
- [ ] 单片刻意 >2MB → `413 E_MEETING_TOO_LARGE`
- [ ] 乱序上传（先 2 后 0、1）→ 云端按 `seq` 正确归位

### D. 正常结束（无缺片）

- [ ] 上传 0..N 全部后 `end(last_seq=N)` → `status=transcribing`
- [ ] `GET status` 最终变为 `draft`（或 `failed` 并带 `error_message`）
- [ ] 后台「会议纪要」能看到转写、纪要、待办
- [ ] 重复 `end` → 幂等，不重复转写

### E. 缺片与补传

- [ ] 只传 0、2，`end(last_seq=3)` → `status=uploading`，`missing_seqs=[1,3]`
- [ ] 此时 `GET status` → `uploaded_count=2`、`missing_seqs=[1,3]`
- [ ] 补传 1、3 → 自动 `transcribing`，`missing_seqs=[]`
- [ ] 补传后再次 `end` → 仍幂等
- [ ] 补传 `seq=4`（> expected_last_seq）→ `409 E_MEETING_STATE`

### F. 重启 / 断网续传

- [ ] `start` 后断网，设备重启；用同一 `meeting_id` 调 `GET status` → 状态与缺片正确
- [ ] 按 `missing_seqs` 补传 → 自动转写
- [ ] 用同一 `client_key` 重新 `start` → 返回原 `meeting_id`，不会新建会议

### G. 超时自动收尾（可选，耗时约 10 分钟）

- [ ] `end` 后留缺片不补，等待 10 分钟 → 自动 `transcribing`，缺片记录保留
- [ ] 后台可见该会议与缺片信息

### H. 端到端内容验证

- [ ] 录一段日语会议语音（≥10 秒），按 5 秒切片上传
- [ ] `end` 后后台生成日语转写、结构化纪要、待办
- [ ] 导出 docx 成功、回听音频成功

## 5. 关键限制（务必遵守）

| 项 | 值 |
|---|---|
| 音频格式 | PCM16 / 16kHz / 单声道 |
| 分片时长 | **5–30 秒**（60/120 不支持） |
| 单片大小 | ≤2MB（30 秒约 960KB） |
| 音频保留 | 30 天（到期删音频，保留转写/纪要） |
| 并发会议 | 同一设备同一时刻只允许一个进行中的会议 |
| 触发方式 | 只能现场按键；不提供远程静默开启 |
| 开始提示 | 必须本地提示，`notice_played=true` |
| 离线上传 | 云端支持补传；设备本地缓存能力由固件决定 |

---

## 6. 联调顺序建议

1. 健康检查 + 鉴权（A）
2. `start → 顺序上传 → end` 正常链路（B、C、D）
3. 缺片补传（E）
4. 重启续传（F）
5. 错误码逐项验证（B、C）
6. 真实语音端到端内容验证（H）
