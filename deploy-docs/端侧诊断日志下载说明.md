# 端侧诊断日志下载说明

> 面向：端侧固件开发 / 联调同学
> 日期：2026-11-06
> 配套：**上传**看《端侧诊断日志上传说明》（`POST /api/v1/device/logs`），本文件讲**下载**。

---

## 1. 用途

端侧把日志上传到云端后，云端或端侧同学可以**随时下载某台设备「最近上传」的日志**来排查问题。

日志正文落云端共享卷、DB 只存索引，所以**从哪个应用实例下载，数据都一致**（58081 / 58083 等都能查）。

下载走后台接口，需要后台租户头（测试环境固定 `X-Customer-Id: 1`、`X-Store-Id: 1`）。

---

## 2. 方式一：后台页面（推荐，可视化）

1. 浏览器打开：`https://aicard.seassoon.net:58081/admin.html`
2. 点顶部 **「诊断日志」** 页签。
3. 页签内有上下两块：

| 区块 | 用途 |
|---|---|
| **下载最新日志** | 填设备 ID → 点「下载最新日志」，浏览器直接下载该设备**最近一条**日志（`.log` 文件） |
| **设备诊断日志列表** | 按设备 ID / 会议 ID / 上传起止时间筛选，逐条「下载」；可看级别、大小、压缩、上传/过期时间 |

> 「下载最新」适合现场排障随手拉一条；「列表」适合需要翻历史、按会议号关联时用。

---

## 3. 方式二：curl 一键下载最新（脚本 / 排障）

「下载最新日志」本质是两步：先按设备取最新一条的 `log_id`，再按 `log_id` 下载正文。下面给一个可直接用的脚本：

```bash
HOST=https://aicard.seassoon.net:58081
CUSTOMER=1
STORE=1
DEVICE_ID=demo-device-001   # 改成实际设备 ID

# 1) 取该设备最新一条日志的 log_id（列表按上传时间倒序，limit=1 即最新）
LOG_ID=$(curl -s "$HOST/api/device-logs?deviceId=$DEVICE_ID&limit=1" \
  -H "X-Customer-Id: $CUSTOMER" -H "X-Store-Id: $STORE" \
  | grep -o '"log_id":"dlog-[a-f0-9]*"' | head -1 \
  | sed 's/.*"log_id":"\(dlog-[a-f0-9]*\)".*/\1/')

if [ -z "$LOG_ID" ]; then
  echo "该设备暂无诊断日志（未上传，或已过 7 天保留期）"
  exit 1
fi

# 2) 下载正文（gzip 已自动解压为纯文本）
curl -s "$HOST/api/device-logs/$LOG_ID" \
  -H "X-Customer-Id: $CUSTOMER" -H "X-Store-Id: $STORE" \
  -o "$DEVICE_ID-latest.log"

echo "已下载 $LOG_ID -> $DEVICE_ID-latest.log"
```

## 4. 接口参考

### 4.1 列表 `GET /api/device-logs`

| 参数 | 说明 |
|---|---|
| `deviceId` | 设备 ID（可选，**注意是 `deviceId` 不是 `device_id`**） |
| `meeting_id` | 会议 ID（可选） |
| `from` / `to` | 按**上传时间**过滤，ISO-8601 instant（可选） |
| `limit` | 条数，默认 100，最大 200 |

返回字段（snake_case）：`log_id` / `device_id` / `meeting_id` / `fw_version` / `level` / `captured_from` / `captured_to` / `size_bytes` / `raw_size_bytes` / `compressed` / `created_at` / `expires_at`。

### 4.2 下载 `GET /api/device-logs/{log_id}`

返回 `text/plain`；若上传时是 gzip，云端已自动解压。

## 5. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 列表空、下载 404 | 该设备没上传过日志；或日志已过 **7 天保留期**被自动删除 |
| 页面点「下载最新」提示「该设备暂无诊断日志」 | 同上，确认设备 ID 正确且已上传 |
| 列表里 `captured_from/to` 为空 | 上传时没带 `X-Log-From` / `X-Log-To` 头，属正常 |
| 需要按会议关联 | 上传时带 `X-Meeting-Id`，下载侧用 `meeting_id` 筛选 |

---

## 6. 与上传的对应关系

| 动作 | 接口 | 入口 |
|---|---|---|
| 上传日志 | `POST /api/v1/device/logs`（Bearer 设备 token） | 端侧，58083 |
| 下载日志 | `GET /api/device-logs` / `GET /api/device-logs/{log_id}`（租户头） | 后台，58081 |

> 上传用设备 token，下载用后台租户头——两者鉴权不同。端侧排障时一般由云端同学下载，或端侧拿到租户头后自行下载。
