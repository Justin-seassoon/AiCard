## 三、⚠️ 需要运维配合：放通 8080 端口

**当前 8080 端口只在服务器内部监听（`0.0.0.0:8080`），但云安全组/防火墙未对外放通，端侧真机从公网无法连接。**

请完成：

1. 在云控制台安全组，添加一条**入站规则**：放通 `TCP 8080`（源地址按需，建议先放通测试网段或全量，联调结束后收紧）。
2. 如果服务器有本地防火墙（`iptables`/`firewalld`/`ufw`），同步放通 8080。

放通后，外部应能访问健康检查：
```bash
curl http://120.253.215.110:8080/actuator/health
# 期望返回 {"status":"UP"}
```

## 五、环境变量说明（更新应用时）

应用通过环境变量读取配置，均在 `application.yml` 有默认值。关键项：

| 环境变量 | 作用 | 当前值 |
|---|---|---|
| `DB_URL` | 数据库 JDBC 地址 | `jdbc:postgresql://10.0.189.32:5432/root` |
| `DB_USER` / `DB_PASSWORD` | 数据库账号 | `root` / `<见 docker-compose>` |
| `AZURE_SPEECH_KEY` | Azure Speech 密钥 | 已注入（不在文档明文记录） |
| `AZURE_SPEECH_REGION` | Azure region | `japaneast` |
| `TZ` | 时区 | `Asia/Tokyo` |

> 密钥不落盘、不写进仓库文件，仅通过 `docker run -e` 或 `--env-file` 注入。

## 七、知识库重灌（answer_embedding 修复后必做）

2026-09-09 起，知识库校验段改用 chunk 的 `answer_embedding`（答案向量）。旧数据该列为 NULL，校验段会跳过、命中率下降，需清空重灌。

1. 清空知识库表（连入应用实际使用的库，当前为 `db_ai_card`）：

```bash
docker exec -it aicard-postgres psql -U root -d db_ai_card \
  -c "TRUNCATE chunk, document RESTART IDENTITY CASCADE;"
```

2. 带灌库参数重启应用（`KnowledgeSeeder` 非幂等，灌库前必须先清空）：

```bash
java -jar app.jar \
  --skb.seed.enabled=true \
  --skb.seed.files=/app/便利店与免税店-日语版.md,/app/连锁酒店-日语版.md \
  --skb.seed.customer-id=1 --skb.seed.store-id=1
```

> 灌库完成后，去掉 `--skb.seed.*` 参数正常启动（避免每次重启重复灌库）。
