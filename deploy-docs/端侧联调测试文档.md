# AI 工牌 1.0 · 端侧联调测试文档

> 面向端侧（ODM）测试人员。说明如何连接云端后端进行通信协议联调，以及需要验证的测试内容。
> 更新日期：2026-09-02

---

## 一、连接信息

| 项 | 值 |
|---|---|
| 协议 | WebSocket（当前为 `ws://` 明文，生产转 `wss://`） |
| 公网地址 | `ws://120.253.215.110:8080/ws` |
| 内网地址（同内网时） | `ws://10.0.189.32:8080/ws` |
| device_id | `demo-device-001` |
| token | `demo-token-001` |
| fw_version | `0.1.0`（可填实际固件版本） |
| proto_ver | `1` |

完整连接 URL：

```
ws://120.253.215.110:8080/ws?device_id=demo-device-001&token=demo-token-001&fw_version=0.1.0&proto_ver=1
```

- 握手时云端用 `device_id + token` 鉴权，失败拒绝握手（HTTP 403）。
- 会话级短连：一次会话一个连接，会话结束断开，不维持长连接。

## 二、帧结构速查

| 帧 | 方向 | 编码 | frame_type |
|---|---|---|---|
| 音频分片 | 端 → 云 | 二进制帧 | `0x01` |
| TTS 音频 | 云 → 端 | 二进制帧 | `0x81` |
| 控制消息 | 双向 | JSON 文本帧（UTF-8） | — |

- 多字节整数一律**大端 big-endian**。
- JSON 字段 **snake_case**；`0x81` 二进制帧只带 turn_id，不带 session_id（靠连接关联会话）。

### 上行音频帧（0x01）字节布局

```
偏移  长度      字段
0     1 byte    frame_type = 0x01
1     1 byte    turn_id_len = N（1~255）
2     N bytes   turn_id（UTF-8，UUID）
2+N   4 bytes   sequence（uint32 大端，turn 内从 0 递增）
6+N   8 bytes   timestamp（uint64 大端，会话内相对毫秒）
14+N  1 byte    source_side：0=wearer 1=counterparty 2=uncertain
15+N  1 byte    input_source：0=badge_near 1=badge_far 2=headset_mic 3=uncertain
16+N  剩余       audio_payload（原始音频字节，PCM16 16kHz 单声道）
```

### 下行 TTS 帧（0x81）字节布局

```
偏移  长度      字段
0     1 byte    frame_type = 0x81
1     1 byte    turn_id_len = N
2     N bytes   turn_id（UTF-8）
2+N   剩余       tts_audio（PCM 音频，流式分片下发）
```

> ⚠️ **单帧上限 ≤8KB**：上行音频分片和下行 TTS 分片都不得超过 8KB，务必分片。

## 三、最小联调时序（翻译链路）

```
设备 ──握手（query 带鉴权参数）──► 云端
设备 ──session_init（JSON 文本帧）──► 云端
设备 ──0x01 音频分片 ×N（二进制帧）──► 云端
设备 ──eou（JSON 文本帧）──► 云端
云端 ──0x81 TTS 分片 ×M（二进制帧，流式）──► 设备
云端 ──tts_end（JSON）──► 设备
云端 ──language_state（JSON）──► 设备
```

## 四、消息示例

### 4.1 session_init（建连后首条，必发）

```json
{"type":"session_init","session_id":"s1","scope":"translate","staff_language":"ja-JP",
 "translation_mode":"fixed","lang_pair":"zh-ja","headset_state":"disconnected",
 "input_source":"badge_far","wifi_band":"5GHz","network_state":"good",
 "config_version":123}
```

字段说明：

- `scope`：会话业务域 `translate`（翻译）／ `staff_qa`（员工问答，暂为桩）。
- `translation_mode`：**默认 `fixed`**（固定语言对）；`auto`（自动判定语言）可选。
- `staff_language`：员工语言（双向翻译锚点），默认 `ja-JP`。
- `lang_pair`：固定语言对，游客侧-员工侧，**默认 `zh-ja`（中文→日文）**。
- `candidates`：`auto` 模式语种判定用，`fixed` 模式可省略。

**端侧行为对照（当前默认「中转日」）**：

| 端侧传参 | 云端行为 |
|---|---|
| 不传 `translation_mode` / `lang_pair` | 默认 `fixed` + `zh-ja`（中文→日文，跳过语种判定，时延约 2.2s） |
| `translation_mode=fixed` + `lang_pair=xx-xx` | 按指定语言对翻译（跳过语种判定） |
| `translation_mode=auto` | 自动判定语言（时延更高，约 5s） |

### 4.2 音频分片（二进制 0x01）

**音频必须流式分片上传**：说话过程中边采集边发送（建议 100ms 一帧），**不要等说完一次性上传整段**。

- 每个 turn 内 `sequence` 从 0 递增、`timestamp` 为会话内相对毫秒（建连起）。
- 单帧 ≤8KB（100ms × 16kHz × 2 字节 = 3200 字节，远小于上限）。
- 云端收到分片后按 turn_id **累积缓冲**，`eou` 尾包到达才触发翻译（云端为「累积后处理」，非边收边 ASR）。
- 流式上传的意义：音频在说话过程中已传完，`eou` 后只剩尾包，省去「说完再传整段音频」的延迟。

### 4.3 eou（尾包，该 turn 最后一条）

```json
{"type":"eou","session_id":"s1","turn_id":"t1","source_side":"counterparty",
 "last_sequence":23,"utterance_duration_ms":1500,"input_source":"badge_far"}
```

### 4.4 下行回包（云端 → 设备）

**TTS 音频**（0x81 二进制，分片流式）→ **tts_end**（JSON）：

```json
{"type":"tts_end","session_id":"s1","turn_id":"t1"}
```

**language_state**（语言状态，屏幕显示用）：

```json
{"type":"language_state","session_id":"s1","turn_id":"t1","visitor_language":"zh-CN","state":"locked"}
```

**error**（错误/降级）：

```json
{"type":"error","session_id":"s1","turn_id":"t1","code":"E_LID_LOW","message":"请再说一遍","fallback_action":"ask_repeat"}
```

## 五、测试内容清单

### 5.1 基础连通

- [ ] 握手鉴权成功（正确 device_id + token）。
- [ ] 鉴权失败被拒（错误 token → HTTP 403）。
- [ ] 健康检查 `GET /actuator/health` 返回 `{"status":"UP"}`。

### 5.2 翻译链路（P0）

- [ ] **流式分片上传**：说话过程中持续发送多帧（`sequence` 递增、`timestamp` 递增），云端正确累积，`eou` 后返回完整翻译。
- [ ] `session_init` → 流式音频分片 → `eou` → 收到 `tts_audio`（0x81）+ `tts_end` + `language_state`。
- [ ] **fixed 模式**：`translation_mode=fixed` + `lang_pair=zh-ja`，游客说中文 → 收到日文 TTS。
- [ ] **auto 模式**：`translation_mode=auto`，游客说中文 → 云端自动判定语言并翻译。
- [ ] 员工说话（`source_side=wearer`）→ 反向翻译（员工语言 → 游客语言）。

### 5.3 TTS 播放与打断

- [ ] 收到多个 0x81 分片，按顺序播放，`tts_end` 后停止。
- [ ] 播放中检测到新语音 / 按键 → 端侧本地停止（≤100ms），发 `stop_tts`：

```json
{"type":"stop_tts","session_id":"s1","turn_id":"t1","reason":"voice"}
```

- [ ] 打断后迟到的 TTS 分片按 turn_id 丢弃。

### 5.4 会话生命周期

- [ ] 再次短按翻译键 → 结束会话（断开），重新短按 → 新会话。
- [ ] 空闲超时（约 20s 无语音/按键）→ 会话结束断开。
- [ ] 断线重连：断网 → 新 session_id 重新握手，回到初始语言状态（不需重启设备）。

### 5.5 域切换（预留，1.0 部分为桩）

- [ ] `scope_change` → `staff_qa`：目前云端回固定桩答案（员工知识库 P5 实现）。

## 六、测试注意点

1. **单帧 ≤8KB**：音频分片和 TTS 分片都不得超过 8KB，务必按帧长（建议 100ms 一帧）分片。
2. **时延口径**（实测，japaneast）：
   - `eou` 尾包 → 首个 TTS 分片：**fixed 约 2.2s，auto 约 5.0s**。
   - 体感时延 = 上值 + 说话时长 + VAD 静音约 1.2s。
3. **VAD 静音约 1.2s** 触发 `eou` 尾包（端侧断句）。
4. **音频格式**：当前按 PCM16 · 16kHz · 单声道；采样率/编码/帧长属待冻结项（见接口规范 §9），联调时需确认。
5. **流式上传**：端侧必须在采集过程中边采边传（100ms 一帧），云端按 turn_id 累积、`eou` 才处理。
6. 协议完整定义见《端云通信接口规范-v1.md》（v4 定稿）。
